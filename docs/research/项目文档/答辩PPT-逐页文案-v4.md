### P03 · 行业痛点与立项动因（三个门槛）
- **页眉**：01  立项基础
- **标题**：硬件昂贵、算法离散、断网停摆：双足机器人的教学痛点
- **导语**：高校开设具身智能实验课，阻力常在设备采购开销、脚本碎片化和对公网的依赖。
- **板块一 · 门槛一：套件单价高，实验室难以规模化排课**：
  - 现状代价：商业教育双足动辄 6000 到 12000 元，采买 20 台就要 12 至 24 万元。多数实验室只买得起一两台放在展台，学生只能轮流看演示。
  - 后果：学生接触不到底层接线、总线配置和真机标定，难以开展系统性软硬件实验。
  - A.T.R.I. 方案：新增采购压到 ¥2725–3260 元，班级总预算控制在 5 万余元，让成班人手一机调试成为可能。
- **板块二 · 门槛二：各模块代码独立，缺乏通用调度结构**：
  - 现状代价：人脸抓取、地面循迹、抓取动作分别写在独立脚本里，主循环和串口接口各写各的。
  - 后果：学生做完实验只拿到零碎 demo，换个任务场景就要大改代码架构。
  - A.T.R.I. 方案：底层抽象出统一状态机与技能插件规范，换任务只需要改换一张 JSON 任务卡。
- **板块三 · 门槛三：强依赖外部网络，比赛现场极易超时锁死**：
  - 现状代价：视觉调公有云大模型接口，发声走在线语音合成。赛场 Wi-Fi 稍微丢包限速，动作流程就超时中断。
  - 后果：现场可靠性不可控，高校实验课的人脸和图像数据也存在外传合规顾虑。
  - A.T.R.I. 方案：单目轻量感知、多级离线语音与板载状态机全部跑在本地单板，运行期间不产生任何网络出站请求。
- **状态标签**：`◇ 设计目标`
- **讲者一句**：做这个项目的初衷，就是把成本做低、把调度做统一、把网络依赖拿掉，让双足机器人从展台上的演示样品变成学生工位上能独立修改的实验平台。

### P05 · 软硬件分层系统架构
- **页眉**：02  构型与架构
- **标题**：决策、运动与执行分层解耦，接口契约边界清晰
- **导语**：上层不处理底层舵机协议，底层不解析任务语义，全栈基于通用 Python 接口构建。
- **系统分层架构拓扑**：
  - `【大脑层 · 通用 Linux 板】`：
    - 运行环境：通用 Linux aarch64（Python 3.14 标准库，不依赖外部大型包）。
    - 核心模块：任务卡解析器（`TaskCard`）、大脑协调器（`Brain`）、有限状态机（`FSM`）、技能插件库（`Skills`）。
    - 外设接口：单目视觉检测（`Perception`）、多级离线语音（`TTS`）。
  - `【大脑 / 小脑通信边界】`：
    - 统一通过抽象接口 `Cerebellum` 交互，只下发 `set_angles(dict)`、`play_action(id)` 与 `wait_done()` 语义，保持单向解耦。
  - `【小脑层 · 运动与步态控制】`：
    - 现状：在板载 Python 中统一实现 `Cerebellum`，内置 40 帧参数化正弦步态生成与 JSON 动作库回放。
    - 规划：支持将步态生成下沉至 STM32 单片机固件（通过预留的串口通信协议对接）。
  - `【总线驱动与仿真对接】`：
    - 真实硬件：规划 22 路 STS3215 串行总线（接口类 `SerialServoBus`）。
    - 仿真环境：Webots 22 DOF 控制器（在 x86 主机上测试，通过同套接口通信，板端不运行图形仿真）。
- **状态标签**：`● 已完成 ◐ 进行中`
- **讲者一句**：我们把系统拆成大脑决策、小脑运动和小脑总线三层，大脑基于 Python 3.14 跑在通用 Linux 板上，通过标准化接口与下层舵机通信。

### P06 · 大脑核心：任务卡驱动与有限状态机
- **页眉**：02  构型与架构
- **标题**：五项赛题对应五张 JSON 任务卡，6 状态 FSM 管理流程
- **导语**：业务参数与执行代码解耦，状态转移具备确定性与可追溯性，异常自动退出。
- **左侧 · 6 状态有限状态机（FSM）**：
  - 正常转移流程：`STANDBY`（待机）→ `ENTERING`（入场启动）→ `EXECUTING`（技能作业）→ `FEEDBACK`（闭环确认）→ `DONE`（完成终态）。
  - 异常收敛流程：任何一步感知丢失、输入越界或超时中断，均单向收敛至 `ERROR` 状态。
  - 历史轨迹追溯：每次状态跳变自动存入 `history` 列表，离线排查时可以直接还原执行现场。
- **右侧 · JSON 任务卡结构与实例**：
  - 基础字段：`task_id`、`name`、`skills`；可选字段：`params`、`timeout_s`（默认 120s）。
  - 校验机制：启动前校验技能合法性与超时参数，字段缺失或技能未注册直接拒绝执行。
  - 任务卡配置样例：
    - `T-01 人脸识别`：`{"skills": ["face"], "params": {"tts": true}, "timeout_s": 60}`
    - `T-02 二维码循迹`：`{"skills": ["qr"], "params": {"default_payload": {"action": "walk", "steps": 3}}}`
    - `T-03 物品搬运`：`{"skills": ["carry"], "params": {"target": "红块", "distance_cm": 8.0}}`
    - `T-04 体育运动`：`{"skills": ["kick"], "params": {"threshold_cm": 1.0}}`
    - `T-05 娱乐休闲`：`{"skills": ["dance"], "params": {"bars": 2, "keyword": "跳舞"}}`
- **状态标签**：`● 已完成`
- **讲者一句**：五项赛题分别由一张 JSON 任务卡描述，通过 6 状态的有限状态机调度执行，换任务只改数据、不改底层逻辑。

### P07 · 技能层接口契约：防假阳性与超时防护
- **页眉**：03  软件契约
- **标题**：技能契约校验返回值类型，感知失败立即阻断动作
- **导语**：排查并修复早期测试中的逻辑隐患，通过 344 项主包测试锁定边界异常。
- **契约修复一：感知真值必须为布尔类型**：
  - 隐患：早期版本感知若返回字符串 `"False"`，在 Python 条件语句中会被判定为真，造成误动作。
  - 修复：强制断言 `found` 必须是 `bool` 类型。传入字符串或其他非布尔类型直接抛出 `ValueError` 并中断。
- **契约修复二：目标丢失立即退出（Fail-Fast）**：
  - 隐患：目标未找到时仍盲目执行后序踢球或抓取动作，容易造成机械碰撞。
  - 修复：技能执行前先核验感知结果，一旦未检出目标立即置失败退出，不再向小脑下发关节运动。
- **契约修复三：超时保护避免多线程死锁**：
  - 隐患：子线程超时强制调用复位归位（home），容易引发串口总线时序冲突。
  - 修复：后台定时器超时仅原子置位 `abort_event` 标志；位姿归位统一留在主线程退出时执行一次。
- **测试覆盖**：
  - 主包 344 项原生测试完整覆盖状态机边界、非合法输入校验和并发超时处理。
- **状态标签**：`● 已完成`
- **讲者一句**：我们在技能层规范了返回值类型和退出逻辑，目标没识别到就立刻停下，避免盲目动作导致机器人碰撞。

### P08 · 小脑内核：正弦步态、动作库与限位安全
- **页眉**：03  软件契约
- **标题**：正弦步态在线计算，动作库支持 JSON 配置，下发前过滤非有限值
- **导语**：小脑层统一处理步态轨迹插补与关键帧回放，并在关节指令下发前实施硬限位。
- **模块一 · 双足正弦步态生成器（`generate_gait`）**：
  - 时序参数：单步周期 0.8 s，采样频率 50 Hz（控制间隔 20 ms），左右腿正弦相位互差 $\pi$。
  - 映射关系：步长参数 `step_length_cm` 对应髋俯仰角，抬脚高度 `step_height_cm` 对应膝关节屈伸。
  - 躯干平移微调：躯干俯仰（1.5°）配合支撑腿微倾，躯干侧倾（1.0°）按半频补偿身体晃动。
- **模块二 · 关键帧动作库（`ActionLibrary`）**：
  - 文件格式：以 JSON 格式描述关键帧序列 `{frames: [{duration_s, joints: {...}}]}`。
  - 解耦效果：调节固定姿态或舞蹈动作无需修改 Python 代码，更新动作库文件后即可载入。
- **模块三 · 电机安全保护逻辑**：
  - 统一限位钳制：所有关节目标角在 `set_angle()` 内按配置的 `min/max` 进行范围限制，子类仅需实现底层的 `_write_angle()`。

### P19 · 动力学扭矩校核：连续额定主判据
- **页眉**：05  仿真与机械
- **标题**：校核依据取 0.98 N·m 连续额定，明确踝部与腰部过载区间
- **导语**：使用长期工作扭矩评估连续作业表现，针对过载关节制定机械与算法应对方案。
- **扭矩主判据说明**：
  - 瞬态峰值扭矩（1.47 N·m）：代表短时间堵转极限，不能用于长期双足站立或行走工况评估。
  - 连续额定扭矩（**0.98 N·m**）：主校核判据（来自 12V 规格标称），评估电机温升与长期带载能力。
- **重点关节负载测算**：
  - 踝关节静态与准动态负载：**1.630 N·m**（达到连续额定扭矩的 **167%**）。
  - 腰关节俯仰保持负载：**2.092 N·m**（达到连续额定扭矩的 **214%**）。
  - 膝关节、髋关节与肩关节负载保持在额定区间内。
- **改进方向**：
  - 踝部可增加弹性拉簧提供被动支撑扭矩，腰部考虑双舵机并联或连杆辅助，避免实机电机持续发热。
- **状态标签**：`◇ 设计目标`
- **讲者一句**：我们按照 0.98 牛·米的连续额定扭矩来核算，踝关节达到额定的 167%，腰关节达到 214%，真机上需要通过拉簧助力和步态调优来减轻过载。

### P20 · 电源预算与赛题续航核算
- **页眉**：05  仿真与机械
- **标题**：2000 mAh 电池续航约 13 分钟，连续作业 30 分钟需配置 ≥4.53 Ah
- **导语**：根据全机电流测算实际工作时间，评估大容量电池对机体配重的影响。
- **整机运行功耗测算**：
  - 22 路舵机静态维持电流：约 150 mA × 22 ≈ 3.3 A。
  - 动态行走时腿部电机带载：平均电流上升至约 6.0 A。
  - 边缘计算板与视觉传感器：整机运行开销约 1.25 A。
  - 综合平均工作电流：**约 7.25 A**（11.1 V 供电系统）。
- **续航核算与缺口**：
  - 现用电池：选配 **2000 mAh**（3S 锂电池），放电深度按 80% 计算，实际工作时间约为 **13.2 分钟**。
  - 赛题指标：要求完成连续作业 **≥ 30 分钟**。
  - 标称容量需求：按 7.25 A 测算，所需标称电池容量 **$\ge 4.53	ext{ Ah}$**。
- **工程权衡**：
  - 换装 4.53 Ah 规格电池会增加约 180 g 重量，将进一步加重踝部和腰部舵机负担，实物装配时需做综合权衡。
- **状态标签**：`○ 规划中`
- **讲者一句**：整机平均工作电流约 7.25 安，现有 2000 毫安时电池重载只能撑 13 分钟左右，要跑满赛题要求的半小时，后续需要换成 4.53 安时以上的高容量电池。
