### P03 · 行业痛点与立项动因（三个门槛）
- **页眉**：01  立项基础
- **标题**：设备贵、算法散、断网瘫：阻碍双足进课堂的三道高墙
- **导语**：高校具身智能与机器人实验课的瓶颈不在教学法，而在硬件成本与软件架构孤岛。
- **板块一 · 门槛一：硬件昂贵导致无法成班开课**：
  - 现状：全尺寸双足数十万起步，商业教育双足套件动辄 6000–12000 元，采购 20 台即需 12–24 万元。
  - 后果：实验室只能按「观摩展示」配置 1–2 台，学生无法人手一机参与真实装配与底层调试。
  - A.T.R.I. 应答：新增采购 ¥2725–3260 元，班级预算压至 5 万余元，实现从演示级向成班实验级的跨越。
- **板块二 · 门槛二：算法碎片化形成教学孤岛**：
  - 现状：视觉识别人脸用独立 demo，循迹单独写控制循环，动作回放靠独立串口助手。
  - 后果：学生学到的是互不相交的临时脚本，缺乏大型系统分层工程能力，换场景需大幅重写代码。
  - A.T.R.I. 应答：底座抽离出统一 FSM 调度器与 Skill 插件规范，换任务只需换一张 JSON 任务卡。
- **板块三 · 门槛三：在线架构在脱机赛场与保密教学中脆断**：
  - 现状：视觉依赖云端大模型 API，语音走公有云合成，遇网络延迟、限速或现场断网直接死锁。
  - 后果：赛事现场网络极不可靠；高校实验课堂对人脸等生物与环境数据外传极为敏感。
  - A.T.R.I. 应答：单目轻量视觉、离线 TTS 引擎与本地状态机集成于单板，全程 0 次网络出站。

  - `【大脑层 · Linux 边缘板】`：

    - 通过抽象接口 `Cerebellum` 交互，仅传递 `set_angles(dict)`、`play_action(id)` 与 `wait_done()` 语义，杜绝跨层污染。

    - 现状：在板载 Python 中统一实现 `Cerebellum`，集成 40 帧参数化正弦步态生成与动作库回放。

    - 硬件总线：22 路 STS3215 串行总线舵机拓扑（规划真机接口 `SerialServoBus`）。

### P06 · 大脑核心：任务卡驱动与有限状态机
- **页眉**：02  构型与架构
- **标题**：五项任务五张 JSON 任务卡，严格 FSM 守住状态安全
- **导语**：任务与代码彻底解耦，状态转移收敛可逆，杜绝非法跳转与死锁。
- **左侧 · 6 状态有限状态机（FSM）**：
  - 转移主链路：`STANDBY`（待机）→ `ENTERING`（入场识别）→ `EXECUTING`（技能作业）→ `FEEDBACK`（闭环反馈）→ `DONE`（成功终态）。
  - 异常收敛链路：任何阶段感知丢失、校验失败或动作异常，均严格流转至 `ERROR` 终态。
  - 状态历史追溯：状态机全流程记录 `history` 状态跳变列表，为脱机运行提供完整黑匣子日志。
- **右侧 · JSON 任务卡结构与实例**：
  - 必填字段：`task_id`、`name`、`skills`；可选：`params`、`timeout_s`（默认 120s）。
  - 格式校验：严格验证技能名合法性与超时数值有效性，禁止非法任务卡带病上电运行。
  - 任务卡实例展示：
    - `T-01 人脸识别`：`{"skills": ["face"], "params": {"tts": true}, "timeout_s": 60}`
    - `T-02 二维码循迹`：`{"skills": ["qr"], "params": {"default_payload": {"action": "walk", "steps": 3}}}`
    - `T-03 物品搬运`：`{"skills": ["carry"], "params": {"target": "红块", "distance_cm": 8.0}}`
    - `T-04 体育运动`：`{"skills": ["kick"], "params": {"threshold_cm": 1.0}}`
    - `T-05 娱乐休闲`：`{"skills": ["dance"], "params": {"bars": 2, "keyword": "跳舞"}}`
- **状态标签**：`● 已完成`
- **讲者一句**：五项赛题全部抽象为标准 JSON 任务卡，由包含 6 个核心状态的 FSM 统一驱动，从机制上杜绝了任务走半途失控的工程隐患。

### P07 · 技能层接口契约：防假阳性与超时防护
- **页眉**：03  软件契约
- **标题**：技能契约杜绝假成功，found 严守布尔，超时只置标志位
- **导语**：工程审计中暴露的「假成功」隐患已被全面修复，344 项主包测试构筑起严密防火墙。
- **契约修复一：感知返回与严格布尔判定**：
  - 隐患：此前若感知返回字符串 `"False"`，Python 条件判定将其视为真，引发非预期的虚假动作触发。
  - 修复：强制断言 `found` 必须为 `bool` 类型。若为非布尔类型，立即拒绝并抛出异常，杜绝误触发。
- **契约修复二：真实成败原则（Fail-Fast）**：
  - 隐患：目标未检测到时仍硬编码盲操执行后续踢球或抓取动量，造成物理碰撞。
  - 修复：技能执行前检查感知成败，若未找到目标立即置任务失败并退出，不再下发实体关节运动。
- **契约修复三：超时保护线程安全**：
  - 隐患：子线程超时强制归位（home）易造成串口通信紊乱与死锁冲突。
  - 修复：定时器超时仅单向置位 `abort_event` 标志；位姿归位严格移至主线程安全返回后执行一次。
- **测试佐证**：
  - 主包 344 项标准库测试全面覆盖状态机边界、非合法参数防御与超时竞争。
- **状态标签**：`● 已完成`
- **讲者一句**：我们彻底根除了早期测试中的假成功逻辑，强校验感知真值并规范线程安全超时，确保机器人动作执行真实可靠。

### P08 · 小脑内核：正弦步态、动作库与限位安全
- **页眉**：03  软件契约
- **标题**：正弦步态在线解算，动作库 JSON 驱动，拒绝 NaN/Inf 保护电机
- **导语**：小脑层统一负责步态轨迹生成与多轴时序插补，全通道硬件安全限位硬隔离。
- **模块一 · 双足正弦步态生成器（`generate_gait`）**：
  - 参数化周期：周期 0.8 s，采样频率 50 Hz（控制周期 20 ms），左右腿正弦半相交替（相差 $\pi$）。
  - 参数映射：步长系数 `step_length_cm`（线性换算髋俯仰）与抬脚系数 `step_height_cm`（换算膝关节抬高）。
  - 躯干动态调平：躯干俯仰（1.5°）与摆动腿协同微倾，躯干侧倾（1.0°）按半频引入微调补偿。
- **模块二 · 关键帧动作库规范（`ActionLibrary`）**：
  - 格式规范：JSON 描述关键帧时序序列 `{frames: [{duration_s, joints: {...}}]}`。
  - 解耦价值：调试复杂舞蹈或预备抓取位姿无需改动 Python 源码，直接更新动作库数据即可热加载生效。
- **模块三 · 动力学边界与数值安全防御**：
  - 全通道限位钳制：所有关节目标角统一经过 `set_angle()` 的 `min/max` 范围钳制，底层仅需实现 `_write_angle()`。

  - 整机重载平均电流：**约 7.25 A**（11.1 V 供电系统）。
- **续航核算与瓶颈暴露**：
  - 现有方案：选配 **2000 mAh**（3S 25C）电池组，计算重载工作时间：
    $$T = \frac{2.0\text{ Ah} \times 0.8\text{（放电深度）}}{7.25\text{ A}} \times 60 \approx \mathbf{13.2\text{ 分钟}}$$
  - 赛题硬指标：要求现场连续自主作业 **≥ 30 分钟**。
  - 理论需求容量：逆推得出实际所需标称电池容量 **$\ge 4.53\text{ Ah}$**。
- **工程挑战说明**：换装 4.53 Ah 电池将导致电池自重增加约 180 g，会进一步加剧踝腰关节扭矩负担，需系统级权衡。
- **状态标签**：`○ 规划中`
- **讲者一句**：按整机 7.25 A 功耗测算，现有 2000 mAh 电池仅能维持 13 分钟，要达成赛题 30 分钟连续作业，后续必须换装 4.53 Ah 以上的高比能电池组。
