## 1. 项目概述

A.T.R.I. 面向小人形组五项任务：人脸识别、二维码循迹、物品搬运、体育运动、娱乐休闲。它是一台约 40.7 cm 的 22 自由度桌面双足人形：双腿 10、双臂 8、躯干 2、头部 2，全机 22 只飞特 STS3215。软件用 JSON 任务卡 + FSM 调度，默认全离线、不断网。

本计划书诚实区分三层证据：**数据集 / 合成图 / 代码路径**已经可复现；**带重力仿真录屏**脚本已具备、画面未录；**样机与赛场指标**全部未测。我们不把第一层写成第三层。

- 实装包络：**407 × 268 × 160 mm**（高×宽×深），赛题上限 600×300×300。
- 结构件 CAD 实算 **1383.8 g / 81 件**（上限）；整机纸面约 **3029.8 g**，重量方案未定案。
- 软件主包当场测试：**639 项 OK**（零依赖 skip 46）；Webots 离线桩 **41 项**。CAD 布局门禁 17 项。

**现状一句话**：设计冻结 + 离线软件可复现 + CAD 可打印；**样机尚未制造**（未测项 A1）。赛题要的实物展示视频 ≤3 分钟仍缺实物。

## 2. 技术方案

软件分三层，避免「演示脚本各写一份」：

1. **大脑**：JSON 任务卡描述五项赛题；FSM 按 ENTERING → EXECUTING → FEEDBACK → DONE 调度；技能失败熔断，禁止假成功。
2. **小脑**：步态、侧踢、22 轴短舞、限位钳制；`NaN/Inf` 直接拒绝下发。
3. **总线**：开发期 `MockServoBus`；真机路径 `Sts3215Bus`（装配后必须回填 `sign` / `zero_pulse`，目前标定文件是空的）。

感知走统一 `PerceptionResult`。人脸真识别 = YuNet + SFace + `FaceDB` + 显式拒识；二维码三解码器对照后主用 WeChatQRCode，载荷 `atri.path.v1`；搬运/踢球用 HSV 色块，距离未标定则标 `uncalibrated`。语音默认 Mock 关键词；可选 vosk 惰性导入，没引擎不算听清。

仿真：默认 `webots/worlds/atri_22dof.wbt` 是 **gravity 0、无地面** 的运动学联调世界，CI 钉死不得覆盖。带重力派生世界由 `webots/tools/make_gravity_world.py` 写出（`gravity -9.81`、`maxTorque 2.94`×22、`Plane`）。**只有派生世界才能谈「站得住」；默认世界不能。** GUI 录屏步骤见 `docs/process/sim/重力世界录屏脚本.md`，本机无 Webots。

机械：包络 407×268×160 mm；81 件 PETG 关节笼 + 叉 + 管；零位摆放错误 0。扭矩主判据 **0.98 N·m**，踝 147.5% 最紧，10 个腿部关节超额定——这是已知风险，不是隐瞒项。

## 2.1 五项任务怎么接到同一套栈上

每张任务卡只声明「做什么」，不内嵌算法。换场景 = 换 JSON。无硬件时 `run_demo.py --fast` 可 5/5 走完流程；这证明的是调度与技能契约，**不是**赛场完成度。技能层强制带 `source`（recognition / perception / params），答辩时按字段解释数字从哪来。

## 3. 五项任务（赛题原文 → 我们做了什么 → 不能写成什么）

| 赛题 | 软件现状 | 材料里禁止写 |
|---|---|---|
| ① 人脸识别 | 真识别 + 拒识；LFW 困难协议 50 人 rank-1 98.6%；头部开环随动 | 把 LFW 写成实机成功率 |
| ② 二维码循迹 | `atri.path.v1` 多段路径；合成图 WeChat 6/6、指令 10/10 | 把合成图写成真相机；到位误差 ≤50 mm（未测 A3） |
| ③ 物品搬运 | 没对准不夹、没看见地标不放；合成图推荐参数 20/20 | 抓取成功率 ≥80%（未测 B6） |
| ④ 体育运动 | 绿球多轮闭环，不收敛也踢但回报 `converged` | 踢球成功率 ≥70%（未测 B7） |
| ⑤ 娱乐休闲 | 关键词白名单 + 22 轴短舞 + TTS；无 ASR | 声纹 / 跟着音乐跳 / 赛场噪声识别率 |

## 4. 创新点（可写，不夸大）

1. **一张任务卡调度五项赛题**：人脸 / 二维码路径 / 搬运两步对准 / 踢球闭环 / 舞蹈门闩共用 FSM 与失败熔断，换场景不重写主程序。
2. **失败比假成功更值钱**：没对准不夹、没看见地标不放、听不清说没听清、认不出拒识。材料里把这些写成工程纪律，而不是成功率。
3. **数字带出处**：`source` 字段、LFW / 合成图 / 几何评测分栏、未测项单独成表。评委问「测过没有」可以直接翻表。
4. **22 DOF 含躯干 2 轴**：对齐小人形组「上肢躯干 ≥10」（是否含头待主办方确认，D1）。桌面尺度全机统一 STS3215，新增采购压在约 2725–3260 元。
5. **默认世界与派生世界分开**：CI 钉死 gravity 0 的可复现联调；带重力校核另生成，避免「改默认世界导致测试漂移」。

## 5. 可行性与风险

| 维度 | 已具备 | 卡点（不粉饰） |
|---|---|---|
| 几何检录 | 包络在 600×300×300 内；高度余量 +193 mm | 内部宽门禁 270 mm **只剩 2 mm**（肩部错轴代价） |
| 软件 | 当场 **Ran 639 + Ran 41** 全绿；无硬件 5/5 | 真相机 / 真平衡 / 真串口未联调 |
| 制造 | 81 件可出 STEP/STL；宿舍级 FDM 可打 | **尚未打印、尚未装配**（A1/A5） |
| 力矩 | 缺口已记账；主判据 0.98 N·m，不拿 1.47 峰值冒充达标 | 踝 **147.5%** 额定，10 个腿部关节超额定；12V 实物温升未测（A4） |
| 电源 | 缺口已记账 | 现选 3S 2000 mAh **模型约 13 min**，**不得写 30 分钟续航**（B4）；加大电池会反推扭矩 |
| 仿真 | 22 轴映射离线桩 41 项 | 默认世界 **gravity 0**，不能证明站得住；带重力世界可生成，GUI 录屏 **TODO** |
| 视频 | 路线 B CAD 渲染可保底 | 必须标明「渲染动画，非物理仿真」；路线 A 依赖队友机器 |

## 9. 未测项诚实声明

**我们还没有样机。** 下列指标只有设计值 / 仿真值 / 数据集值，**不是这台机器人在真实赛场上量出来的**。
完整表见 `docs/process/未测项清单.md`。答辩若被问行走 1 m、抓取成功率、续航、实机识别率：**答未测，并指出测它需要样机 + 哪条命令**。不编造。

### 9.1 阻断级

- 样机尚未制造（A1）
- 双足连续行走 ≥ 1 m（A2）—— Webots 跑通的是任务流程 5/5，不是「走了 1 米不倒」
- 路径到位误差 ≤ 50 mm（A3）
- STS3215 真实连续扭矩与温升（A4）
- 整机能否站起来 / 减重是否成立（A5）

### 9.2 重要级（材料里最容易写过头）

- T-01 实机距离档与现场光照（B1）—— **LFW ≠ 实机**
- T-02 真相机（B2）—— **合成畸变 ≠ 反光/模糊/打印质量**
- 树莓派耗时（B3）；满电 ≥30 min（B4）；TTS ≤1 s（B5）
- 抓取成功率 ≥80%（B6）—— **合成图闭环 ≠ 实机抓取**
- 踢球成功率 ≥70%（B7）；样机上的离线关键词识别（B8）
- 相机内参 / 夹爪容差（B9/B10）

### 9.3 已闭合但只在各自条件下成立

- 人脸：LFW rank-1（不是实机）
- 二维码：合成图 WeChat 6/6、回放 10/10（不是真相机；到位误差仍未测）
- 搬运：合成图色块 23/23、推荐参数闭环 20/20（不是夹爪实物）
