## 1. 项目概述

A.T.R.I. 面向小人形组五项任务：人脸识别、二维码循迹、物品搬运、体育运动、娱乐休闲。它是一台约 40.7 cm 的 22 自由度桌面双足人形：双腿 10、双臂 8、躯干 2、头部 2，全机 22 只飞特 STS3215。软件用 JSON 任务卡 + FSM 调度，默认全离线、不断网。

本计划书诚实区分三层证据：**数据集 / 合成图 / 代码路径**已经可复现；**带重力仿真录屏**脚本已具备、画面未录；**样机与赛场指标**全部未测。我们不把第一层写成第三层。

- 实装包络：**407 × 268 × 160 mm**（高×宽×深），赛题上限 600×300×300。
- 结构件 CAD 实算 **1383.8 g / 81 件**（上限）；整机纸面约 **3029.8 g**，重量方案未定案。
- 软件主包当场测试：**639 项 OK**（零依赖 skip 46）；Webots 离线桩 **41 项**。CAD 布局门禁 17 项。

**现状一句话**：设计冻结 + 离线软件可复现 + CAD 可打印；**样机尚未制造**（未测项 A1）。赛题要的实物展示视频 ≤3 分钟仍缺实物。

## 2. 技术方案

软件分三层，避免「演示脚本各写一份」：

1. **大脑**：JSON 任务卡描述五项赛题；FSM 按 ENTERING → EXECUTING → FEEDBACK → DONE 调度；技能失败熔断，禁止假成功。
2. **小脑**：步态、侧踢、22 轴短舞、限位钳制；`NaN/Inf` 直接拒绝下发。
3. **总线**：开发期 `MockServoBus`；真机路径 `Sts3215Bus`（装配后必须回填 `sign` / `zero_pulse`，目前标定文件是空的）。

感知走统一 `PerceptionResult`。人脸真识别 = YuNet + SFace + `FaceDB` + 显式拒识；二维码三解码器对照后主用 WeChatQRCode，载荷 `atri.path.v1`；搬运/踢球用 HSV 色块，距离未标定则标 `uncalibrated`。语音默认 Mock 关键词；可选 vosk 惰性导入，没引擎不算听清。

仿真：默认 `webots/worlds/atri_22dof.wbt` 是 **gravity 0、无地面** 的运动学联调世界，CI 钉死不得覆盖。带重力派生世界由 `webots/tools/make_gravity_world.py` 写出（`gravity -9.81`、`maxTorque 2.94`×22、`Plane`）。**只有派生世界才能谈「站得住」；默认世界不能。** GUI 录屏步骤见 `docs/process/sim/重力世界录屏脚本.md`，本机无 Webots。

机械：包络 407×268×160 mm；81 件 PETG 关节笼 + 叉 + 管；零位摆放错误 0。扭矩主判据 **0.98 N·m**，踝 147.5% 最紧，10 个腿部关节超额定——这是已知风险，不是隐瞒项。

## 2.1 五项任务怎么接到同一套栈上

每张任务卡只声明「做什么」，不内嵌算法。换场景 = 换 JSON。无硬件时 `run_demo.py --fast` 可 5/5 走完流程；这证明的是调度与技能契约，**不是**赛场完成度。技能层强制带 `source`（recognition / perception / params），答辩时按字段解释数字从哪来。

## 4. 创新点（可写，不夸大）

1. **一张任务卡调度五项赛题**：人脸 / 二维码路径 / 搬运两步对准 / 踢球闭环 / 舞蹈门闩共用 FSM 与失败熔断，换场景不重写主程序。
2. **失败比假成功更值钱**：没对准不夹、没看见地标不放、听不清说没听清、认不出拒识。材料里把这些写成工程纪律，而不是成功率。
3. **数字带出处**：`source` 字段、LFW / 合成图 / 几何评测分栏、未测项单独成表。评委问「测过没有」可以直接翻表。
4. **22 DOF 含躯干 2 轴**：对齐小人形组「上肢躯干 ≥10」（是否含头待主办方确认，D1）。桌面尺度全机统一 STS3215，新增采购压在约 2725–3260 元。
5. **默认世界与派生世界分开**：CI 钉死 gravity 0 的可复现联调；带重力校核另生成，避免「改默认世界导致测试漂移」。

## 4.1 五项任务的技术实现（逐条）

**① 人脸识别。** 取帧 → YuNet 检测 → 5 点对齐 → SFace 128 维特征 → `FaceDB` 余弦比对 → 播报或拒识。两条纪律：相似度不过阈值就说「我不认识你」，绝不从任务卡借一个名字；结果必须带 `source`。识别成功后把头两轴按目标框开环对准。退化的参数兜底通路保留，但演示日志必须打印 `source="params"`，不得当成识别率。LFW 困难协议 50 人 rank-1 98.6% 是**公开数据集**数字，实机距离档 0.5/1.0/1.5 m 与现场光照仍未测（B1）。

**② 二维码循迹。** 赛题要的是「识别二维码并按指示路径行走」，不是沿黑线巡线。载荷用带版本号的 `atri.path.v1`（`{"schema":"atri.path.v1","path":[...]}`），旧单动作格式继续兼容。三个解码器对照后主用 WeChatQRCode。整条路径**先校验再动手**，任一段失败即停。合成畸变图上判据条件 6/6、指令回放 10/10；真实相机的反光/运动模糊/打印质量未测（B2），到位误差 ≤50 mm 未测（A3，小脑只有标称位移）。

**③ 物品搬运。** 两步对准、两步都要「看见」：目标物色块多轮横向伺服进死区才夹；走到位后若放置区地标通道已接入，先对准再释放，**没看见地标就停住不释放**。夹取门槛 `grasp_tolerance_cm` 默认等于死区——没对准就不夹，宁可失败也不盲抓。控制常数全部走 `config/carry.json`（任务卡 > 文件 > 代码默认）。合成图 + 一维几何下默认参数 11/20、推荐参数 20/20；实机抓取成功率与夹爪容差未测（B6/B10）。

**④ 体育运动（踢球）。** 绿球 HSV 阈值 → 多轮 `lateral_servo` 偏航闭环 → 按球的横向符号选左/右脚侧踢。踢球是「接触即尽力而为」：迭代封顶仍不收敛**也会踢**，但结果里必须回报 `iterations` / `converged`，不许把「凑合踢」写成「对准了」。距离门闩 4–40 cm 外直接失败且不下发动作。一维几何评测：默认 20/24 技能 ok、收敛 11/24；推荐参数收敛 20/24。实机成功率未测（B7）。

**⑤ 娱乐休闲。** 语音通道（可选）→ 关键词白名单 → 可选本地 wav（无播放器标 `audio=unavailable`）→ `cerebellum.dance()` 22 轴短舞 → TTS。通道已接入却听不清，就说「我没听清」并判失败，不拿任务卡关键词冒充听清。可选 vosk 惰性后端：没装引擎时 `available()=False`，`build_recognizer()` 返回 None，不静默降级成 Mock。没有声纹、没有节拍同步；赛场噪声识别率未测（B8）。

### 5.1 三个最硬的风险与对策

**风险一：扭矩余量为负。** 踝关节需求 1.446 N·m = 连续额定的 147.5%，膝 141.2%、髋 pitch 134.1%，共 10 个腿部关节超额定。腰 `trunk_roll` 零姿态 41.1% / 最不利 45.1%，不超。本项目**不把峰值 1.47 N·m 当达标**。对策：① 结构减重（现行 CAD 已从 1490 g 降到 1383.8 g，仍是上限口径）② 控制上降额运行——默认限流、禁止把单腿支撑当静止保持姿态、禁止长时间「躯干倾斜 + 双臂外伸」③ 采购 1 只 12V 实物舵机测连续扭矩与温升（约 90 元，A4）。纸面反解已说明：只减结构无解，必须同时接受降额。

**风险二：续航与赛题 30 分钟差一倍以上。** 现选 3S 2000 mAh 按现行电流模型约 13 分钟。要满足 30 分钟需标称 ≥10.40 Ah，整包重量约 1.05 kg——会反过来加重腿部扭矩缺口。对策：把「降额运行」同时当续航杠杆；若晋级，重新平衡电池容量、整机质量与踝关节余量，而不是只换一块更大的电池。

**风险三：没有样机，实物视频这条硬要求无法由软件补。** 赛题要实物展示视频 ≤3 分钟。当前能出的是**仿真录屏**（带重力世界，脚本已就绪，需 Webots GUI）与**CAD 渲染动画**（本机可出片，但只能证明几何与关节点位，**不是物理仿真**）。对策：两条路线都准备，材料里逐帧标注是哪一种；借用样机后立刻补 S1 静立、S2 扭矩探针、T-03/T-05 任务卡三段实拍。

## 9. 未测项诚实声明

**我们还没有样机。** 下列指标只有设计值 / 仿真值 / 数据集值，**不是这台机器人在真实赛场上量出来的**。
完整表见 `docs/process/未测项清单.md`。答辩若被问行走 1 m、抓取成功率、续航、实机识别率：**答未测，并指出测它需要样机 + 哪条命令**。不编造。

### 9.1 阻断级

- 样机尚未制造（A1）
- 双足连续行走 ≥ 1 m（A2）—— Webots 跑通的是任务流程 5/5，不是「走了 1 米不倒」
- 路径到位误差 ≤ 50 mm（A3）
- STS3215 真实连续扭矩与温升（A4）
- 整机能否站起来 / 减重是否成立（A5）

### 9.2 重要级（材料里最容易写过头）

- T-01 实机距离档与现场光照（B1）—— **LFW ≠ 实机**
- T-02 真相机（B2）—— **合成畸变 ≠ 反光/模糊/打印质量**
- 树莓派耗时（B3）；满电 ≥30 min（B4）；TTS ≤1 s（B5）
- 抓取成功率 ≥80%（B6）—— **合成图闭环 ≠ 实机抓取**
- 踢球成功率 ≥70%（B7）；样机上的离线关键词识别（B8）
- 相机内参 / 夹爪容差（B9/B10）

### 9.3 已闭合但只在各自条件下成立

- 人脸：LFW rank-1（不是实机）
- 二维码：合成图 WeChat 6/6、回放 10/10（不是真相机；到位误差仍未测）
- 搬运：合成图色块 23/23、推荐参数闭环 20/20（不是夹爪实物）

## 9.5 本阶段工作总结（写给评委）

到目前为止，本项目在**没有样机、没有采购经费**的条件下完成了三件可核查的事：

1. **把赛题五条在离线软件里逐条做实**，每条都有对应报告写明「测的是什么、不是什么」，而不是只交一份演示录像。人脸与二维码走真模型、真解码；搬运与踢球走真检测器 + 真技能类；舞蹈走真门闩。主包当场 639 项测试、Webots 41 项测试全绿，四条命令可现场复现。
2. **把机械设计冻结到可打印**：81 件、包络 407×268×160 mm、零位摆放错误 0、17 项布局门禁通过，并给出材料与减重决策表。同时把**扭矩缺口如实记账**，没有用峰值冒充达标。
3. **建立了一套「未测项」纪律**：任何写进材料的能力都要能回答「哪条命令、哪份报告能证明」。答不上来的进 `docs/process/未测项清单.md`，分阻断级 / 重要级 / 背景级 / 待主办方确认，共 20 余项。这份表是本项目最不像学生作业的地方。

下一步的唯一瓶颈是**样机**。它一旦到手，标定、行走 1 m、实机抓取与踢球、续航与温升都能在两周内出数——测试脚本、评测工具、标定文件入口都已经准备好（`tools/face_enroll.py`、`tools/qr_eval.py`、`tools/carry_eval.py`、`tools/kick_eval.py`、`config/calibration.json`、`config/odometry.json`）。
