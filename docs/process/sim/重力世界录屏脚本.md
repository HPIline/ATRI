> 给**有 Webots GUI 的队友机器**用。本机（Mac）可能没有 Webots，
> 本文件里的 `webots …` 命令**本机未实测**，请按原文复制、按「期望」核对。
>
> 对应：`webots/README.md`「带重力/带地面的校核跑法」、
> `design/handoff/仿真请求-Webots验证清单.md` S1/S2/S5、
> `docs/contest/提交材料清单.md` §二（视频 ≤100 MB，建议 720p / ≤3 分钟）。
>

## 0. 先把口径钉死（录之前必读）

### 0.1 只有带重力世界才能谈「站得住」

| 世界 | 路径 | gravity | 地面 | maxTorque | 能证明什么 |
|---|---|---|---|---|---|
| **默认（CI 钉死）** | `webots/worlds/atri_22dof.wbt` | **0** | 无 | 不写（Webots 默认 10 N·m） | 22 个关节角有没有下发/跟随。**不能**证明站立 |
| **校核派生** | `docs/process/sim/worlds/atri_22dof_gravity.wbt` | **-9.81** | `Plane` 4×4 m | **2.94 N·m × 22** | 静立、站立扭矩、带接触的动作 |

默认世界是**零重力运动学联调**世界：机器人悬浮、不下垂，电机静力矩 ≈ 0。
用它录的「静立 10 s」看起来像站住了，数字全是废的，**不许进答辩材料**，
也不许写成「仿真证明站得住」。

带重力世界才是 S1 / S2 / 答辩视频路线 A 的输入。它仍然是**刚体仿真值**，
不是实测，材料里必须写「仿真」。

### 0.2 本机可能没有 Webots GUI

- 生成脚本只做：调用生成器 → 写派生 `.wbt` → grep 自检 → 打印命令。
- **不**打开 Webots、**不**录屏、**不**压码。这些步骤全部交给队友。
- 若本机 `command -v webots` 为空：跳过第 2 节以后的命令，只交世界文件 + 本清单。

### 0.3 平台硬限制（提交材料清单 §二）

- 附件视频 **mp4 ≤ 100 MB**；建议总时长 **≤ 3 分钟**。
- 推荐编码：**720p30 @ 4 Mbps H.264**（约 30 MB/min → 3 分钟 ≈ 90 MB，留余量）。
- 1080p30 @ 6 Mbps ≈ 45 MB/min，只能稳妥放 ≤2 分钟。
- **不要**用相机默认 12 Mbps，1 分钟就可能超限。

### 0.4 三条不许混用的词

仿真 / 渲染动画 / 实测。路线 A（本清单）是 **Webots 物理仿真录屏**；
路线 B（`design/cad/tools/make_pose_video.py`）是 **CAD 渲染动画，非物理仿真**。
不许把默认零重力世界的画面说成「站得住」。

## 1. 生成带重力世界（本机或队友都可以跑）

仓库根目录：

```bash
python3 webots/tools/make_gravity_world.py
```

它内部就是：

```bash
python3 webots/tools/generate_atri_world.py \
  --gravity=-9.81 --max-torque=2.94 --ground \
  --out docs/process/sim/worlds/atri_22dof_gravity.wbt
```

（Windows PowerShell 必须写成 `--gravity=-9.81` 这种 `=` 形式，否则 `-9.81` 会被当成参数名。）

生成后自检（脚本会自己 grep；手工复核用下面三条，**三条都过再录**）：

```bash
W=docs/process/sim/worlds/atri_22dof_gravity.wbt
grep -c "gravity -9.81" "$W"     # 期望 1
grep -c "maxTorque 2.94" "$W"    # 期望恰好 22
grep -cE "Floor|Plane" "$W"      # 期望 ≥1
```

**禁止**覆盖 `webots/worlds/atri_22dof.wbt`。CI 会重跑无开关的生成器并 `git diff --exit-code`。

## 2. 运行前：让 Webots 找得到控制器

Webots 在「世界文件所在 **project** 的 `controllers/`」里找控制器。
派生世界若留在 `docs/process/sim/worlds/`，project 就变成 `docs/process/sim/`，
那里没有 `controllers/atri_controller`——表现是报告 JSON 一直不出现、
控制台可能报找不到控制器。**本机没装 Webots，这一条未实测。**

**推荐（办法 1）**：复制到 `webots/worlds/` 再打开（project 不变）：

```bash
# Linux / macOS
cp docs/process/sim/worlds/atri_22dof_gravity.wbt \
   webots/worlds/atri_22dof_gravity.wbt
```

```powershell
# Windows
Copy-Item docs\process\sim\worlds\atri_22dof_gravity.wbt `
          webots\worlds\atri_22dof_gravity.wbt
```

这个 `webots/worlds/atri_22dof_gravity.wbt` 是**运行副本，不要提交**。
下面命令里的 `$W` 一律指这份运行副本。

**办法 2**：保持 `docs/process/sim/worlds/` 不动，把
`webots/controllers/atri_controller/` 整目录复制成
`docs/process/sim/controllers/atri_controller/`（S2 还要再复制 `torque_probe`）。

确认控制器起来的标志：控制台出现 `A.T.R.I. Webots 控制器启动`（S1/T-05）
或 `[torque_probe] 已绑定 + 扭矩反馈:`（S2）。

下面统一：

```bash
W=webots/worlds/atri_22dof_gravity.wbt
```

```powershell
$W = "webots\worlds\atri_22dof_gravity.wbt"
```

## 3. 录屏通则（三段共用）

### 3.1 启动方式

```bash
# Linux / macOS —— 录屏必须 realtime，不要 fast
webots --mode=realtime "$W"
```

```powershell
webots --mode=realtime $W
```

| 要 | 不要 |
|---|---|
| `--mode=realtime` | `--mode=fast`（动作加速，录出来看不清） |
| GUI 窗口可见 | `--batch --no-rendering --minimize`（那是跑数用的） |
| 工具栏 ▶ 运行后再录 | 暂停状态录黑屏/静帧 |

Webots 自己也可以点工具栏录像按钮；没有的话用系统录屏
（Windows：Win+G；macOS：Cmd+Shift+5；Linux：OBS / SimpleScreenRecorder）。

### 3.2 建议机位（清单 S5）

| 机位 | 建议 | 用途 |
|---|---|---|
| 主（等轴测） | 约 `(0.45, -0.45, 0.35)` 看向 `(0, 0, 0.19)` | 脸、手、脚、地面同时入画 |
| 侧视 | 沿 ±Y 看 XZ 面 | **侧翻 / 重心**，正视看不出来 |
| 足部特写 | 脚盒与 `Plane` 接触 | S1「着地」证据 |

世界文件里已有一个 Viewpoint，打开后可再在 View 里微调。
**录的时候不要裁掉锁盘配合面**——那是真实装配关系，不是穿模。

### 3.3 单段时长

| 段 | 内容 | 建议时长 |
|---|---|---|
| S1 | 双足静立，能看清脚在地面上、10 s 不倒 | 15–20 s（含 10 s 静立） |
| S2 | 零位站姿 + 控制台/报告里的扭矩峰值（可切画面） | 15–20 s |
| T-05 | 舞蹈任务卡动作 | 20–30 s |
| **合计** | 三段以内 | **≤ 3 分钟**（含片头/字幕） |

答辩时间紧，宁短勿长。三件事必须能看清：
**脚在地面上、关节在动、任务卡在跑**。

### 3.4 分辨率 / 帧率

- 录制：窗口拉到 ≥1280×720，30 fps。
- 提交：压成 **1280×720 @ 30 fps、H.264、约 4 Mbps**。
- 不要 4K。RTX 4060 够 1080p，但体积和邮件都吃不消。

## 4. S1 · 静立 10 s

**目的**：带重力 + 地面下，双足站 10 s 是否翻倒。这是「站得住」的最小证据。

**不要**拿 `run_webots_batch` 的退出码判定 S1：空任务卡目录会让
`passed=0 / total=0`，脚本以 2 退出——这是预期，只看 JSON / 画面。

### 4.1 准备

```bash
mkdir -p docs/process/sim/empty_cards
# 确认该目录里没有任何 *.json
```

```powershell
New-Item -ItemType Directory -Force docs\process\sim\empty_cards | Out-Null
```

### 4.2 GUI 录屏（推荐）

```bash
export ATRI_WEBOTS_MAX_TORQUE=2.94
export ATRI_WEBOTS_TASK_CARD_DIR=docs/process/sim/empty_cards
unset ATRI_WEBOTS_EXIT_ON_DONE          # 录屏时不要跑完就退
webots --mode=realtime "$W"
```

```powershell
$env:ATRI_WEBOTS_MAX_TORQUE = "2.94"
$env:ATRI_WEBOTS_TASK_CARD_DIR = "docs\process\sim\empty_cards"
Remove-Item Env:ATRI_WEBOTS_EXIT_ON_DONE -ErrorAction SilentlyContinue
webots --mode=realtime $W
```

操作：点运行 → 等回零稳定 → **再录至少 10 s 静立**（侧视或等轴测，脚必须入画）→ 停。
建议再切一次足部特写 5 s。

### 4.3 同时跑数（可选，不录）

```bash
export ATRI_WEBOTS_MAX_TORQUE=2.94
export ATRI_WEBOTS_TASK_CARD_DIR=docs/process/sim/empty_cards
bash webots/tools/run_webots_batch.sh \
  -World "$W" \
  -Report docs/process/sim/s1_report.json \
  -Log    docs/process/sim/s1_console.log \
  -TimeoutSec 600
```

```powershell
$env:ATRI_WEBOTS_MAX_TORQUE = "2.94"
$env:ATRI_WEBOTS_TASK_CARD_DIR = "docs\process\sim\empty_cards"
powershell -File webots\tools\run_webots_batch.ps1 `
  -World  $W `
  -Report docs\process\sim\s1_report.json `
  -Log    docs\process\sim\s1_console.log `
  -TimeoutSec 600
```

看 `s1_report.json`：`simulation_alive: true`、`bound_joints: 22`、
`max_torque_nm: 2.94`。`joint_travel_deg` 应接近 0（真的站住，不是在跳舞）。

### 4.4 要记的画面 / 数字

- 10 s 内倾倒 / 未倾倒（仿真值，目视）。
- 脚盒与 `Plane` 接触的特写。
- 若 GUI 开了 Center of Mass：质心投影截图。
- 世界参数写进报告：`gravity=-9.81`、`basicTimeStep=32`、`maxTorque=2.94`（×22）。

失败先查：穿地或悬浮 → `translation 0 0 0.1942` 被改了；抖动 → 派生副本里把
`basicTimeStep` 改成 8 再试，并在报告注明；站得过于轻松 → `maxTorque` 还是默认 10。

## 5. S2 · 扭矩探针

**目的**：零位站姿保持 10 仿真秒，逐关节 `|τ|` 峰值，对照
**0.98 / 1.47 / 2.94 N·m** 三档。重点看踝 pitch、`trunk_roll`、髋 pitch。

`atri_controller` **不读扭矩**。仓库已有独立控制器：

```
webots/controllers/torque_probe/torque_probe.py
```

它会写 `docs/process/sim/s2_torque_peak.json`（相对 **Webots 启动时的 cwd**）。
**请从仓库根目录启动 webots**，否则 JSON 会写到别处。

### 5.1 把 Robot.controller 指到探针

**不要改** `docs/process/sim/worlds/atri_22dof_gravity.wbt` 源文件
（下次 `make_gravity_world.py` 会覆盖）。只改运行副本：

1. 打开 `$W`；
2. Scene Tree → `Robot` → `controller` 从 `atri_controller` 改成 `torque_probe`；
3. 保存运行副本（仍是 `webots/worlds/atri_22dof_gravity.wbt`，不提交）。

`torque_probe` 与 `atri_controller` 同在 `webots/controllers/` 下，办法 1 的
project 能直接找到。若走办法 2，还要把 `webots/controllers/torque_probe/`
复制到 `docs/process/sim/controllers/torque_probe/`。

### 5.2 GUI 录屏

```bash
# 从仓库根目录启动，好让探针把 JSON 写到 docs/process/sim/
cd /path/to/ATRI
webots --mode=realtime "$W"
```

点运行 → 看控制台刷 `[torque_probe] 已绑定 + 扭矩反馈:`（期望 22 行）→
保持 ≥10 s → 停。画面：机器人站着 + 控制台峰值（或事后打开 JSON 做字幕）。

### 5.3 期望产物

`docs/process/sim/s2_torque_peak.json` 里应有
`peak_abs_torque_nm` / `min_torque_nm` / `max_torque_nm` / `final_joint_deg`。

自检：`final_joint_deg` 应接近 0（肘 ≈ −10）。
若腿软下去、关节被压到限位——**2.94 N·m 撑不住这个站姿，这本身就是结论**，
照实写，不要把 `maxTorque` 调大再跑。

对照三档都要给，别只写一个「合格」。纸面需求踝 1.492、`trunk_roll` 1.899 N·m
已超额定；仿真大概率低于纸面（世界质量 3136.6 g，盒子脚）——
**写成「仿真偏保守，不能据此宣布合格」**。

### 5.4 录完改回去

运行副本的 `controller` 改回 `atri_controller`，否则下一段 T-05 会继续跑探针。

## 6. T-05 · 舞蹈

## 7. 怎么录、怎么压到 720p / ≤100 MB

### 7.1 原始素材落盘

```
docs/process/sim/video/
  S1_静立_YYYYMMDD.mp4          # 或 Webots/系统录屏的原始文件
  S2_扭矩探针_YYYYMMDD.mp4
  T05_舞蹈_YYYYMMDD.mp4
  ATRI-webots-demo.mp4          # 剪完 + 压完，准备提交的那一条
```

原始文件可以先 1080p；**提交那一条**必须过体积关。

### 7.2 剪什么

建议顺序（总 ≤3 min）：

1. 2–3 s 片头：项目名 + 「Webots 带重力仿真，非实测」。
2. S1 静立（侧视 + 足部特写）。
3. S2 站姿 + 屏幕字：踝 / `trunk_roll` 峰值（仿真值，单位 N·m）。
4. T-05 舞蹈。
5. 2 s 片尾：世界参数 `gravity=-9.81` / `maxTorque=2.94` / `basicTimeStep=32`。

不要配「30 分钟续航」「已实测站立」这类仓库纪律禁止的词。

### 7.3 压缩（按机器有什么用什么）

目标：**1280×720、30 fps、H.264 yuv420p、约 4 Mbps、mp4 ≤100 MB**。

**A. 系统有 ffmpeg**

```bash
ffmpeg -i docs/process/sim/video/ATRI-webots-demo-src.mp4 \
  -vf scale=1280:720 \
  -c:v libx264 -preset medium -b:v 4M -maxrate 4M -bufsize 8M \
  -r 30 -pix_fmt yuv420p \
  -c:a aac -b:a 128k \
  -movflags +faststart \
  docs/process/sim/video/ATRI-webots-demo.mp4

ls -lh docs/process/sim/video/ATRI-webots-demo.mp4
# 必须 < 100 MB；仍超就改 -b:v 2.5M 或再剪时长
```

**B. 本机 Mac 有 `avconvert`，但只吃单个媒体文件**

```bash
# 输入必须已经是视频，不能是 PNG 序列
avconvert --source docs/process/sim/video/ATRI-webots-demo-src.mp4 \
          --output docs/process/sim/video/ATRI-webots-demo.mp4 \
          --preset Preset640x480     # 若体积仍大；具体 preset 以 man avconvert 为准
```

`avconvert` **不吃图片序列**。队友在 Windows 上应优先用 ffmpeg / HandBrake。

**C. ATRI 仓库 `.venv-cad` 里的 imageio-ffmpeg（Mac 保底转码）**

```bash
FFMPEG=$(.venv-cad/bin/python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())")
"$FFMPEG" -i docs/process/sim/video/ATRI-webots-demo-src.mp4 \
  -vf scale=1280:720 -c:v libx264 -b:v 4M -r 30 -pix_fmt yuv420p \
  -an -movflags +faststart \
  docs/process/sim/video/ATRI-webots-demo.mp4
```

**D. Windows 无 ffmpeg 时**：HandBrake 预设
「Gmail Large 3 Minutes 720p30」，或剪映/CapCut 导出 720p、码率 4 Mbps。

### 7.4 体积速算（提交材料清单 §二）

| 方案 | 大约 | 3 分钟 |
|---|---|---|
| 720p30 @ 4 Mbps | ≈30 MB/min | ≈90 MB ✅ |
| 1080p30 @ 6 Mbps | ≈45 MB/min | ≈135 MB ❌ 超 |
| 1080p30 @ 12 Mbps（相机默认） | ≈90 MB/min | 只能约 1 分钟 |

压完用资源管理器 / `ls -lh` 看字节，不要只看「看起来不大」。
