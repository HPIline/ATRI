| 5 | `left_forearm` ↔ `pelvis` | **29 430** | 27.8% | `shoulder_roll` -49.2°、`elbow` -1.5° |

- **最扎眼的一条**：`left/right_gripper` ↔ `left/right_hip_yaw_link` 各 **9 383 mm³（31.9%）**，

  含义：**手臂内收 + 肘折叠 + 膝大角度**是动态碰撞的三个主要来源，而当前限位全都放到 100%
  （`shoulder_roll` ±90°、`elbow` -120…0、`knee` 0…90、`hip_yaw` ±45°）。

## 4. 顺手挖出的一个**真 BUG**：生成的 Webots 世界是坏的（已修）

**症状**：联调报告 5/5 通过、22/22 绑定，但 **有行程关节只有 11/22**，而 `webots/README.md`
记的是 18/22；膝 0.01°、肘 0°、夹爪 0° —— 看起来像"动作没下发"。

**排查**（`_sync/wbprobe/` 里的临时探针 project，未改仓库）：
- 软件侧没问题：跑一遍五张任务卡，**22 个关节全部下发过**（膝 14.4°、肘 -40°、夹爪 20°）。
- 世界侧有问题：探针读位置传感器，**启动 4 个物理步（128 ms）内**这些关节就被弹到
  `trunk_pitch -1309°`、`knee -1976°`、`shoulder_pitch -2937°`、`elbow +4138°`、`gripper +17636°`，
  之后卡死、传感器读数恒定、**不再跟随任何指令**。
- 对照实验（同世界，只改一处）：

| 变量 | 结果 |
|---|---|
| A. `Robot.selfCollision FALSE` | ❌ 依旧爆炸（不是自碰撞的锅） |
| B. 每个关节加 `dampingConstant 0.5` | ✅ **全部正常**：膝→20.0°、肘→-40.0°、夹爪→20.0°，精确到位 |
| C. A+B | ✅ 同 B |

**根因**：世界文件里 22 个 `HingeJointParameters` **一个阻尼都没写**。零重力 + 22 个轻质连杆
对这个约束求解器是不稳定的，启动瞬间就把若干关节打飞并卡死。

**修复**（生成器统一写死，不再依赖"默认值"）：
- `webots/tools/generate_atri_world.py`：新增 `JOINT_DAMPING = 0.5` 并逐关节写 `dampingConstant`
- `webots/worlds/atri_22dof.wbt`：重生成（+22 行）
- `webots/tests/webots_api_stub.py`：解析器补 `dampingConstant`
- `webots/tests/test_atri_controller.py`：新增断言「每个关节阻尼必须 > 0」

**复验（真机批量，同一套任务卡）**：

| | 修复前 | 修复后 |
|---|---|---|
| 有行程关节 | **11/22** | **18/22**（与 README 记录一致） |
| 无行程关节 | 11 个（含膝/肘/夹爪） | 4 个 = `hip_yaw`/`hip_roll` ×2（**任务卡本来就不用**，README 已说明） |
| 膝/肘/夹爪行程 | 0.01° / 0° / 0° | 26.79° / 25.0° / 35.61° |
| 离线测试 | 40 项 OK | **41 项 OK** |

> 结论：**修之前，Webots 这一侧的"动态"结论是不可信的**（一半关节的数值是坏的）。
> 现在它才够格作为动态验证的第二条腿。
