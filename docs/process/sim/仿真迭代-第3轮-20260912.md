## 1. 证伪：重生成 placements.json 是退步

### 1.1 先看清这个生成器到底做什么

`design/gen_placements.py` **不做摆位决策**，它只把三处誊抄进 `placements.json`：
`robot_model.json`（舵机/结构件/包络）、`components.json`（电子件的位置与尺寸）、
`components.json` 的线束/紧固件质量。所以"重生成"能不能修好干涉，完全取决于
**源文件里写的是什么**。

对照两版电子件清单（旧 = 仓库里的派生文件，新 = 重生成）：

| 电子件 | link | 旧 position_mm | 新 position_mm | 变化 |
|---|---|---|---|---|
| Raspberry Pi 4B | `torso_upper` | 0,0,−12 | 0,0,−12 | 无（**RPi 早就不在头里**） |
| 相机模组 | `head` | 38,0,**13.5** | 38,0,**13.5** | 无 |
| 拾音模块 | `head` | 35,0,−12 | 10,0,−10 | 有，但 **`assembly.py:325 ELEC_HEAD` 会覆盖位置**，等于没变 |
| IMU | `pelvis` | **−36,0,−3** | **0,0,9.5** | **有 → 出事** |

### 1.2 实测结果（真跑一遍装配审计）

| | 仓库现状 | 重生成后 |
|---|---|---|
| 干涉对 | 189 | 190 |
| **『摆放错误』** | **0** | **1** |
| 新增 ❌ | — | `servo__trunk_roll ↔ elec__ICM-42688-P 模块`：**900 mm³，重合率 100%** |
| 总相交体积 | 159 743 mm³ | 160 957 mm³ |

**为什么**：`skeleton.py:550-551` 的设计口径白纸黑字写着「**IMU 坐后桥，避开 trunk_roll**」
（后桥 x=−36），派生文件里的 `[-36,0,−3]` 就是照这个坐的；
而 `components.json` 里写的 `[0,0,9.5]`（"骨盆重心附近"）正好落在 trunk_roll 舵机体里。
**源文件与设计意图不一致**，而派生文件是被手工改对过的 —— 所以重生成 = 把手调结果冲掉。

> 暂停文档队列第 ① 项「重生成 `placements.json` + 全量复验」的前提不成立，
> 建议改成「先修 `components.json` 的 IMU/拾音条目，再重生成」。本轮已按这个思路修了 IMU。

## 2. 找到的落位错误：相机比头壳口袋低 14.5 mm

第 2 轮零件级复核里，`servo__head_pitch ↔ elec__UVC 相机模组` 是：零位 3 556 mm³ ⚠️、
展示姿态 5 241 mm³ ❌ ——`components.json` 的备注还说"第 5 轮沿 +X 再送出 20 mm，避开 head_pitch 舵机"，
说明**前人已经挪过一次，仍没解决**。

于是去看头壳自己是怎么留位的（`skeleton.py:701 head_shell`）：

```python
part = part.cut(box(20.0, 40.0, 17.0, at=(hl / 2 - 12.0, 0, z0 + 6.0), centered_z=True))  # 相机口袋
part = part.cut(cyl(18.5, 14.0, at=(hl / 2 - 6.0, 0, z0 + 6.0), axis="X"))                # Φ37 镜头孔
```

`z0 = 22`、`hl = 76`、`hw = 68`，代入得：口袋中心 **(x≈26, z≈28)**，40 宽 × 17 高 —— 与相机占位体
38×15 的窄面**刚好对得上**（各留 1 mm）。也就是说**头壳是照 z≈28 建的**，而
`components.json` 把相机写在 **z=13.5**。

### 2.1 位置搜索（不改仓库文件，脚本 `_sync/camera_sweep.py`）

相机位置由 `placements.json` 直接决定（头部件里唯一不受 `ELEC_HEAD` 覆盖的一件），所以可以搜。
先用 z∈[8,19] 搜：最好只到 3 187/6 466 mm³；**换到 z∈[22,34] 后**：

| 相机位置 | 零位干涉 | 展示姿态干涉 |
|---|---|---|
| 现状 (38, 0, **13.5**) | 5 314 mm³（其中 head_pitch **3 556**） | 6 756 mm³（其中 head_pitch **5 241**） |
| (26, 0, **28**) | **654 mm³**（head_pitch **0**） | **654 mm³**（head_pitch **0**） |
| (38, 0, **28**) | **654 mm³**（head_pitch **0**） | **654 mm³**（head_pitch **0**） |

- **z=28 让 head_pitch 那一项彻底归零**，而且与 x 无关（x 从 22 到 38 结果完全一样）。
- 剩下 654 mm³ 全部来自 `head__head_shell`：相机 38 宽刚好比 Φ37 镜头孔半径大 0.5 mm，
  四个角各蹭一点 —— 是"占位体比孔大 1 mm"的问题，不是位置问题。

## 4. 还没修完的漂移（交给设计侧）

修完相机与 IMU 后，再跑一次 `gen_placements.py`，**只剩两处**与仓库派生文件不同：

| 项 | 派生文件（仓库，CAD 用） | 源文件（components.json） | 影响 |
|---|---|---|---|
| 拾音模块 `size_mm` | `[8, 25, 8]`（备注写明"CAD 占位：厚度沿 X"） | `[25, 15, 8]`（实物尺寸） | 重生成会把占位体从 8 厚变成 25 厚 → 顶出前脸罩，**会引入新干涉** |
| 结构件质量 | v3 旧值（如 pelvis 159.7 g） | 当前值（124.0 g） | 只影响账面，不影响几何 |

建议：把**实物尺寸与 CAD 占位尺寸分成两个字段**（现在两处都叫 `size_mm`，语义不同才导致漂移），
而不是继续让派生文件"替源文件记事"。
