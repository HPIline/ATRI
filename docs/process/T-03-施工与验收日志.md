## 二、这次做了什么

### 1. 新增可调参数层 `atri/tuning.py`（T-03/T-04/T-05 共用）

机器人结构与零件**未定案**、**没有实物**，现在代码里每个控制常数都是设计值。
为了"实物到手后标定"只是改一行 JSON，做了这一层：

- 文件：`software/atri/config/<skill>.json`，缺键=代码默认值；
- 优先级：**任务卡 params > config/<skill>.json > 代码默认值**；
- 写错的键/非法值/坏 JSON **只告警不抛异常**（联调现场不该因为一个逗号停摆）；
- 每次调用重新读文件（改完立刻生效，不用重启）；
- `ATRI_TUNING_DIR` 可指向别的目录（现场联调不动仓库）。

随代码发布的 `config/carry.json` **只有说明、没有任何覆盖值**——测试
（`tests/test_carry_tuning.py::test_real_carry_config_is_notes_only`）会盯住这条：
随代码走的配置文件不许偷偷改设计值。

### 2. `skills/carry.py`：两步对准 + 参数外置 + 诚实回报

- 全部控制常数走 tuning；返回值新增 `tuning_source` / `tuning_overridden`；
- **新增"放置区对准"**：走到位后若"放置区"通道真的接入了（`detect_place`），先对准再释放；
- **通道接入但没看见地标 → 失败且不释放**（`status=failed`，`release` 一次都不下发）；
- 通道完全没接入（纯 Mock / 没地标方案）→ 按任务卡参数释放，但结果里如实写
  `place.status="channel-unavailable"`；
- 失败结果也带过程量（`iterations` / `align_x_cm` / `grasp_tolerance_cm`），供调参复盘。

### 3. `perception/opencv.py::detect_place` + `perception/mock.py::ServoMockPerception.detect_place`

真相机侧：与目标物异色的地标色块（默认蓝），复用同一套 HSV 掩膜与像素当量换算，
距离口径同样标 `calibrated` / `uncalibrated`。Mock 侧只给 `ServoMockPerception`
（纯 `MockPerception` **故意不给**该通道，于是 T-03 在纯 Mock 下会说"没接入"）。

### 4. 评测工具 `tools/carry_eval.py`（本任务的核心产出）

三段，每段都写明"真代码是什么、数据是怎么来的"：

| 段 | 内容 | 数据来源 |
|---|---|---|
| A | 色块检测成功率与横向误差：偏移/尺度/亮度/噪声/模糊/干扰/遮挡/距离口径 | **程序合成图**（cv2 画的）+ 真 `OpenCVPerception` |
| B | 搬运闭环端到端：真 `CarrySkill` + 真 `Cerebellum` + 真检测器，图像在环 | 合成图 + 一维几何（`x_rel = x_true − D·tanθ`，针孔相机 f=277.1 px） |
| C | 参数边界表：每个 gain / 迭代上限 / 步长增益下的"最大可纠正偏差" | 纯数学（与 `lateral_servo` 同式复算，有对照测试） |

## 四、三个"原来不对"的发现（都已改/已写进报告）

### 1. 默认参数在真实相机几何下**不够用**（不是逻辑错，是数值错）

`ServoMockPerception` 里 gain 固定 **1.5 cm/°**，等价于"物距 86 cm"；而桌面任务的实际物距是
8–20 cm，针孔几何给出的 gain 只有 **0.14–0.35 cm/°**——**差 7 倍**。
Mock 里闭环"很容易收敛"，是因为**模型比现实乐观**。

后果：按代码默认值（`max_iters=5, step_gain=0.5`），12 cm 物距下只能纠正 3.4 cm 偏差，
超过就不收敛。报告 §4.1 给出推荐值 `max_iters=15, step_gain=1.0`（数据来自边界表），
B 段实测从 11/20 → **20/20**。

> 这条**没有改 Mock 的默认 gain**：改了会把这个乐观模型藏起来。报告里写清了，
> 实机第一步就是量真实的 gain（发 10° 看真转了多少）再回填。

### 2. 抓取判据把"没对准"当成了"对准"

原实现：闭环后只要 `|x| ≤ give_up_cm(4.0)` 就照抓，而"对准"的死区是 2.0 ——
**夹着 3.4 cm 偏差去夹，返回的还是 `status=ok`**。
本次拆成语义清楚的两个量：

- `deadband_cm`：闭环**收敛目标**（对准）；
- `grasp_tolerance_cm`：**夹爪实际能容忍**的偏差（实机标定值），默认 = 死区（没对准就不夹）。

没进死区但在容差内仍然允许夹，但会打印 ⚠ 并回报 `aligned=False` + `grasp_within_tolerance`
——**不允许**把"凑合夹"说成"对准了"。

### 3. 遮挡会让检出中心**系统性偏移**（不是随机噪声）

第一版遮挡场景是"红块中间挖个洞"，结果中心一点没变——因为连通区没断，
boundingRect 也没变，那是个**假场景**。改成全高挡条后才量出真实后果：
挡住左侧 20%/40%/60% → 检出中心右偏 **+0.40 / +0.65 / +0.95 cm**。
这类偏差把目标"看偏了"，闭环会稳定收敛到**错误的位置**——面积加权估心解决不了，
要么用外接矩形/角点，要么把地标做大到不容易被挡。

  `lateral_servo` 的最终偏差/迭代次数必须一致——否则报告里那张表就是另一套东西。

## 六、还缺什么（不装懂）

| 缺口 | 为什么 | 怎么才能补 |
|---|---|---|
| 实机抓取成功率 | 没有样机、没有夹爪 | 样机 + 标定物，跑 N 次（未测项 B6 仍然成立） |
| 真实相机上的色块检测 | 没有相机；A 段是合成图 | 打印色块卡 + 真相机，按同一批场景重跑 `carry_eval.py` |
| 像素当量 / 焦距 | 没有相机内参 | 棋盘格标定 → 回填 `config/carry.json` |
| 髋偏航指令 → 身体实际转角 | 无位移/里程计 | 实机量 10° 真转多少；写 `config/odometry.json` |
| 步长 → 实际位移 | 同上 | 直走 N 步量距离 |
| 放置区地标方案 | 赛题未规定用不用地标 | 定了之后标定 `detect_place` 的色域与尺寸 |
| Webots 控制器仍注入静态 MockPerception | 仿真侧未接摄像头 | Webots 机器人加 Camera + 接 `OpenCVPerception` |

**一句话**：T-03 现在是"**代码路径跑得通、参数能标定、边界有数据、结论不越界**"的状态；
它的"成功率"仍然只有合成图口径，**不是实机指标**。
