## 二、给队友的适配器补的三处（都是加法，默认行为不变）

### 1. 关掉"语法约束"才看得到"听错"

`_make_recognizer()` 原来无条件把白名单当**语法**喂给解码器：

```python
grammar = json.dumps(list(self.keywords), ensure_ascii=False)
return vosk.KaldiRecognizer(model, self.sample_rate, grammar)
```

这会让引擎**只会吐白名单里的词**——实测把 `跳个舞`、`来段舞蹈`、`请你跳个舞好吗`
**全都转写成 `跳舞`**。于是"命中率 100%"是约束的产物，不是识别精度。

改法：加构造参数 `constrained: bool = True`（`build_recognizer` 同步透传）。
默认仍是 True（现场抗噪更好），但**评测时两种模式都跑**，报告里并列给出。

### 2. 白名单判定要归一化空白

`match_keyword()` 原来是直接在文本里找子串。而**自由解码**的原文是 `跳 个 舞`、`来 段 舞蹈`
（引擎会在汉字间吐空格）——不归一化就永远匹配不上多字关键词：**念对了却判成没听见**。
实测这条修完，自由解码的白名单命中从 **6/21 → 17/21**。

改法：新增 `_squeeze()`（去掉所有空白，含全角空格），文本与关键词都先归一化再比，
"最长命中优先"的规则不变。

### 3. 原文要留下来

`recognize()` 原来只返回命中的关键词，把引擎原文丢了——报告里就只能写"命中了"，
没法让人核对。新增 `self.last_text`（引擎**原样**转写），`tests/test_voice_offline.py` 不受影响。

## 三、真解码证据（本次的核心产出）

工具：`software/atri/tools/asr_decode_eval.py`（只用标准库，用 `--asr-python` 指向装了 vosk 的
独立 venv；仓库基准解释器保持零依赖）。语料：macOS `say -v Tingting` 合成 → `afconvert` 16 kHz 单声道
→ 程序按信噪比叠高斯白噪声（seed 固定）→ 真 vosk 解码 → 仓库自己的 `match_keyword` 判定。

复跑命令：

```bash
.python/bin/python3 software/atri/tools/asr_decode_eval.py \
    --asr-python /tmp/atri-asr/venv/bin/python \
    --vosk-model /tmp/atri-asr/models/vosk-model-small-cn-0.22 \
    --report design/handoff/T-05-语音真解码验证报告.md \
    --json design/results/t05_asr_decode.json
```

结果（35 条 = 5 句 × 7 档噪声；引擎 vosk 0.3.44 + `vosk-model-small-cn-0.22`）：

| 解码模式 | 白名单命中 | 其中**真的说出被念的词** | 白名单外负样本误接受 |
|---|---|---|---|
| 语法约束（技能默认） | 21/21 | **7/21** | 0/7 |
| 自由解码 | **17/21** | 17/21 | 0/7 |

自由解码按噪声档（三个 S-05 变体）：

| 信噪比 | 干净 | 70 dB | 50 dB | 30 dB | 20 dB | 10 dB | 0 dB |
|---|---|---|---|---|---|---|---|
| 命中 | 3/3 | 3/3 | 3/3 | 3/3 | 3/3 | 2/3 | 0/3 |

**两条读法（必须一起说）**：

1. **S-05 的 30/50/70 dB 噪声轴区分不出方案好坏**——白噪声在这几档几乎不影响识别；
   有信息量的是 20 dB 以下。要当真指标，得用现场录音而不是白噪声。
2. **"约束模式 21/21"不能读成"识别很准"**：约束模式下引擎只会吐白名单词，
   三个变体被压成同一个词（实测都变 `跳舞`），它证明的只是"白名单外的语音不会被误接受"。
   要看"听清没听清"，看自由解码那一列。

缺件演练（同一次运行）：解释器路径不存在 → 干净跳过并给出重建提示；模型路径不存在 →
`available()` 报 False 并写明缺什么。两条都 exit=0，**不会用 Mock 顶替真识别**。

## 五、还缺什么（B8 仍未测）

| 缺口 | 说明 |
|---|---|
| **现场识别率** | 素材是 `say` 合成音 + 程序白噪声；真实人声/音乐/混响未测 |
| 实机麦克风链路 | 没有麦克风，音频是文件喂进去的；采样率需对齐 16 kHz 单声道 |
| 说话人 / 口音 / 距离 | 只有一个 TTS 音色 |
| 端点检测（VAD） | 现在整段 wav 一次性喂进去，没有"什么时候开始听"的策略 |
| 节拍同步 | 舞蹈动作与伴奏各走各的，没有音频时钟对齐 |
| 引擎可移植性 | 本机（macOS arm64）实测；树莓派 aarch64 未验 |

**一句话**：T-05 现在是"队友的适配器与接线 + 我的真解码证据与两处口径修正"。
"离线关键词识别**在合成语音上**能做到什么程度"这件事**已经有数字了**；
"现场能做到什么程度"**仍然没有数字**。
