## 二、补的两条硬要求（他的版本当时没有）

### 1. 缺「球的横向偏移」时不许当成"正前方"（fail-safe）

原实现：`raw_x = obs.get("x_cm", ctx.params.get("x_cm", 0.0))` —— 观测里没有 `x_cm` 时**默认 0.0**
（"球就在正前方"），然后照常摆腿。这与 T-03 已修的口径不一致
（`carry` 缺 `x_cm` 判失败、`validation.py` 写明「转换失败返回 None，**绝不猜**」）。

改后取值顺序：**观测 → 任务卡 params → 判失败**，`0.0` 这个隐含默认被删除：

```python
obs_x = obs.get("x_cm") if "x_cm" in obs else None
ball_x = as_finite_float(obs_x)
if ball_x is None:
    ball_x = as_finite_float(ctx.params.get("x_cm"))
if ball_x is None:
    return fail("球的横向偏移缺失或非法: 观测=… 任务卡=…（不把「没量到」当成正前方）")
```

实测（自写脚本，不依赖他的测试）：

| 观测 | 改前 | 改后 |
|---|---|---|
| `{"found": True, "x_cm": 2.0, "distance_cm": 12}` | ok（踢 1 次） | ok（踢 1 次） |
| `{"found": True, "distance_cm": 12}`（无 x_cm） | **ok（盲踢）** | **failed，0 动作** |
| `x_cm=NaN` / `x_cm="很远"` | ok / 异常边角 | **failed，0 动作** |
| 观测无 x_cm，但任务卡 `x_cm=2.0` | ok | ok（兜底仍生效） |

### 2. 参数出处与告警：失败路径也要看得见

- `load_tuning("kick", KICK_DEFAULTS)` → 补 `warn=print`（与 `carry`/`dance` 同口径）；
- 新增 `_fail()` 统一失败出口，失败结果同样带 `tuning_source` / `tuning_overridden` / `tuning_warnings`；
- `tuning_source` 改为**真正生效**的语义（见下）——只由"文件里有没有键"决定是不够的。

### 3. 顺手统一的一条口径：`tuning_source` 要认"被任务卡盖住"的键

三个技能原来的写法是 `tuning_source = 文件名 if t.overridden else "code-defaults"`：
只要**文件里有键**就报文件名，哪怕那一次的取值其实来自任务卡。这正是 T-03 独立复核提过的
"把现场临时指定的值说成标定回填的值"。现在统一走 `atri/tuning.py` 的新助手：

```python
effective_overrides(t, params)   # 文件里**真正生效**的键（被任务卡盖住的不算）
tuning_source_label(t, params)   # "code-defaults" 或文件名
```

我的 `tests/test_kick_tuning.py::test_task_card_beats_file` 就断言这一条：
文件写 `deadband_cm=6`、任务卡写 `deadband_cm=1` 时，必须报 `code-defaults`。

## 四、还缺什么（与他报告 §5 一致，未新增）

| 缺口 | 说明 |
|---|---|
| 实机踢球成功率（B7） | 没有样机、没有球、没有场地 |
| 真实相机上的绿球检测 | A 段是**程序合成图** |
| `gain_cm_per_deg` 的真实值 | 现在是假设值（1.5 cm/°，等价物距 86 cm，比桌面真实值乐观约 7 倍） |
| "球位移 ≥100 mm"（S-04 判据） | 踢球是预标定轨迹，不模拟球被踢出去之后的运动 |
| 光照轴（100/400/800 lux） | 一维几何里没有光照项，扫了只会得到三段一样的数字 |
| Webots 端到端 | 控制器仍注入静态 `MockPerception` |

**一句话**：T-04 现在是"队友的实现 + 主线的两条硬要求 + 用有 cv2 的解释器补齐的 A 段证据"，
数字全部可复跑；**实机踢球成功率仍未测**。
