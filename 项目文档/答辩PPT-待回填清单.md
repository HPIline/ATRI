## 一、为什么冻结

现在 PPT 里的工程数据全部来自 `design/robot_model.json`（`model_status: design-provisional`），
是**设计模型值**，不是实测值。在建模、采购、仿真落地之前继续调 PPT，只是在错误的数字上反复打磨。

而且设计模型已经变过四次（尺寸 37.3 → 47.5 → 37.3 → **41.8 cm〔CAD 实装〕**、
质量 1.65 → 2263 → 2146 → **3437 g**、预算口径随 BOM 重算），
**PPT 跟着变一次就要改十页**。等基准稳定了再改，一次到位。

## 三、当前版本里仍是"设计值"的数字（改的时候别漏）

- 尺寸 **41.8 × 22.3 × 12.9 cm**（v3，CAD 实装）— 装配体实测，非实物称重；基元/运动学口径为 37.3 × 19.0 × 12.3 cm
- 整机质量 **3437 g**（v3）— 结构 1790〔CAD 实算 74 件〕+ 舵机 1210 + 电子件与电池 316 + 线束紧固件 120；**未执行减重**
- 单侧臂长 **9.57 cm**（v2）— 肩关节→夹爪末端直线距离，官方未定义测量基准（`gen_urdf.shoulder_to_gripper_mm()`）
- 腿部关节力矩 **1.629 N·m（占「堵转×50%」判据 111% ❌ 超标）** — 动态系数 2.0 与 CoP 偏移 25 mm 均为工程估算；须执行减重路径 A+B
- BOM **¥2788–3456** — 量级估算，随行就市
- 步态参数 **2.0 / 1.2 / 0.8 s** — 生成公式的线性系数，不是实测步长
- 收敛序列 **seed 20260910** — 来自 `design/run_sim.py`，非实机

## 四、截至冻结时，已知且**未修**的三处（属于 design/ 工作区，需一并处理）

1. `design/robot_model.json` 的 `design_constraints.competition_max_depth_mm`
   —— 官方六类约束里**没有"深度"这一条**（官方是 身高 / 体宽 / 臂长(单侧)）
2. 同文件的 `single_arm_max_length_mm` **声明了但 `gen_urdf.check()` 从未校验**
3. `gen_urdf.py::reach_mm` 的标签写"肩→夹爪"但实际从骨盆累加（输出 78.3mm，
   真正的肩→夹爪约 122.5mm）；PPT 用的是后者的口径

> 这三处会影响工程图作为报名材料的可用性，建议在出正式图纸前修掉。

## 五、改的时候怎么改

**不要手工改 PPTX。** 全部内容都在 `ppt/build_deck.py` 里，改文案改数字都改这个文件，
然后：

```bash
cd '/Users/hpi/Documents/搞机器人'
bash ppt/build.sh ppt/build_deck.py "ATRI-答辩PPT-定稿"
```

一条命令跑完 生成 → PowerPoint 导出 PDF → 栅格化逐页校验。
改完先跑 `python3 ppt/check_layout.py` 看有没有压盖/越界（应为 0 页）。

设计规范、配色、字体、两个已踩过的坑都记在 `ppt/README.md`。
