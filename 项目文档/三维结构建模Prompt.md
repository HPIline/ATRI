## 二、第二步：舵机选型（"最通用最廉价"）

### 2.1 推荐方案：TTL 半双工串行总线舵机

| 项目 | 推荐 | 理由 |
|---|---|---|
| **协议** | **TTL 半双工串行总线**（单线级联） | 生态最大、文档最多、一根线串 22 个 |
| **首选型号** | **飞特 Feetech STS3215**（或 STS3032） | 20kg·cm 级，约 90—120 元，磁编码器，支持位置/温度/负载回读 |
| **平替** | 创客工场 LX-15D / 幻尔 HTS-35H | 价格相近，库支持好 |
| **控制板** | 飞特 FE-URT-1 / 幻尔总线舵机驱动板 | USB-TTL 转接，Python/Arduino 库齐全 |
| **备选（更便宜）** | 辉盛 MG996R + PCA9685（PWM 方案） | 单颗仅 20 元，但**无位置回读**、走线多、不适合 22 DOF |

**推荐 TTL 总线而非 PWM 的理由**（写进材料的技术论证）：
1. **单线级联**：22 个舵机只需 1 根信号线，大幅简化线束（PWM 需 22 路）
2. **绝对位置回读**：可做闭环校验，PWM 做不到
3. **状态回传**：温度/电流/负载，可实现过载保护
4. **ID 寻址**：软件上就是一个 `set_angle(id, deg)`，与现有 `ServoBus` 抽象完美契合

> ⚠️ **重要**：现有代码 `ServoBus.set_angle(joint_id, deg)` 的接口设计**正好匹配总线舵机语义**，不需要改代码。这是选总线协议的额外好处，可写进材料。

### 2.2 关键尺寸（建模必须用到）

| 组件 | 参考尺寸 (mm) | 备注 |
|---|---|---|
| STS3215 舵机本体 | 40 × 20 × 40.5 | 含输出轴 |
| 舵机含舵盘高度 | 约 45 | 预留旋转间隙 |
| 舵机安装孔 | M2.5，孔距 30mm×10mm | 对称双耳 |
| 3S 锂电池（18650×3） | 70 × 55 × 20 | |
| 树莓派 4B | 85 × 56 | 含接口留 90×60 |
| STM32 最小系统板 | 55 × 25 | |
| MPU6050 模块 | 21 × 16 | |
| USB 摄像头（广角） | 30 × 30 × 25 | |

> ⚠️ 建模前**务必实测手上舵机的真实尺寸**，上面是通用参考值。**如果还没买舵机，就按上表建模，并在图纸标注"按通用规格建模，实物到货后复核"。**

### 2.3 供电与线束

- 电池：3S 11.1V 锂电（满足 ≥7.4V 要求）
- 舵机供电：**独立 BEC 降压**（避免舵机堵转拉垮主板）
- 建议每个舵机并联 470μF 电容（抑制瞬时压降）

## 三、第三步：建模任务（SolidWorks 或 Fusion 360）

### 3.1 建模顺序（自下而上，先骨架后外壳）

```
① 骨架层（Skeleton / 布局草图）
   - 画出 22 个关节的安装点坐标
   - 标注连杆长度与关节轴线方向
   - 这是整个模型的基础，先定死

② 关节模块（重复 22 次，但只需设计 4 种）
   - 髋关节模块（3 DOF：yaw/roll/pitch 串联）
   - 膝关节模块（1 DOF：pitch）
   - 踝关节模块（1 DOF：pitch）
   - 肩关节模块（2 DOF：pitch/roll）
   - 肘关节模块（1 DOF：pitch）
   - 夹爪模块（1 DOF：开合）
   - 头部模块（2 DOF：yaw/pitch）
   - 躯干模块（2 DOF：pitch/roll）

③ 连杆件（大腿/小腿/上臂/前臂/躯干壳/头壳）
   - 按 1.1 节长度建模
   - 预留舵机安装腔与走线孔

④ 装配体
   - 按骨架层坐标装配
   - 做运动仿真验证：每个关节能否到达限位角度
   - 检查干涉（尤其腿部交叉步态时）
```

## 四、第四步：导出格式（三种都要）

| 格式 | 用途 | 导出要求 |
|---|---|---|
| **STEP (.step/.stp)** | 给评审看、通用 CAD 交换 | 保留装配层级与颜色 |
| **STL (.stl)** | 3D 打印 | 每件单独导出，精度 0.05mm |
| **URDF (.urdf)** | 导入 Webots / PyBullet 仿真 | 必须带正确关节类型与限位 |

### 4.1 URDF 特别要求

URDF 是**直接给仿真用的**，必须和现有代码对齐：

```xml
<!-- 示例：左膝关节，注意 limit 必须与 config.py 一致 -->
<joint name="left_knee_pitch" type="revolute">
  <parent link="left_thigh"/>
  <child link="left_shank"/>
  <axis xyz="0 1 0"/>
  <limit lower="0" upper="1.5708" effort="20" velocity="6.0"/>
</joint>
```

**对齐要求**：
- 关节名必须与 `config.py` 中的 22 个名称**完全一致**
- `limit` 必须与 `config.py` 的 `limit_deg` 一致（注意 URDF 用弧度）
- 关节顺序建议与 id 0—21 一致

> ⚠️ **`webots/controllers/atri_controller/joint_mapping.json` 也要同步更新**——目前它是"同名映射"，对于自建模型这是对的；但如果用 Nao/DARwin-OP 做临时验证，要换成对应的映射文件。

## 七、执行约束

1. **所有尺寸必须自洽**：总高 = 头 + 躯干 + 腿，误差 ≤ 2mm
2. **关节限位不得小于 `config.py`**：这是硬约束，建模后逐项核对
3. **关节命名必须与代码一致**：22 个名称直接从 `config.py` 抄，不要自创
4. **未定细节用第五节默认值**，不要留空，也不要随便发明
5. **建模完成后必须做干涉检查**（极限姿态下）
6. **导出 URDF 后在 Webots/PyBullet 里加载一次**，确认关节能正常驱动
7. 不要把 CAD 大文件（>50MB）直接提交到 git，放网盘并在仓库里放说明

## 九、一句话提醒

**结构图的核心作用不是"好看"，而是证明"这 22 个自由度是真的想清楚了怎么装"。**
评委看的是：躯干那 2 个自由度在哪、每个关节的行程够不够、整体尺寸合不合规。
**把这三件事在图上说清楚，就达到目的了。**
