# A.T.R.I. 三天作战计划（9/10—9/13）

> 适用前提：**3 天、无硬件采购与组装、无经费、无深度导师介入、大二新生、产出几乎全部依赖 AI 生成。**
> 目标：13 号交出一份**在网评里站得住**的材料。
>
> 本文不是"理想计划"，是**在真实约束下什么能做、什么必须放弃、以及 AI 到底能替我们产出什么**。

---

## 零、先把话说透：这次评审我们靠什么赢

网络评审的评委，在每份材料上停留时间通常只有几分钟。他们**不会逐行看代码**，但会形成三个直觉判断：

| 评委会形成的判断 | 靠什么形成 | 我们能不能控制 |
|---|---|---|
| "这项目合规吗？" | 尺寸/电压/关节数/传感器对照表 | ✅ 完全可控，已达标 |
| "他们真做过东西吗？" | **图表、数据、可复现的产物** | ✅ 可控，见下方"AI 能产出的硬证据" |
| "有技术含量吗？" | 一个具体的技术主张 + 证据 | ✅ 可控，但要选对 |

**反过来，会扣分的是：**
- ❌ 漂亮但空泛的形容词堆砌（"赋能""闭环""生态"）
- ❌ 明显 AI 生成的大段排比与对仗
- ❌ 宣称了却没有证据的能力（写"ZMP 毫秒级解算"但代码里没有）
- ❌ 一看就是编造的精确数据（"成功率 94.7%"）

**核心策略：宁可少宣称，不能不兑现。所有写进材料的技能，代码里必须真的能跑出来。**

## 一、残酷的取舍：3 天能做什么，不能做什么

### 1.1 必须放弃的（做了反而扣分）

| 事项 | 为什么不做的更好 |
|---|---|
| **实物样机 / 硬件采购** | 3 天不可能。硬写"已采购"或含糊其辞，评委一问就穿 |
| **Webots 完整仿真** | 装环境 + 建模型 + 调参 + 出数据，实际需要 1—2 周。3 天只够装环境 |
| **真机行走视频** | 无硬件即无视频，不必强求 |
| **编造实测数据** | **红线。** 一旦被发现，整个项目可信度归零 |
| **深度学习/VLA 算法** | 训练需要算力和数据，3 天不可能，且与"离线低算力"定位冲突 |
| **复杂的 ZMP 控制器调参** | 理论可写，但**调不出可信数据**，容易变成"AI 编的曲线" |

### 1.2 必须做的（投入产出比最高）

| 事项 | 为什么 3 天能做成 | 产出形态 |
|---|---|---|
| **软件栈跑通 + 可复现** | ✅ 已经能跑（5/5 通过） | 运行日志、测试报告 |
| **视觉伺服闭环改造** | ✅ 纯软件，当天可完成 | 收敛数据 + SVG 曲线 |
| **SolidWorks 工程图** | ✅ 你们已有这个渠道 | 三视图 + 关节编号图 |
| **新增任务演示** | ✅ 代码量小，是创新点硬证据 | 20 行 JSON + 对比数据 |
| **材料口径统一** | ✅ 纯文字工作 | 一致的设计/目标/计划口径 |
| **答辩 Q&A 准备** | ✅ 纯文字工作 | 能答上"机器人在哪" |

## 二、AI 到底能替你们产出什么（诚实清单）

你提到"几乎只能依靠 AI 生成产物"。这没问题，**关键是用对地方**。AI 在这类任务上的能力差异极大：

### 2.1 AI 能做得很好（应该全力用）

| 任务 | AI 能力 | 注意事项 |
|---|---|---|
| **写可运行代码** | ⭐⭐⭐⭐⭐ | 这是 AI 最强项。必须有测试和运行日志佐证 |
| **重构现有架构** | ⭐⭐⭐⭐⭐ | 改成闭环、加元数据、加日志，AI 很擅长 |
| **生成 SVG/图表** | ⭐⭐⭐⭐ | 从真实数据生成，不是凭空画 |
| **写技术文档结构** | ⭐⭐⭐⭐ | 但需人工加入具体细节，否则有 AI 味 |
| **对照官方要求逐条核查** | ⭐⭐⭐⭐⭐ | 极适合 AI，不易出错 |
| **准备答辩 Q&A** | ⭐⭐⭐⭐ | 很好，但答案要基于真实情况 |
| **SolidWorks 建模脚本/尺寸计算** | ⭐⭐⭐ | 能算尺寸链，但建模仍需人工操作 |

### 2.2 AI 做得不好（必须警惕）

| 任务 | 风险 |
|---|---|
| **凭空编造实验数据** | ❌ **绝对禁止**。AI 会生成看起来合理的数字，但那是编的 |
| **生成"拟真"的仿真截图** | ❌ 一旦被问细节就崩 |
| **写过度华丽的项目愿景** | ⚠️ 典型 AI 味，评委一眼识别 |
| **假装已完成的研发叙事** | ❌ 与"规划中"的进展表自相矛盾 |

### 2.3 铁律

> **AI 生成的一切，必须能被你们自己跑一遍、讲清楚。**
> 凡是自己都讲不清来龙去脉的内容，删掉。宁缺毋滥。

具体做法：**每一份 AI 产出的材料，你们要能用一句话说出"这是怎么来的"**。例如：
- ✅ "这条曲线是我们跑 `python3 -m atri.analysis.servo_bench` 生成的，日志在 `logs/` 里"
- ❌ "这是我们仿真出来的" （说不出怎么仿的）

## 三、把创新点收敛成一个（不要四个）

3 天时间，**只能讲清楚一个创新点**。讲四个的结果是四个都讲不透。

### 3.1 推荐主张

> **我们提出并实现了一套"任务卡—技能"解耦的机器人任务描述规范：新增一项任务只需写一个 JSON 配置文件和一个技能模块，无需改动调度框架。**
> **并配套实现了基于视觉反馈的迭代伺服闭环，使动作参数由实时感知计算得出，而非固定脚本。**

### 3.2 为什么是这个

| 理由 | 说明 |
|---|---|
| **可当场验证** | 现场加一个 JSON 就多一项任务，演示 30 秒完成 |
| **有代码支撑** | 框架已经存在（`task_card.py` + `brain.py` 技能注册表），只需补证据 |
| **AI 擅长实现** | 这是纯软件架构工作，AI 能高质量完成 |
| **不需要硬件** | 完全绕开我们最大的短板 |
| **一句话说得清** | 评委能复述给别人听 |

### 3.3 怎么证明（这就是 3 天的核心工作）

**证据一：框架可扩展性**
- 写一个赛题外的新任务（如"巡逻-异常上报"）
- **只加**一个 JSON + 一个技能模块，**不改** `brain.py` / `fsm.py`
- 统计：新增任务用了多少行代码
- 对比传统写法（每任务独立程序）需要多少改动

**证据二：闭环 vs 开环的行为差异**
- 同一个"抓取"任务，改变目标初始位置
- 记录**实际下发的关节角序列确实不同**
- 对比成功率：开环固定脚本 vs 闭环伺服

**证据三（加分）：能力边界**
- 主动说明"在什么条件下我们的闭环会失效"
- 这比宣称"成功率 95%"可信得多

### 3.4 不做 ZMP 的说明

**建议不要在材料里主打 ZMP。** 理由：
- 代码里目前没有 ZMP 计算，写了就是"宣称未兑现"
- 3 天内调不出可信的 ZMP 数据，硬做容易变成编数据
- 正确做法：**把 PPT 里"基于 ZMP 与倒立摆模型毫秒级解算"删掉或改成"规划中"**

> 这一条很重要：**主动删掉一个兑现不了的宣称，比留着它更有说服力。** 评委发现一处夸大，会怀疑全部。

## 五、口径统一：把"没做"说清楚反而加分

3 天时间，我们**必须坦率承认处于方案设计阶段**。关键是**怎么说**。

### 5.1 三词口径

| 用词 | 用在哪 |
|---|---|
| **设计目标** | 未实现的硬件与算法（22 DOF 构型、STM32 小脑、ZMP 步态） |
| **当前状态** | 已完成的（软件栈、测试、仿真验证的闭环） |
| **后续计划** | 晋级后要做的事 |

### 5.2 改写示例

| ❌ 不要写 | ✅ 改成 |
|---|---|
| "小脑负责逆运动学与 ZMP 步态生成" | "小脑**设计为**负责步态生成与姿态控制；**当前**已在纯 Python 中验证脚本步态与动作调度" |
| "机器人识别二维码后完成透视矫正" | "二维码模块的**实现流程为**：识别 → 透视矫正 → 解析 JSON → 调用动作" |
| "面积成本仅 3600 元" | "**设计目标**新增采购约 1500—2800 元（边缘板与 STM32 由实验室提供）" |
| "基于 ZMP 与倒立摆模型毫秒级解算" | **直接删掉**，或改为"步态控制算法规划中" |

### 5.3 关于"机器人在哪"的标准答案

这是人形专项**一定会被问**的问题。建议口径：

> "项目目前处于方案设计与软件验证阶段。我们已经完成 22 自由度构型设计、SolidWorks 结构工程图，以及一套可运行的'大脑—小脑'软件栈——五项任务的调度、状态机、视觉与语音接口已通过 51 项单元测试，视觉伺服闭环可以在无硬件条件下完整验证。
> 实物样机我们**计划在晋级后启动**，优先借用校内现有平台验证算法，再自组样机。
> 我们清楚这在人形专项里是弱项，所以现阶段把重心放在**可复现的软件架构和工程仿真**上，确保方案不是停在纸面。"

**要点：主动承认弱项 + 说明为什么这样安排 + 展示已经做了什么。** 这比含糊其辞强得多。
