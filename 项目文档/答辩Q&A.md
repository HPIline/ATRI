# 答辩 Q&A 口径

> 与 `项目文档/修改意见.md` 的评审关注点一一对应。口径原则：不编造已实现结果，用“设计目标 + 当前状态 + 后续计划”回答。

## Q1：为什么晋级后才做样机？

**口径：**
- 报名/校赛阶段以“方案设计 + 软件栈 + 仿真验证”为主要交付，避免在没有明确晋级信号前投入整机成本。
- 我们不是“不做样机”，而是按 0 预算 → 借用样机 → 自组样机的顺序推进。校赛/晋级后优先借用实验室或二手双足机器人，先把算法闭环跑出真实视频。
- 软件栈已经可以在无硬件情况下跑通五张任务卡；Webots 仿真控制器已提供给 Windows 环境联调，因此方案不是停在纸面。

## Q2：你们的创新点到底是什么？

**口径：**
- 不做“重新发明双足机器人”的大词包装。
- 我们的技术主线是：**在有限算力和断网条件下，用统一任务描述（JSON 任务卡 + 二维码指令）驱动一台小型双足机器人完成五项不同赛题任务。**
- 具体体现为三点：
  1. 五项任务共用同一套硬件、同一套“大脑-小脑”框架，新增任务通过技能库和任务卡扩展；
  2. 二维码同时承担“标识”和“指令下发”，解码后直接驱动 FSM 动作，减少现场人为配置；
  3. 视觉伺服：**闭环控制律已在 `design/run_sim.py::servo_loop()` 中实现**，并在带噪感知与域随机化下
     跑出收敛序列（5 cm→5 轮→0.24；12 cm→5 轮→0.93；20 cm→7 轮→0.85）与失效边界
     （ideal 12/12、nominal 12/12、harsh 9/12、adversarial 4/12）。
     技能层 `kick.py` 目前仍是单次开环修正——**待办是移植，不是从零写**。
- 如果评委追问“有没有原创算法”：诚实回答当前是系统集成 + 工程优化，原创性主要在任务统一框架和低成本可复现路径。

## Q3：22 DOF 具体怎么分布？踝关节为什么是 1 个自由度？

**口径：**
- 22 = 双腿 10（每腿髋 3 + 膝 1 + 踝 1）+ 双臂 8（每臂肩 2 + 肘 1 + 夹爪 1）+ 躯干 2 + 头部 2。
- 踝关节只保留俯仰（pitch）1 个自由度，是为了控制重量、成本和结构复杂度；横滚方向依靠髋部 roll 和步态规划补偿。
- 末端不设独立腕关节也是同样的取舍：夹爪直接安装在肘部末端，面向桌面轻物抓取。
- 结构图/关节编号 CAD 将在样机阶段补充。

## Q4：为什么说“具身智能”？和普通遥控机器人有什么区别？

**口径：**
- 当前系统是“感知 + 规则决策 + 动作执行”，不是端到端大模型。
- 具身智能的体现集中在**带阈值的视觉修正**：摄像头检测目标 → 计算横向误差 → 阈值判定 → 调整朝向。
- 闭环形态已在设计数据包中实现并跑出收敛数据；技能层目前是一次开环修正，移植列入阶段二。
- 我们不会把“具身智能”一词抬高到不匹配的程度；文档中按“桌面级具身智能实验平台”的定位，强调低成本和可复现。

## Q5：预算 3600 元为什么可信？

**口径：**
- BOM 已按“新增采购”和“实验室已有设备”两档列示，22 个舵机 + 控制板 + 电源 + 3D 打印等逐项估算，合计约 1500–2800 元。
- 如果实验室提供边缘板和 STM32，则新增采购更低。
- 备用舵机、结构件损耗、线材等均单独列出，不出现“一份预算卡死全部”的情况。

## Q6：现在到底完成了什么？

**口径：**
- 已完成：22 关节设计模型（v2：373 mm / 2.146 kg）与 4 张工程图、169 项测试、五项任务无硬件闭环 5/5、闭环控制律与鲁棒性边界、Webots 22 DOF 运动学世界与 19 项离线桩测试、任务卡与动作库规范。
- 未完成：真实样机、实机行走/抓取/踢球数据、真实摄像头联调。这些按计划在仿真和借用样机阶段推进。

## Q7：如果现场断网，语音/人脸/二维码还能用吗？

**口径：**
- 能。线程上：二维码解析用 OpenCV（纯本地）、TTS 用本地引擎（macOS `say`）。
- **人脸检测**用本地 Haar（已实现），但**身份比对模块尚未实现**，`config/face_db.json` 目前从未被代码加载；
  真机接上摄像头后会播报任务卡里的默认名。身份比对是阶段二第一优先项。
- Mock 版本已把这条链路跑通；真实离线识别精度在样机阶段用固定光照条件逐步标定。
