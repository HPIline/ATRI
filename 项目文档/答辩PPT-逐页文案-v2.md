**三栏**

## P07 · 门槛二：算法碎片化
- **页眉**：01 立项基础
- **标题**：五项任务、五套工程——学生学到的是五个互不相通的孤岛
- **导语**：现状不是"没有算法"，而是算法之间没有共同的骨架。

**左（现状）** —— 五个独立方框，各自带"相机初始化 / 状态管理 / 主循环"，中间画虚线断口
**右（本方案）** —— 一个「JSON 任务卡 + FSM + 技能库」底座，上面五个技能模块插上去

**三条后果**
1. 换一项任务就要改主程序，实验之间无法对照
2. 无法评测"系统能力"，只能评测"某个脚本能不能跑"
3. 学生学到的是一次性脚本，不是可扩展的系统设计

- **一行结论**：任务 = 一份 JSON 文件；能力 = 一个技能模块；调度 = 一个状态机
- **状态**：○ 规划中（方案）；● 已完成（任务卡/FSM/技能库已在仓库中实现）
- **口径**：左栏现状为对现有开源工程与常见参赛做法的归纳，非针对特定对象

## P08 · 门槛三：云端依赖
- **页眉**：01 立项基础
- **标题**：比赛现场拔掉网线的那一刻，很多方案就失效了
- **导语**：全离线不是技术炫技，是赛题要求下的工程必选项。

**上下链路对比图**
- 上（云端链路）：相机 → 上传 → 云推理 → 下发 → 执行，标出 4 个失败点（网络抖动 / 限速 / 服务变更 / 数据外传）
- 下（本方案）：相机 → 板载推理 → FSM → 小脑 → 舵机——**整条链路在一个盒子里**

**诚实的代价**（必须写，否则是回避）
- 本地小模型的识别精度不如云端大模型
- 我们的应对：先用固定光照 + 固定颜色目标把稳定性做上去，再逐步扩展工况
- 教学场景对数据外传敏感，离线同时解决了这一层顾虑

- **状态**：○ 规划中
- **口径**：不宣称任何精度对比数据；"精度不如云端"为设计阶段的定性判断

## P17 · 总体技术架构图 ← 核心页
- **页眉**：03 技术架构与实现
- **标题**：五层架构，两条边界——一条是算力边界，一条是硬件边界
- **导语**：上层不关心关节怎么转，下层不关心任务是什么，两层之间只传一份 JSON 协议。

**五层架构图**
| 层 | 内容 | 承担者 |
|---|---|---|
| 任务层 | 人脸识别 / 二维码循迹 / 物品搬运 / 体育运动 / 娱乐交互 | 赛题清单 |
| 编排层 | JSON 任务卡 → 任务调度器 → 有限状态机 FSM → 技能库 | **大脑**（边缘计算板 · Linux） |
| 感知交互层 | 单目相机 → 视觉检测 ｜ 麦克风 → 离线语音 | 大脑 |
| 控制层 | 步态生成 / 动作库回放 / 视觉伺服 / 姿态闭环·失稳保护 | **小脑**（STM32 + 6 轴 IMU） |
| 执行层 | 串行总线 → 22 路总线舵机（双腿 10 · 双臂 8 · 躯干 2 · 头部 2） | 硬件 |

## P21 · 关节取舍：为什么是这 22 个
- **页眉**：03 技术架构与实现
- **标题**：少掉的每一个自由度，都是一个主动的工程取舍
- **导语**：这一页正面回答"为什么踝关节只有 1 个、为什么没有腕关节"。

**三张取舍卡**
1. **踝关节只保留 1 个（俯仰）**
   - 省下重量、成本与结构复杂度
   - 横滚方向由髋关节 roll 与步态相位补偿
   - 代价：侧向扰动容忍度下降，靠加大髋 roll 行程与控制频率弥补
2. **末端不设独立腕关节**
   - 夹爪直接安装在肘部末端
   - 代价：抓取姿态受限，只能做"正对目标"的抓取
   - 收益：减少 2 个关节、降低臂长与转动惯量
   - **目标明确：只做桌面轻物抓取（≤100 g），不做复杂抓取**
3. **躯干保留 2 个自由度**
   - 不是为了"凑够 18 个"，而是给行进中的重心补偿留余量
   - 上限只有 ±10° / ±15°，是"微调量"而非"大动作"
   - 副作用：上肢 + 躯干 = 10，正好压在官方下限上，无余量（已在 P19 标出）

- **视觉**：右侧放"设计目标示意"配图位（◇ 设计目标 · 非实物）
- **状态**：◇ 设计目标
- **口径**：取舍结果是 37.3 cm / 1.65 kg 这一组规格的直接原因，非事后解释

## P25 · 小脑层 · 双足步态生成 ← 核心页
- **页眉**：03 技术架构与实现
- **标题**：步态不是录好的动画，是每个周期现算出来的 40 帧
- **导语**：摆动腿与支撑腿相差半个相位，躯干做小幅反向补偿。

**左 · 步态相位图**：左右腿正弦相位（相差 π），标出摆动相 / 支撑相
**中 · 参数表**（取自 `config/robot.json`）
| 参数 | 当前值 | 含义 |
|---|---|---|
| 步长 `step_length_cm` | 2.0 cm | 单步前向位移 |
| 抬脚高度 `step_height_cm` | 1.2 cm | 摆动腿离地高度 |
| 步态周期 `period_s` | 0.8 s | 一个完整左右交替周期 |
| 控制周期 | 20 ms | 每周期采样 40 帧 |
| 6 步总帧数 | 240 帧 | 6 × 40 |

**右 · 生成逻辑**（`cerebellum.generate_gait()` 真实片段）
```python
phase = 2.0 * math.pi * t
left_amp  = max(0.0, math.sin(phase))
right_amp = max(0.0, math.sin(phase + math.pi))
frame = {
  "left_hip_pitch":   8.0 * left_amp  * step_length_cm / 2.0,
  "left_knee_pitch": 12.0 * left_amp  * step_height_cm,
  "left_ankle_pitch": -6.0 * left_amp,
  "trunk_pitch": 1.5 * math.sin(phase),
  "trunk_roll":  1.0 * math.sin(phase / 2.0),
}
```

**四个关节如何随相位变化**
- 摆动腿：`hip_pitch` 前摆 → `knee_pitch` 抬起 → `ankle_pitch` 落地缓冲
- 支撑腿：反相补偿，保持重心投影在支撑面内
- 躯干：`trunk_pitch` / `trunk_roll` 小幅正弦抵消重心偏移

- **状态**：● 已完成（纯 Python 已可生成并回放）；◐ 进行中（实机参数待标定）
- **口径**：**这是一套用于验证软硬件链路与帧序列调度的步态，不是已实测能稳定行走的步态。** 实机参数在 Webots 标定后替换。

## P29 · 感知层 · 视觉伺服闭环 ← 核心页 / 创新页
