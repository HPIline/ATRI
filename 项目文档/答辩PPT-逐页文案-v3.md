## P05 · 三重外部条件同时成立
- **页眉**：01 立项基础
- **标题**：政策、区域、赛事三条线，在同一年交汇到同一个点
- **重音数字**：`2026.4`
- **导语**：这三件事同时要求同一件东西：一台便宜、能拆开讲原理、能跑完整任务链的机器人。

1. **国家政策** —— 2026 年 4 月「具身智能」列入普通高等学校本科专业目录，西安交通大学为首批获批建设高校之一，同年秋季开始本科招生。新专业需要能成班开出的实验设备。
2. **区域政策** —— 陕西省推进「人工智能+教育」行动计划，需要可落地的教学载体，而不只是课程与平台。
3. **赛事规则** —— 人形机器人专项设小人形组，五项任务清单（人脸识别 / 二维码循迹 / 物品搬运 / 体育运动 / 娱乐休闲）本身就是一份可验收的教学大纲。

- **底部结论条**：三条线指向同一个缺口——缺少一台"买得起、拆得开、跑得完"的桌面双足平台
- **状态**：● 已完成（政策事实）
- **口径**：专业目录与西交大获批为公开信息；赛题清单依官方通知；地方政策来源见 `项目文档/大创赛_小机器人组_群聊讨论稿_v1.md` 第九节

## P07 · 门槛二：算法碎片化
- **页眉**：01 立项基础
- **标题**：五项任务、五套工程——学生学到的是五个互不相通的孤岛
- **导语**：现状不是"没有算法"，而是算法之间没有共同的骨架。

**左（现状）**：五个独立方框，各自带"相机初始化 / 状态管理 / 主循环"，中间虚线断口
**右（本方案）**：一个「JSON 任务卡 + FSM + 技能库」底座，上面五个技能模块插上去

**三条后果**
1. 换一项任务就要改主程序，实验之间无法对照
2. 无法评测"系统能力"，只能评测"某个脚本能不能跑"
3. 学生学到的是一次性脚本，不是可扩展的系统设计

- **一行结论**：任务 = 一份 JSON 文件；能力 = 一个技能模块；调度 = 一个状态机
- **状态**：● 已完成（底座已在仓库中实现）
- **口径**：左栏现状为对现有开源工程与常见参赛做法的归纳，非针对特定对象

## P08 · 门槛三：云端依赖
- **页眉**：01 立项基础
- **标题**：比赛现场拔掉网线的那一刻，很多方案就失效了
- **导语**：全离线不是技术炫技，是赛题要求下的工程必选项。

**上下链路对比图**
- 上（云端链路）：相机 → 上传 → 云推理 → 下发 → 执行，标出 4 个失败点（网络抖动 / 限速 / 服务变更 / 数据外传）
- 下（本方案）：相机 → 板载推理 → FSM → 小脑 → 舵机——整条链路在一个盒子里

**代价与边界**
- 本地小模型的识别精度不如云端大模型
- 我们的应对：先用固定光照 + 固定颜色目标把稳定性做上去，再逐步扩展工况
- 教学场景对数据外传敏感，离线同时解决了这一层顾虑

- **状态**：○ 规划中
- **口径**：不宣称任何精度对比数据；"精度不如云端"为设计阶段的定性判断

## P24 · 小脑层 · 双足步态生成
- **页眉**：03 技术架构与实现
- **标题**：步态是每个周期现算出来的 40 帧关节角序列
- **重音数字**：`40 帧 / 周期`
- **导语**：摆动腿与支撑腿相差半个相位。

**左 · 步态相位图**：左右腿正弦相位（相差 π），标出摆动相 / 支撑相
**中 · 参数表**（取自 `design/robot_model.json` 与 `config/robot.json`）

| 参数 | 当前值 | 含义 |
|---|---|---|
| 步长系数 `step_length_cm` | 2.0 | 生成公式里的线性系数（隐含 4°/cm） |
| 抬脚系数 `step_height_cm` | 1.2 | 生成公式里的线性系数（隐含 12°/cm） |
| 步态周期 `period_s` | 0.8 s | 一个完整左右交替周期 |
| 控制周期 | 20 ms | 每周期采样 40 帧 |
| 6 步总帧数 | 240 帧 | 6 × 40 |

**右 · 生成逻辑**（`cerebellum.generate_gait()` 真实片段）
```python
phase = 2.0 * math.pi * t
left_amp  = max(0.0, math.sin(phase))
right_amp = max(0.0, math.sin(phase + math.pi))
frame = {
  "left_hip_pitch":   8.0 * left_amp  * step_length_cm / 2.0,
  "left_knee_pitch": 12.0 * left_amp  * step_height_cm,
  "left_ankle_pitch": -6.0 * left_amp,
  "trunk_pitch": 1.5 * math.sin(phase),
  "trunk_roll":  1.0 * math.sin(phase / 2.0),
}
```

- **这一版生成的到底是什么（写清楚，避免被问穿）**
  - 它是一个**关节角时间序列**，用于验证"帧生成 → 20 ms 调度 → 舵机总线"这条链路
  - 支撑腿在 `max(0, sin)` 的下半周期输出为 0，即**该腿三个关节保持零位、不做蹬伸**；实测 40 帧中有 21 帧如此
  - `trunk_pitch` 与摆动腿**同相**（不是反向补偿）；`trunk_roll` 是**半频**，用于引入非对称扰动
  - 公式里的 2.0 / 1.2 是**角度系数，不是厘米位移**；代码不计算实际位移
- **状态**：● 已完成（纯 Python 与 Webots 均可回放）；○ 规划中（实机步态参数待标定）
- **口径**：**这不是一套已实测能稳定行走的步态。** 实机步态在 Webots 标定后替换。

## P28 · 感知层 · 视觉伺服：当前实现与目标实现 ← 核心页
- **页眉**：03 技术架构与实现
- **标题**：视觉伺服的闭环还差一个 while
- **重音数字**：`1 次 vs N 次`
- **导语**：把差距写出来，比把单次修正说成闭环更有说服力。

**左 · 当前实现**（`atri/skills/kick.py` 真实代码）
```python
obs = ctx.perceive("ball")           # 只在进入技能时检测一次
ball_x = float(obs.get("x_cm", 0.0))
if abs(ball_x) > 1.0:                # 单次判断，不回到检测
    yaw = max(-10.0, min(10.0, ball_x / 2.0))
    ctx.cerebellum.set_pose({"left_hip_yaw": yaw, "right_hip_yaw": yaw})
ctx.cerebellum.kick(...)
```
- **这是一次开环修正，不是闭环**：没有 `while`，没有二次检测，没有收敛判据

**右 · 目标实现**（阶段二）
```
while 迭代 < N 且 未超时:
    obs = 重新检测球位
    if |x| <= 1.0 cm: break          # 收敛出口
    yaw = clamp(x / 2, ±10°)
    调整朝向
执行踢球
```
- 加入最大迭代次数与超时，避免目标丢失时死循环

**两个已知的量纲问题（写在页面上）**
1. `x(cm) → yaw(deg)` 之间缺雅可比（相机像素到角度的映射）。按当前几何估算，球距 12 cm、横向偏 1.5 cm 需要约 7.1°，控制律只给 0.75°，**欠调约 9.5 倍**
2. 限幅 10° 在单次开环修正里没有"防过冲"的作用；它只有在闭环里才有意义
