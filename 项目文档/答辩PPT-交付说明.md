### 2. 最重要的一处翻案：把最强的证据藏起来了
`design/run_sim.py::servo_loop()` 是一个**真闭环**（含收敛出口、最大迭代、丢帧搜索、振荡降增益）。
v3 文案把它判为"阶段二待办"，等于自认没有量化证据。本轮实测复现：

```
偏移  5.0cm → 5 轮，末误差 0.240
偏移 12.0cm → 5 轮，末误差 0.930
偏移 20.0cm → 7 轮，末误差 0.850

sweep: ideal 12/12 ｜ nominal 12/12 ｜ harsh 9/12 ｜ adversarial 4/12
```

已写入 P28 / P31 / P43 / P47；P48 / P51 从「待办」改为「**待移植**」。

## 五、需要你决定 / 需要别人做的事（我没动的部分）

### A. 设计数据包里有三处判断，我判断属于他人工作区，没有修改
本会话期间另一个 agent 在该仓库提交了 7 个 commit（`design/`、`webots/`），因此我没有改动这些文件，只把问题原样报给你：

1. **`design/robot_model.json` 的 `design_constraints`**
   - `competition_max_depth_mm: 300.0` —— 官方六类约束里**没有"深度 ≤30cm"这一条**（官方是身高/体宽/**臂长(单侧)**）
   - `single_arm_max_length_mm: 300.0` —— **声明了但 `gen_urdf.check()` 从未校验**
   - 建议：删或改名深度约束；把臂长真正纳入 `check()`

2. **`design/drawings/01_关节编号图.svg` 的「尺寸合规核验」框**
   - 只核了高度/体宽/深度，**4 张图里"臂长"出现 0 次**，却写着"可直接用于报名与检录核对"
   - 本 PPT 的 P19 **刻意裁掉了这个框**并加了说明；但图纸本身若作为材料提交，建议重出

3. **质量预算未含舵机 / 扭矩口径**
   - `robot_model.json` 质量合计 1.650 kg，但 23 个 link 里**没有舵机**；22 只 STS3215 级舵机约 +1.25 kg
   - `effort_nm` 有 8 路 > 舵机额定 2.0 N·m，其中 4 路 = 堵转 3.0 N·m，且 `check()` 不校验扭矩
   - `design/packages/domain_random.json` 的 `mass_kg` 范围 `[1.55, 1.75]` 会随之错位

4. **`gen_urdf.py::reach_mm` 的标签**
   - 它从骨盆开始累加，输出 78.3 mm，标签却写"肩→夹爪"；真正的肩→夹爪约 **122.5 mm**
   - 本 PPT 用的是 122.5 mm（12.25 cm），工具的标签建议一并修

5. **`webots/README.md`** 说零行程关节是 `left/right_hip_yaw` + `hip_roll`，实测 `left_hip_yaw` 有 0.75° 行程（`kick.py` 下发的）
