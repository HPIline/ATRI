## 0. 先讲三个诊断（决定了后面所有设计）

### 诊断一：最大的问题不是「不够漂亮」，是「把自己的实力写没了」

现有 11 页 PPT 第 8 页写着：

> 五项任务实现　**规划中**

但同一份仓库里，`软件/atri/run_demo.py --fast` 现在就能一次跑通五张任务卡：

```
闭环演示完成: 5/5 项任务通过
```

`python3 -m unittest discover -s tests` → **Ran 51 tests … OK**
`atri/` 全部 import 只有 `abc / argparse / dataclasses / enum / json / math / pathlib / subprocess / sys / time / typing` —— **零第三方依赖**。

也就是说：**这不是一个"什么都没有"的项目，而是一个"软件栈已经真的跑起来了、硬件还在路上"的项目。**
现在的 PPT 用「规划中」一刀切，把已经可验证的 1494 行代码、51 项测试、五任务闭环演示全部让掉了。

> 修改意见里给的技术可信度 5.5/10、竞争力 6/10，多半就是这么丢的。
> **新 PPT 的第一原则：把已经能证明的东西，用能被当场验证的方式摆出来。**

### 诊断二：必须建立「三色状态标签」制度，否则前后口径一定打架

修改意见第 3、4、27 条的火力全集中在这里：前面写得像成品，后面说还没做。

新 PPT 的解法不是"把语气改软"，而是**把状态变成可见的视觉元素**：

| 标签 | 含义 | 颜色 | 判定标准 |
|---|---|---|---|
| `● 已完成` | 代码/文档/测试可当场查证 | 验证绿 `#2E9E7B` | 仓库里有，跑得起来 |
| `◐ 进行中` | 已启动，未完成 | 朱橙 `#E4572E` | 有人在做，有中间产物 |
| `○ 规划中` | 只有设计，无产物 | 中性灰 `#6B7A8C` | 方案写了，没落地 |

**全片每一处技术声明后面都挂一个标签。** 这一条同时解决三个问题：口径一致、评委一眼看懂进度、诚实度加分。

### 诊断三：现在的视觉方向是反的

现有主视觉 `hero-robot.png` 是：**全黑背景 + 紫青霓虹辉光 + 卡通表情脸 + 结构上不成立的机械手**。

这正是你说的「光怪陆离」。而且对答辩是**减分项**——评委看到一张结构错误的机器人渲染图，会本能地怀疑整份材料的技术严谨度。

新方向：**浅色底、真实结构、工程感**。理由很简单——**你要证明的是"我们真的算过这台机器人怎么做"，那么配图的气质就应该是产品规格书，不是科幻海报。**

## 1. 视觉设计规范

### 1.1 视觉主题：「工程蓝图 × 关节节点」

一句话：**整份 PPT 长得像一份被精心排版过的技术规格书，而不是一份宣传物料。**

三个贯穿全片的视觉母题（都承载信息，不是纯装饰）：

1. **淡网格底**：极浅的 8px 方格（透明度 6%），只在深色章节页可见，暗示"这是图纸"。
2. **关节节点**：小圆点 + 连线的图形语言。**每个圆点代表一个自由度**——章节页 03 的装饰就是 22 个点连成的拓扑链，不是随便撒的粒子。
3. **状态色点**：三色标签（见诊断二）。

明确禁止（这些是"廉价 AI 味"的来源）：
- ❌ 深色底 + 霓虹辉光 / 渐变荧光
- ❌ 圆角卡片 + 投影 + 玻璃拟态
- ❌ 彩虹色多系列图表
- ❌ 无意义的抽象科技背景（粒子、光带、电路板纹理）
- ❌ 与内容无关的 stock 图（握手、地球仪、齿轮、灯泡）

### 1.2 配色（2 结构色 + 1 强调色 + 2 语义色，共 8 个值）

```
墨蓝   #0A2540   深色章节页底 / 主标题 / 大数字
结构蓝 #1264A3   主色：架构图、连接线、表头、小标题
蓝雾   #E8F0F7   卡片底、分区底
浅蓝   #9CC0DC   次级线条、网格、未激活态
纸白   #F7F9FB   内容页页面底色
石墨   #1F2A37   正文
中性灰 #6B7A8C   次要说明、注释、来源标注
─────────────────────────────────────
朱橙   #E4572E   唯一强调色：关键数字、当前重点、风险
验证绿 #2E9E7B   唯一语义色：已完成 / 测试通过
```

设计意图：**结构蓝承担 80% 的视觉，朱橙只出现在真正需要看的地方（每页不超过 2 处）。** 颜色越少，重点越强。

> 为什么用交大蓝系而不是"科技紫"？答辩现场是西安交大的场子，用学校色系是**对口的**，而且蓝色在投影仪上偏移最小、最不刺眼。

| 页面主标题 | 思源黑体 SC Bold / 微软雅黑 Bold | 32–36 pt |
| 副标题（导语） | 思源黑体 SC Regular | 16 pt |
| 正文 | 思源黑体 SC Regular | 14 pt |
| 卡片小标题 | 思源黑体 SC Bold | 15 pt |

**⚠️ 需要你决策（见第 7 节 Q1）**：本机装了思源黑体 SC（Source Han Sans SC），但**没有微软雅黑**；Windows 机反过来。答辩当天用哪台机器放，就按哪台选字体。我的建议是**思源黑体 SC**——字重齐全（Light→Heavy）、免费、装一次即可，而且比微软雅黑更"工程感"。

### 1.4 版式与栅格

- 画布 16:9，13.333 × 7.5 in（与现有 PPT 一致，PDF 导出尺寸不变）
- 左右边距 0.83 in，上边距 0.55 in，下边距 0.50 in
- 内容区宽 11.67 in，12 栏栅格（每栏 0.90 in + 0.09 in 间距）
- **直角、细线、大留白**：卡片一律 1px 蓝雾描边 + 纸白底，无圆角无阴影

### 1.5 每页固定构件（易读性的关键）

```
┌──────────────────────────────────────────────────────────┐
│ 03 技术架构与实现              第 3 章 · 共 16 页          │ ← 页眉 9pt 结构蓝
│                                                          │
│ 一台任务从相机出帧到舵机到位，要经过 8 个环节             │ ← 主标题 34pt 墨蓝
│ 每个环节的职责边界清晰，换后端不动上层代码               │ ← 导语 16pt 中性灰
│ ────────────────────────────────────────────────────     │ ← 0.02in 结构蓝横线
│                                                          │
│                    【内容区】                             │
│                                                          │
│ ● 已完成  ◐ 进行中  ○ 规划中                              │ ← 状态标签条
│ A.T.R.I. 桌面自主人形智能                    09 / 51      │ ← 页脚 9pt
└──────────────────────────────────────────────────────────┘
```

**标题必须是完整判断句，不是名词短语。**
- ❌「系统架构」 → ✅「一次任务从相机出帧到舵机到位，要经过 8 个环节」
- ❌「创新点」 → ✅「二维码不只是标签，它本身就是一段可执行的程序」

这一条直接决定 PPT 是"言之有物"还是"空洞标题党"。

### 1.6 图表规则

- 单色系：所有图表默认结构蓝，仅"我们"用朱橙，仅"已完成"用验证绿
- 每个图表下方必须有 `数据来源：` 或 `口径：` 小字
- 折线/柱状图不放网格线背景，只保留坐标轴
- 架构图用**正交连线**（横平竖直），不用曲线箭头

### 第一章 · 立项基础（P04–P10）

#### P04 · 章首页 01
- **大标题**：为什么要在此时、此地，做一台桌面双足机器人

#### P05 · 三重外部条件同时成立
- **标题**：政策、区域、赛事三条线，在同一年交汇到同一个点
- **三栏 + 时间轴**：
  1. **国家政策**：2026 年 4 月「具身智能」列入本科专业目录，西安交大首批获批并于同年秋季招生 → 需要实验设备
  2. **区域政策**：陕西省「人工智能+教育」行动计划 → 需要可落地的教学载体
  3. **赛事规则**：人形机器人专项设小人形组，五项任务清单（人脸/循迹/搬运/体育/娱乐）本身就是一份教学大纲

- **版式**：三栏等宽卡 + 底部一条横向时间轴

#### P06 · 门槛一：设备价格
- **标题**：想开一门双足实验课，第一道坎不是教学法，是预算
- **`[绘]` 价格带对比图**（横轴对数刻度，三个色带）：
  - 全尺寸人形（如宇树 G1 级）：¥数万 – 十余万 → 一个班 20 台 = 百万级，不可能
  - 教育型小型双足套件：¥万元级 → 一个班 20 台 = 20 万，仍难成班
  - **A.T.R.I. 方案：¥1500–2800（新增采购）** → 一个班 20 台 ≈ 3–6 万，进入可申请范围
- **下方一行结论**：价格门槛不降下来，"成班开课"这四个字就不成立
- **小字口径**：价格区间取自公开电商页与厂商官方参数页；本方案为设计目标清单，见 P50

#### P07 · 门槛二：算法碎片化
- **标题**：五项任务、五套工程——学生学到的是五个互不相通的孤岛
- **`[绘]` 左右对照图**：
  - 左（现状）：5 个独立方框，各自带"相机初始化 / 状态管理 / 主循环"，中间画虚线断口
  - 右（本方案）：1 个「JSON 任务卡 + FSM + 技能库」底座，上面 5 个技能模块插上去
- **三条后果**（现状）：
  1. 换一项任务就要改主程序，实验之间无法对照
  2. 无法评测"系统能力"，只能评测"某个脚本能不能跑"
  3. 学生学到的是一次性脚本，不是可扩展的系统设计
- **本方案的解法**：任务 = 一份 JSON 文件；能力 = 一个技能模块；调度 = 一个状态机

#### P08 · 门槛三：云端依赖
- **标题**：比赛现场拔掉网线的那一刻，很多方案就失效了
- **`[绘]` 链路对比图**：
  - 上（云端链路）：相机 → 上传 → 云推理 → 下发 → 执行，标出 4 个失败点（网络抖动/限速/服务变更/隐私）
  - 下（本方案）：相机 → 板载推理 → FSM → 小脑 → 舵机，**整条链路在一个盒子里**
- **诚实的代价**：本地小模型精度不如云端大模型，我们先用固定光照 + 固定颜色目标把稳定性做上去，再扩展
- **一行结论**：全离线不是技术炫技，是赛题要求下的工程必选项

#### P09 · 我们要解决的那一个真问题 ← **全片题眼**
- **标题**：小型双足机器人，如何在有限算力和断网条件下，用统一任务描述完成多任务自主执行？
- **三个子问题**（这是后面技术章节的目录）：
  1. **怎么描述任务**，才能让五项任务共用一套程序？ → 第三章 · 任务卡与状态机
  2. **怎么在无 GPU 的板载算力上完成感知与决策**？ → 第三章 · 离线感知链路
  3. **怎么让动作不是死脚本，而是跟着视觉反馈走**？ → 第三章 · 视觉伺服闭环
- **版式**：中央大号问题句（28pt，墨蓝），下方三张子问题卡横向排列
- **说明**：这一页正面回应修改意见第七、八条——不再用"具身智能"这类大词包装，而是把创新收敛到一个具体问题上

#### P10 · 立项四条验收线
