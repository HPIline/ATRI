# A.T.R.I. 创新点与硬伤（本地速查）

> 用途：写材料、做 PPT、答辩前速查。**这份文件是单一事实来源（single source of truth）**，所有材料口径以本文为准。
> 更新日期：2026-09-10

---

## 一、创新点（收敛为一个，不要四个）

### ✅ 主创新点（写进材料、PPT、答辩）

> **任务卡—技能解耦的机器人任务描述规范**
>
> 新增一项任务只需写一个 JSON 配置文件和一个技能模块，**无需改动调度框架**。配套实现基于视觉反馈的迭代伺服闭环，使动作参数由实时感知计算得出，而非固定脚本执行。

**两个组成部分：**

| 组成 | 一句话 | 证据 |
|---|---|---|
| **A. 任务描述解耦** | 任务"做什么"与机器人"怎么做"彻底分离 | 现场加一个 JSON 就多一项任务，`brain.py`/`fsm.py` 零改动 |
| **B. 视觉伺服闭环** | 动作参数来自实时感知，不是固定脚本 | 改变目标初始位置 → 实际关节角序列不同；开环/闭环成功率对比 |

**为什么这个创新点站得住：**

1. **可当场验证** —— 不需要硬件，不需要仿真，评委可以亲眼看
2. **有代码支撑** —— 框架已存在（`task_card.py` 校验 + `brain.py` 技能注册表），只需补证据
3. **可量化** —— "新增任务从 XXX 行降到 YY 行"
4. **绕开短板** —— 纯软件，不需要样机
5. **一句话能复述** —— 评委能转述给别人

---

### ⚠️ 备选创新点（只在被追问时使用，不要主动写）

| 方向 | 什么时候用 | 风险 |
|---|---|---|
| 低成本+欠驱动约束下的步态可行性 | 被问"硬件这么差怎么做双足" | 需要数据支撑，3 天内难产出 |
| 能力边界（主动说明失效条件） | 被问"成功率多少" | ⭐ 推荐：回答"我们在什么条件下失效"比报数字可信 |
| 具身智能的具体机制 | 被问"具身智能体现在哪" | 答案：动作参数来自实时感知计算，非固定脚本 |

---

### ❌ 不要当创新点写的（评委每年看几百份）

| 常见写法 | 为什么不算 |
|---|---|
| "一台机器人完成五项任务" | 赛题规定，不是创新 |
| "二维码下发 JSON 指令" | 工程技巧，容易被当"花招" |
| "全离线运行" | 比赛规则硬性要求，做到是应该的 |
| "成本低、可教学复用" | 商业定位，非技术壁垒 |
| "采用了 ZMP / 逆运动学 / 深度学习" | 用现成方法是实现，不是创新 |
| "方案与研发记录同源" | 研发管理方式，评委不关心 |

## 二、硬伤清单（提交前必须逐项处理）

### 🔴 硬伤 1：ZMP 宣称与代码不符 —— **最严重**

| 位置 | 问题 |
|---|---|
| PPT 第 4 页 | 写着"基于零力矩点（ZMP）与倒立摆模型，毫秒级解算 22 自由度关节目标角" |
| `cerebellum.py:generate_gait()` | **实际是两条腿独立的正弦波**，没有任何 ZMP 计算 |
| 躯干控制 | `1.5*sin(phase)`、`1.0*sin(phase/2)` 是随手加的正弦扰动，**不是平衡补偿** |

**处理方式（二选一）：**
- **推荐：直接删掉这句**，改为"步态控制算法规划中"
- 或者：实现 LIPM 后如实写"已实现简化 LIPM 步态生成（纯 Python 验证）"

> ⚠️ **主动删掉一个兑现不了的宣称，比留着它更有说服力。** 评委发现一处夸大，会怀疑全部。

### 🟠 硬伤 3：完成态表述与实际进展撕裂

前面写"小脑负责…""机器人识别…"（像已实现），进展表又写"仿真/样机/五项任务全部规划中"。

## 三、答辩必答题（三问）

### Q1：创新点是什么？

> "我们的创新在**任务描述层**。传统做法是每项任务写一个独立程序，换场地或改规则就要重烧代码。我们把任务抽象成 JSON 任务卡，技能做成可注册的原子能力，中间通过统一的技能上下文注入参数和感知结果。
> 这意味着**新增一项任务只需要写一个配置文件和一个技能模块，不需要改动调度框架**。
> 我们可以现场演示：用一个二十行的 JSON 文件新增一项赛题之外的任务。"

**配合动作**：现场演示（如果允许）；或展示代码量对比表。

---

### Q2：具身智能体现在哪？

> "我们把具身性定义为**动作参数不是来自固定脚本，而是来自当前感知状态的实时计算**。
> 具体来说：同一个抓取技能，面对不同距离和角度的目标，会产生**不同的关节角序列**。这是可以观测验证的——改变目标初始位置，记录实际下发的指令，序列确实不同。
> 同时我们做的是迭代闭环：感知 → 算误差 → 微调 → **再感知** → 误差达标才执行抓取。不是执行一次固定动作就结束。"

---

### Q3：机器人在哪？（一定会被问）

> "项目目前处于**方案设计与软件验证阶段**。
> 已完成：22 自由度构型设计、SolidWorks 结构工程图、以及一套可运行的'大脑—小脑'软件栈——五项任务的调度、状态机、视觉与语音接口已通过单元测试，视觉伺服闭环可以在无硬件条件下完整验证。
> 实物样机**计划在晋级后启动**，优先借用校内现有平台验证算法，再自组样机。
> 我们清楚这在人形专项里是弱项，所以现阶段把重心放在**可复现的软件架构和工程仿真**上，确保方案不是停在纸面。"

**要点**：主动承认 + 说明为什么这样安排 + 展示已做的

## 四、AI 生成内容的三条铁律

1. **禁止编造数据。** 所有数字必须来自真实运行的代码，注明生成命令与日期。没有就写"未测试（规划中）"。
2. **每个 AI 产出都要能跑一遍、讲一遍。** 自己能跑 `python3 xxx.py` 得到同样结果，能用一句话说清"这是怎么来的"。**讲不清的删掉。**
3. **不用形容词替代证据。** "实现了高效的闭环控制" 不如 "误差从 12.3cm 收敛到 0.9cm，4 轮迭代"。
