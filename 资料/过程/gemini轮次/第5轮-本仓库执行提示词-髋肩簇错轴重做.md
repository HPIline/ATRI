## 0. 先接受一个判断（不许跳过）

**继续优化现有零件碰撞方案，是死路。**

原因不是「减重窗挖得不够」或「钟点位没翻够」，而是几何硬约束：

| 事实 | 数字 | 含义 |
|---|---|---|
| 髋 yaw→roll→pitch 三轴正交、两两相距 | **19.6 mm** | 写在 URDF / `robot_model.json`，改了运动学全废 |
| STS3215 沿输出轴厚度 | **35.0 mm** | 官方规格书 + B-rep 实测 |
| 机身长度（垂直轴） | **45.2 mm**，轴心偏置 10.2 / 35.0 | `kit.servo_frame()` |
| 现方案 | 每个关节原点放一只舵机，机体以原点为中心 | 两只 35 mm 厚的机体要挤进 19.6 mm 的轴距 |
| 钟点翻转实验 | 肩 pitch↔roll 16 255 mm³ **翻转后不变**；髋 yaw↔roll 7 521 mm³ **翻转后不变** | 互咬发生在**沿轴方向**，绕轴转 180° 不改变轴向占据 |

第 4 轮 Gemini K6 的可迁移结论（数值是 D 级，**拓扑方向可信**）：

> 两个舵机必须**沿轴线错开至少一个机身厚度**，把「大肚子」伸到轴距核心区外侧。
> **禁止**在虚拟轴线上把两套壳体共面交叠。

TonyPi「靠安装耳定轴距」对本机**不成立**（STS3215 无耳，见 `STS3215-机械接口核验.md`）。
可参考的是 OP2/OP3 和 SO-ARM100 的**错轴 / 分体抱箍**做法，不是耳厚拼轴距。

**所以本轮不是「推倒整个 CAD」**：

| 保留（经验资产，禁止重写） | 推倒重做（只这几处） |
|---|---|
| `kit.servo_frame()` / `orient()` 显式矩阵 | 髋簇 6 只舵机的**机体偏置**（左右 × yaw/roll/pitch） |
| `fitcheck.py` / `audit_assembly.py` / `build.sh` 闸门 | 肩簇 4 只舵机的机体偏置（左右 × pitch/roll） |
| 电子件 `kind` 落座、层高 `TORSO_*` | `compact_adapter` 的几何（现方案把下一级机体仍放在轴距核心） |
| I2 舵盘 PCD14 / I3 副轴 MF106ZZ / 金属舵盘外购 | 髋/肩处的笼·叉·座口，改为「单侧抱箍 + 外侧悬臂」 |
| 膝/踝/肘/夹爪的笼+叉+管（轴距 62.8/47.1/39.2，几何上放得下） | — |
| URDF 关节轴位置、限位、22 DOF 数 | —（轴距 19.6 **本轮不改**） |

## 2. 第 1 步：只对髋/肩簇做「错轴」布局实验（先数字，后改零件）

**目标**：证明「把机体沿自身轴向挪开」能把髋/肩舵机-舵机干涉清到接近 0，而不改 URDF 轴距。

做法（建议写进 `design/cad/fit_stagger.py`，不要手改常数试）：

1. 对每个髋/肩关节，给舵机一个沿**自身输出轴**的偏置 `stagger_mm`（正负两个方向都试）。
2. 约束：
   - 关节轴位置不动（`kin.joint_world(jname)` 的原点不变）；
   - 只动舵机占位体，先不动笼/叉（本步是布局可行性，不是出零件）；
   - 偏置上限建议 ±40 mm（再大就改包络了，记下包络增量）。
3. 输出一张表：

| 关节对 | 当前干涉 mm³ | 最优 stagger (mm) | 干涉 mm³ | 包络增量 (深/宽/高) |
|---|---|---|---|---|
| L hip_yaw ↔ hip_roll | | | | |
| L hip_roll ↔ hip_pitch | | | | |
| R 同上 | | | | |
| L shoulder_pitch ↔ roll | | | | |
| R 同上 | | | | |

**本步成功线**：上述 5 组舵机-舵机『摆放错误』全部消失（干涉 < 500 mm³ 或重合率 < 5%）。
失败则写清「哪个方向、多大偏置仍消不掉」——那才允许讨论改轴距（改轴距 = 改 URDF，本轮默认禁止）。

K6 的可执行图像（写进注释，防止下个人又把机体塞回原点）：

```
轴距 19.6 mm 只给「输出轴 + 薄支架」住，不给「机身 35 mm」住。

        轴 A (yaw)                    轴 B (roll)
           │                             │
           │  ← 19.6 mm →                │
     ┌─────┴──────┐                 ┌────┴──────┐
     │  机体 A     │                 │  机体 B     │
     │  沿轴 A 向外│                 │  沿轴 B 向外│
     └────────────┘                 └────────────┘
           ▲ 输出                       ▲ 输出
```

## 3. 第 2 步：重做髋/肩的连接件（这才叫「吸收经验迭代一版」）

第 1 步数字成立之后，才改零件。**新零件族建议另起函数名**，旧的 `compact_adapter` 先留着给膝/颈短链用，不要原地改到面目全非。

建议新件（名字可改，职责不能混）：

| 新件 | 替代谁 | 职责 |
|---|---|---|
| `cluster_horn_arm` | 髋/肩处的 `compact_adapter` 输入侧 | 锁上一级金属舵盘（I2），单侧臂把下一级轴线拉到 19.6 mm |
| `cluster_outrigger` | 髋/肩处的笼 | 在轴距**外侧**抱住下一级舵机两端面 4×M2.5；副轴侧保留 MF106ZZ |
| `cluster_cross` | 骨盆/肩座上的舵机座口 | 只开「轴 + 支架」通过的口，不再按 35 mm 机体开大口 |

硬约束：

1. **I2 / I3 不改**：金属舵盘 4×M2.5 @ PCD14；副轴 Φ6 + MF106ZZ。没有副轴第二支点 = K8#02 / K6 致命错误 #3，直接否决。
2. **STS3215 无耳**：禁止按「标准舵机 U 型架耳孔」建模。夹持面是两端面 4×M2.5 / 9.9×9.9。
3. **舵机壳体不当承力骨架**：弯矩走支架，不走塑料上盖。
4. **出线端不对头**：两只舵机的线座间距 ≥ 8 mm（K6 致命错误 #2）。
5. **批头可达**：沿每颗 M2.5 轴向反投射 Φ5.5 圆柱，与整机求交应为 0（K4/K8#09）。本步至少对髋簇做一次，做不到就改分件，不要假装能装。
6. 新件必须 **单实体 + `isValid()`**，走 `sanitize()`。
7. 参数从 `kit.servo_frame()` / `kit.IF` 取，禁止在零件里再写 35 / 24.7 / 10.2。

左右对称：先做左侧，右侧用轴镜像；镜像后检查手性（K2 常见错误 #3，螺纹/批头方向）。

## 4. 第 3 步：容积与背挂——只做「能装」的最小改，不做形体细化

这两项是第 4 轮修完约定后**暴露出来的真问题**，与髋肩簇一起处理，否则下次装配又被它们淹没。

### 4.1 背挂电子件（3 件悬空）

现状：STM32 / URT-1 / XL4015 / 功放 / 喇叭挂在 `x = −60`，整机深度会被拉到 ~198 mm；其中 STM32 / 功放 / 喇叭与任何零件都不接触。

本轮最小闭环（三选一，写进报告并执行）：

| 选项 | 何时选 |
|---|---|
| A. 补一个 `backpack_plate` 打印件，5 件都坐上去 | 接受深度 198 mm（赛题厚度 ≤300，仍有余量） |
| B. XL4015 + URT-1 留背挂（有接触），STM32/功放/喇叭改回舱内或减件 | 深度想压回 <150 mm |
| C. 换更小模块（需改 `components.json`） | 本轮不默认做，除非 A/B 都证明舱内仍撞 `head_yaw` 笼 |

**不要**再把 5 件塞回躯干「看看行不行」——第 4 轮已经证明树莓派落到 47.6 后顶部撞 `head_yaw` 笼 6 316 mm³。

### 4.2 头部相机

`camera` 与 `head_pitch` 舵机 8 041 mm³。处理：相机沿 +X 再送出，或缩小头壳内腔让位，**不要**改 `head_pitch` 轴位置。

## 7. 为什么不继续优化（给下一个会话，防止回退）

已经做过、证明无效的路：

1. **绕轴转 180°**：`fit_clocking.py` 全局翻转，舵机间 67 325 → 55 691 mm³，肩/髋互咬体积不变。
2. **开窗减重**：第 4 轮预览驱动迭代 1789 → 1470 g，关节模块材料下界仍 ≈ 18–20 g（笼）+14–16 g（叉），全打印 ≤900 g 不可达。
3. **修约定**：电子件 `kind`、层高、占位体中心——假干涉没了，真互咬还在。这是本轮与上两轮的本质区别。

还可以继续优化的，只剩膝/踝/肘的局部让位和打印工艺——**那些不是 26 对摆放错误的来源**。

## 8. 纪律（沿用，一条新加）

1. 程序按 `kind` 索引配件；解析不到就报错。
2. 舵机几何只从 `kit.servo_frame()` 取。
3. `orient()` 保持显式矩阵，禁止退回 `SetTransformation(gp_Ax3, gp_Ax3)`。
4. 改完过 `build.sh`；要提交时能过体检再 `STRICT=1`。
5. **新加**：髋/肩舵机的 `stagger` 必须是数据（来自第 1 步表），不许在 `assembly.py` 里手写一组「看起来没撞」的魔法数。
