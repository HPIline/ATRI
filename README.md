# A.T.R.I. (Autonomous Tabletop Robotic Intelligence)

A.T.R.I. 是一台 22 自由度的桌面双足人形机器人。面向自主决策与运动控制场景，软件在本地全离线闭环运行人脸识别、二维码指令、搬运、踢球、编排舞蹈五项任务。

核心控制软件位于 `software/atri/`，机构与运动学模型位于 `design/`，仿真环境位于 `webots/`。核心软件仅基于 Python 3.14 标准库构建，在没有实体硬件连接的情况下，也能直接跑通任务卡、技能状态机到舵机总线的完整闭环。

```bash
cd software/atri
# 1) 单元测试（344 项通过）
python3 -m unittest discover -s tests
# 2) 任务演示（五项任务卡无硬件闭环快速自检）
python3 run_demo.py --fast
```

项目仅支持 Python 3.14，CI 持续集成矩阵亦仅包含 Python 3.14。

## 目录结构

- `software/atri/`：核心软件栈。包含任务卡解析、状态机调度（FSM）、五项技能库、视觉与语音接口、参数化步态与动作库。主包零第三方顶层依赖。
- `webots/`：22 自由度机器人仿真世界、控制器及软硬件关节映射配置。
- `design/`：机器人正反运动学模型、URDF 描述、设计交接数据包以及基于 CadQuery 的参数化 CAD 装配（运行于独立的 Python 3.9.6 环境）。
- `ppt/`：答辩演示文稿生成脚本、图表模型与逐页文字稿。
- `docs/`：工程说明、调研及参赛规范文档（仅保留四份核心项目文档：`A.T.R.I.项目综述.md`、`BOM与阶段性指标.md`、`两套17自由度方案可行性核查.md`、`技术方案.md`，其余统一归整）。

## 软件契约与运行时安全

- **技能真实成败**：技能执行必须返回真实执行状态。若感知前置步骤未检测到目标，绝不下发实体运动指令，后续串行技能立即熔断，不虚报成功。
- **严格布尔判定**：感知返回的 `found` 字段严格只接受 Python 原生 `bool` 类型，任何非 bool 输入（包括字符串 `"False"`）均被判定为非法并拒绝。
- **超时与协作式中止**：任务超时由独立的定时器线程置位 `abort_event` 标志位。定时器线程绝不越权调用总线写入；长轨迹运动在帧边界主动检查该标志并退出；归零动作 `home()` 仅在主线程且在主流程返回后统一执行一次。
- **关节限位与非数拒绝**：所有关节角度在 `ServoBus.set_angle` 处统一完成物理限位安全钳制。遇到 `NaN` 或 `Inf` 异常数值立即报错拒绝，防止非数引发机械失控。
- **Webots 联调三层判定**：仿真联调判定通过必须同时满足三项硬性条件：关节映射必须精确覆盖全部 22 个合法关节名称；所有非空条目均被真实硬件接口成功绑定；在仿真运行周期内至少有一个关节产生大于 1° 的真实角行程（杜绝全零假阳性）。

|---|---|---|---|

| **整机总质量** | 3437 g | 3050 g | 包含 22 只舵机（1210 g）、电气件与连接紧固件；两套数据未做反向回灌 |

## 运行平台与环境支持

- **板载与开发系统**：基准运行环境为 Linux aarch64 配合 Python 3.14。由于目标嵌入式 Linux 镜像通常未预装 3.14，需要在板端自源码编译安装 Python 3.14。
- **语音引擎探测**：在 Linux 系统中，语音模块依次自动探测 `piper`、`espeak-ng`、`espeak`、`spd-say`，也可通过环境变量 `ATRI_TTS` 指定后端。若未探测到外部引擎，自动降级为安全 `MockTTS`。
- **硬件计算参考**：BOM 清单中的树莓派 4B（4GB）仅作为算力与成本参考选型，软件不绑定树莓派专有硬件，面向标准 Linux aarch64 环境开发。
- **大脑与小脑运行分工**：当前仓库中板载运行的是完整的 Python 小脑与动作调度。硬件架构规划中的 STM32 固件不属于当前软件仓库管理范畴。

## CAD 现状与结构改型

CAD 建模与装配检查位于 `design/cad/`，由于依赖 CadQuery 2.5.2 与 OpenCASCADE，固定运行在专用的 Python 3.9.6 虚拟环境（`.venv-cad`），执行入口：

```bash
bash design/cad/build.sh --fast
```

- **零件定位**：所有电子元件均通过底层固化的唯一标识字段 `kind` 匹配定位，不再使用多变的显示名称。
- **髋肩错轴拓扑**：针对 19.6 mm 微小轴距无法容纳两只 35 mm 舵机机体的物理干涉，改用沿舵机自身输出轴向外抽出 30–35 mm 的错轴结构（见 `fit_stagger.py`），配合专用连接臂 `cluster_horn_arm` 与外抱支架 `cluster_outrigger` 解决冲突。严禁采用 8–12 mm 的非标端面经验净距去篡改 stagger 偏移量。
- **干涉检测工具**：`fitcheck.py` 负责底层干涉判读，`interference.py` 负责整机大批量干涉扫描，模块权责明确。

## 审计分支改了什么

审计分支聚焦于软件可靠性、运行时安全保护、仿真严密性以及合规治理，修复了此前存在的系统性缺陷：

1. **纠正技能假成功缺陷**：修复了技能执行失败仍盲目上报 ok 的逻辑漏洞，确保感知失败时彻底中断动作下发。
2. **消减动作重复下发**：修正了踢球与舞蹈技能中由于状态调用重叠导致的底层动作重复触发问题。
3. **修复死参数与超时预算**：修正了循环步数不受超时控制的缺陷，将超时基准前移至任务进入点，杜绝超时后仍强行加塞技能。
4. **杜绝 Webots 假阳性测试**：重构了仿真评判逻辑，从过去的无有效绑定也能通过，升级为映射覆盖度、完整绑定率、真实运动行程三层约束。
5. **杜绝非数破坏性输入**：在总线层严密拦截 `NaN` 与 `Inf`，防止非数被错误钳制为限位极限导致机械满行程损坏。
6. **校正工程数据口径**：废除以 1.47 N·m 峰值充当安全达标的误导性表述，明确以 0.98 N·m 连续额定为核心主判据，指出减重必要性；更新电池标称需求至 ≥4.53 Ah。
7. **清理合规与依赖风险**：补全第三方开源 NOTICE 与许可说明，彻底移除未使用的无用依赖，确立单一 Python 3.14 架构。

## main 在分叉之后改了什么

自提交节点 `c5491d9` 分叉之后，main 分支主要围绕 CAD 详细机械装配和元件装配冲突展开迭代，形成了现行的几何设计：

1. **引入 fitcheck 装配判据原语**：合并装配判定标准，建立统一干涉校核原语，消除装配验证代码碎片化。
2. **电子件定位规则重构**：修复了 7 处板卡元件因字符串 key 匹配落空导致全数压在躯干舵机上的装配错误，改用稳定的 `kind` 属性进行座口装配。
3. **髋肩机构错轴重构**：针对 19.6 mm 间距下舵机机体共面严重冲突，设计了沿自身轴线平移 30–35 mm 的错轴空间构型，彻底消除了髋部与肩部舵机机体间的直接硬碰撞。
4. **增加装配连接新件**：在 CAD 零件库中新增 `cluster_horn_arm`（金属舵盘外侧连接臂）与 `cluster_outrigger`（外侧副轴抱架），并为多块后置板卡设计了集成背挂托板 `backpack_plate`。
