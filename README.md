## 软件栈（软件/atri）

“大脑—小脑”双层架构 + JSON 任务卡 + FSM + 五项技能 + **脚本动作库/步态生成**（已弃用 VLA）。
核心代码 **仅依赖 Python 3.9+ 标准库**，无硬件、无 GPU 也能跑通全流程。

已新增：
- `atri/perception/`：视觉感知接口 + Mock + OpenCV 实现（人脸/二维码/球）
- `atri/voice/`：离线关键词识别接口 + TTS（Mock / macOS say）
- `atri/qrgen.py`：二维码 JSON 指令生成器
- `action_library/`：动作库 JSON 规范 + 示例 + 校验/回放

```bash
cd 软件/atri

# 编译检查
python3 -m compileall -q atri run_demo.py && echo "compile OK"

# 单元测试（当前 168 项）
python3 -m unittest discover -s tests

# 无硬件闭环演示（五项任务卡；--fast 跳过 sleep 用于快速自检）
python3 run_demo.py --fast
```

## ✅ 已决策：新架构 v2（2026-09-11）

**原"路线分歧"已收敛。** 处置办法：把整机尺寸对齐到量产参考机
（幻尔 TonyPi Pro，373 mm / 1.8 kg / 20 DOF），并把模型质量从"结构占位预算"
改成**真实分布**。完整参数见 **`design/handoff/新架构参数总表.md`**。

| 项 | v1 | **v2** |
|---|---|---|
| 身高 × 宽 × 厚 | 475 × 190 × 123 mm | **373 × 190 × 123 mm**（身高对齐参考机） |
| 整机质量 | 2263 g（实口径） | **2146 g** |
| link 质量口径 | 结构占位 1650 g，**不含舵机/电子件** | **结构 + 舵机 + 电子件 + 线束**（URDF 可直接做刚体动力学） |
| 最大关节需求 | trunk_roll 1.29 / 腿 1.11 N·m | **trunk_roll 1.26 / 腿 1.05 N·m** |
| 扭矩判据 | "额定 1.0 N·m"（**无权威出处**） | **堵转 × 50% = 1.47 N·m**（依据：参考机 1.8 kg 用 1.67 N·m 堵转舵机即可行走） |
| 结论 | 115% 额定，余量耗尽 | **腿 71% / 躯干 86%**，裕度可用 ✅ |

**已修正的两个认识错误：**

1. **"结构减重数学上堵死"是错的。** 同尺寸下你们的结构件（552 g）比参考机放大到同尺寸还轻 15%
   —— 没有浪费。多出的质量里 220 g 是赛题要求的额外 4 个自由度，235 g 是原来更高的机身。
2. **"余量耗尽"主要来自一个没有出处的额定值。** 按厂商实际选型习惯（连续 ≈ 堵转一半），
   STS3215 12V 版裕度是够的；不够的是 7.4V 版。

**仍未消除的唯一硬不确定项**：STS3215 的真实连续扭矩与温升。
→ **建议动作：买 1 只 12V 版实测（约 90 元）**，这比换构型、换材料、买整机都便宜。

## 与外部部件库的协作

本项目缺少工业制品的世界知识（舵机孔位、轴承规格、走线工艺等），
这部分由外部部件库（Gemini 网页版）补充，协作方式：

```
Gemini  →  真实元件参数（型号/尺寸/质量/协议/工艺坑）
              ↓  人肉录入 design/components.json + design/cad/standards.py
本项目  →  check_fit.py 校验（装得下吗？重量对吗？力矩还够吗？）
              ↓
          反馈问题给对方，进入下一轮
```

**分工原则**：对方提供参数，本项目负责**一切需要与模型对照的判断**
（对方看不到模型，此类判断必错）。

已完成 3 轮，交接包见 `design/handoff/`。
