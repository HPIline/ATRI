### 3.1 重摊方法（逐 link 质量怎么来的）

真正做分摊的是生成器 `design/gen_v3_baseline.py` 的 `_apply_structure_scale()`
（**本轮未改这个函数，连一行都没改**），其算法是：

```
k = 新的结构件总量 / 已应用的结构件总量 = 1390.4 / 1490.0 = 0.93315436…
① 每个 link：mass_breakdown_g.structure ← round(旧值 × k, 1)
② 线束/紧固件 120 g 按权重重摊：
   w(link) = structure + servos + electronics（新值）
   harness_fasteners ← round(120.0 × w / Σw, 1)
③ mass_kg ← round((structure + servos + electronics + harness_fasteners) / 1000, 5)
```

幂等：同一个 1390.4 反复跑结果一致（`--refresh` 比对已应用值后直接跳过重算）。

**重摊口径的已知局限（必须写清，否则会被误读成「逐 link 都是实测」）**：
统一比例 **不区分零件族**，等于把各族的真实增减**抹平**成一律 −6.69%。本轮实际被抹平的族差：

| 零件族 | 前小计 | 后小计 | 真实增减 | 统一比例对该族的等效增减（示意 = 旧小计 × 6.69%） |
|---|---|---|---|---|
| `pelvis_frame` | 97.9 | 50.4 | **−47.5** | −6.6 |
| `torso_frame` | 164.9 | 137.6 | **−27.3** | −11.0 |
| `head_shell`（PLA，密度与 PETG 不同） | 67.9 | 53.9 | **−14.0** | −4.5 |
| `foot_plate` | 64.2 | 53.4 | −10.8 | −4.3 |
| `cluster_outrigger` | 137.4 | 137.2 | −0.2 | −9.2 |
| `gripper_jaw` | 9.0 | 9.3 | **+0.3** | −0.6 |
| `joint_cage` / `limb_tube` / `limb_fork` / `joint_cage_yaw` / `cable_clip` 等零差族 | — | — | 0.0 | 一律 −6.69%（相对） |

⇒ **逐 link 质量只保证「总量正确（1390.4 g / 81 件）」，不保证「逐 link 精确」**：误差 = 该 link 的
族构成偏离全局平均（−6.69%）的程度。极端情形——若某 link 全由 `pelvis_frame`（真实 −48.5%）构成，
统一比例会把 97.9 g 记成 91.3 g，**偏差 +40.9 g（+81%）**；`head_shell`（真实 −20.6%）同量级。
所以 6.69% 只是**全局平均差**，不是逐 link 误差上界（本报告初稿曾误写成上界，已订正）。
要做到逐 link 精确，需要给生成器加一张「零件族 → link」映射表（本轮**未做**，见 §9）。

### 7.1 `trunk_roll` 的「系数语义不自洽」——查清了，**是题设那个算式用错了聚合方式**

题设怀疑：`1.688 × 9.81 × 0.137 × 1.8 = 4.08 ≠ 表值 1.899`。逐项复核结论：

1. **本管线算的不是 `M_总 × r_max`，而是 `Σ mᵢ·rᵢ`**（每个下游 link 各用自己的力臂）：
   `total_moment = Σ mᵢ·rᵢ` → `τ_g = total_moment/1000 × 9.81` → `τ_req = τ_g × 1.8`。
   改动前实测 `Σ mᵢ·rᵢ = 107.5419 kg·mm` → `τ_g = 1.0550` → `×1.8 = 1.8990` **正好等于表值 1.899**。
   改动后 `Σ mᵢ·rᵢ = 103.9144 kg·mm` → `τ_g = 1.0194` → `×1.8 = 1.8349` = 新的 1.835。
2. 复核全部 22 个关节：`gravity_torque_nm` 与独立重算的 `Σ mᵢ·rᵢ·g` **全部吻合**（不一致关节数 = 0），
   即 `gravity_torque_nm × 1.8 = required_torque_nm` 在 gravity 主导的关节上恒成立。
3. 题设的 4.08 是把**全部下游质量 1.688 kg 都放在最大力臂 137.4 mm 上**得的上界，
   它比真实 `Σ mᵢ·rᵢ` 大 2.23 倍（231.9 vs 103.9 kg·mm）——所以 4.08 不是本管线的输出，
   **不是生成器的算错**，而是那个对照算式的口径错误。

**结论文本（可直接引用）**：`trunk_roll` 的 1.899（旧）/ 1.835（新）由
`τ = Σ mᵢ · g · rᵢ × 1.8` 得出，`Σ mᵢrᵢ` 是逐 link 力臂加权和，不是 `M_总 × r_max`；
系数 1.8 是显式声明的静力安全系数（`ASSUMPTIONS.safety_factor_static`），语义自洽。

### 7.2 但顺手查出一个**真正需要复核**的问题：力臂定义把「竖直分量」算进去了（**待复核，本轮未改**）

`gen_handoff.perpendicular_arm()` 取的是**质心到关节轴线的垂直距离**（含 z 分量）。
而绕水平轴的重力力矩只由**水平面内的偏移**决定：`τ = m·g·|r_x·a_y − r_y·a_x|`，
质心正对轴线上方/下方时力矩**为 0**。实测偏差（新模型，只读复核，脚本 `torque_semantics_check.py`）：

| 关节 | 代码口径 τ_g | 真实零姿态水平力臂口径 τ_g | 高估倍数 | 是否影响选型结论 |
|---|---|---|---|---|
| `trunk_roll`（轴 [1,0,0]） | 1.0194 | **0.5038** | **2.02×** | ⚠️ **是**（重力主导）：修正后 0.5038×1.8/0.98 = **92.5%**，会从「超额定」变成「不超」 |
| `trunk_pitch`（轴 [0,1,0]） | 0.4466 | **0.0000** | ∞ | ⚠️ 是（重力主导）：躯干质心正对俯仰轴，零姿态静力矩应为 0 |
| `hip_pitch` / `knee` | 0.2716 / 0.0963 | 0.0158 / 0.0158 | 17.2× / 6.1× | 否（需求由单腿支撑项 1.315 / 1.383 主导，与该函数无关） |
| `ankle_pitch` | 0.0158 | 0.0158 | 1.00× | 否（同上，由支撑项 1.446 主导） |

**为什么标「待复核」而不是直接改**：(1) 本轮硬约束只允许回灌质量，改力矩模型会动到
`gen_handoff.py`（不在允许面内）；(2) 修正方式本身需要一次口径决策——
按「零姿态静力」取水平力臂，还是按「关节限位内的最不利姿态」取
（例如 `trunk_pitch` 限位 ±15°，若其下游质心集中在 137 mm 高处，最不利水平力臂 = 137·sin15° ≈ 35 mm，
而不是 0、也不是 137 mm）。**两个口径差 ~4 倍，必须由设计决策定，不能由本线程顺手选一个。**

⇒ 因此上表 187.2% / 82.0% 这两个数是**现行管线的一致性输出**，但
**在力臂口径定案前，`trunk_roll`（以及一切 gravity 主导关节）的百分比不能当最终结论用**。
