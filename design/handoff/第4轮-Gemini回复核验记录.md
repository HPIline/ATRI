## 0. 一句话结论

**K1/K2/K4/K5 是方法论，可直接采纳；K3 是可核的数值表，与本仓库已标定值有 5 处出入；
K6/K7/K8 是经验清单，需要落成断言才有价值。**

必须说清一件事：**K1–K8 里几乎每个数值的来源等级都被对方自己标成 D**
（= 对方自述 / 行业经验，非官方文档、非实测）。按本仓库第 1 条规矩
"每个参数必须有出处，找不到出处的标 `provisional`"，**这批数值一律是候选值，
不得直接改进 `standards.py` 覆盖已有标定**。

反过来，本仓库 `standards.py` 的 `TOL` 段标的是 `verify: "calibrated"`、
来源"部件库实测标定"，**出处等级高于 K3**。所以下面 5 处出入的正确处置是
**"记下差异 → 试件标定定案"，而不是"按 K3 改"**。

### 1.1 K3 的一条系统性差异（值得单独说）

上表第 3、4、7 条是**同一个根因**：本仓库的打印通孔/底孔一律取
**"螺纹公称 + 0.2"**（M2→2.2 / M2.5→2.7 / M3→3.2），而 K3 建议 M2.5 取 +0.3~+0.4。

- 这不是三个孤立差异，是**一条会传播到全库所有孔的约定**。
- 定案成本极低：**打一块测试板，M2.5 通孔做 2.6/2.7/2.8/2.9/3.0 五档，
  各拧一次螺钉，一次就能定**。这与第 3 轮"买 1 只舵机实测"是同一类"便宜的验证"。
- 在标定之前，**不改** `standards.py`——现有值标的是 `calibrated`，出处等级高于 K3 的 D。

## 2. K1 核验（可直接落地的两条）

### 2.1 fuzzy 容差：本仓库全库未设 —— 可直接采纳

```bash
$ grep -n "Fuzzy\|fuzzy" design/cad/*.py
（无输出）
```

K1 指出 OpenCASCADE `BRepAlgoAPI` 求交应设 `FuzzyValue = 0.01~0.05`，
否则共面处会因三角化漂移产生"零厚度实体"式假阳性。

**这条与本仓库现状直接相关**：`fitcheck.py` / `audit_assembly.py` 用的是
`BRepAlgoAPI_Common` 且未设 fuzzy，而 §6.1 的体检分布里恰有
**15 对 <100 mm³、97 对 100–1000 mm³** 的小体积对——其中一部分很可能就是
K1 所说的共面假阳性，而不是真干涉。

**建议**：在 `fitcheck.py` 里把 fuzzy 提成参数（默认 0.01），并做一次
"fuzzy=0 / 0.01 / 0.05"的对照体检，看小体积对的数量如何变化。
**这是一次可复现的实验，不是拍脑袋调参。**

### 2.2 判读口径：K1 与 §6.1 互补，建议合并

- §6.1（本仓库）按**严重度**三分：重合率 ≥30% 或 ≥5000 mm³ = 摆放错误；
  5–30% = 让位不足；其余 = 局部干涉。
- K1（对方）按**界面类别**给允许量：过盈压配、热熔螺母、间隙配合、贴合面、
  运动副、螺纹、卡扣、线缆、电子件占位体。

两者不冲突：**先按界面类别查"允许不允许"，再用严重度决定"改不改"**。
合并成一张表即可，无需推翻 §6.1。

### 2.3 K1 明确点出的一个本仓库真问题

K1 末行"标准电子件简易占位体"要求：**必须把电子件拆成"PCB 基板"与"接插件组件"
分别对待**，并指出 AABB 式占位体会在引脚避空区报假干涉。

这与 §6.2 查出的电子件问题是**同一类**：仓库现在 7 件电子件的占位体来自
`placements.json`，是整体包络，没有"接插件伸出去"的区分。这条可以直接指导
§6.4 第 1 条（加稳定 `kind` 字段）之后的建模细化。

## 3. K2 / K4 / K5 核验要点

### K2 · 基准与配合
- **datum A/B/C 消自由度**（3+2+1）与 `kit.servo_frame()` 的取向修正是**同源思路**：
  本轮刚踩的坑（`orient()` 轴向映射错、35 与 24.7 用反）本质就是"没有显式基准"。
- "常见建模定位错误"4 条里，**第 1 条（世界坐标隐式累加）和第 2 条（URDF 原点
  与装配基准混淆）在本仓库都有对应史**：`assembly.py` 的 `ELEC_DECK_TOP` /
  `ELEC_BACKPACK` 就是"手写常数 + 字符串分支"，第 4 条（AABB 快筛）与 §6.1 同源。
- 5 条 CI 断言模板可直接落到 `fitcheck.py`（原语已具备：干涉体积 / 最小距离 /
  包围盒重叠）。**建议优先实现断言 3（穿透深度红线）与断言 2（同轴度）** ——
  后者正对 K8#02 的"副轴第二支点"失效。

### K4 · DFA
- **逆拓扑拆卸法**可直接跑：仓库已有 STL/B-rep 与装配树，生成"沿 ±X/±Y/±Z
  平移无穷远"的脱出测试在算法上无新依赖。
- 工具包络表（M2→Φ4.5 / M2.5→Φ5.5 / M3→Φ7.0）与本仓库用到的 M2.5、M3 对得上，
  **可直接写成断言：沿螺栓轴向反投射 Φ5.5/Φ7.0 圆柱，与整机求交应为 0**。
  这条正是 K8#09，也是"答辩现场装不起来"的典型死法。

### K5 · 极限姿态
- 5 个基准姿态（劈叉 / 侧踢 / 深蹲 / 抱胸 / 低头+偏航）**提得对且覆盖面好**，
  比"离散枚举"务实。与仓库 `design/atri.urdf`（23 link / 22 joint）直接对接。
- **建议先实现"深蹲"与"抱胸"两个**：前者暴露大腿-躯干挤压（也正是 §4.2 里
  髋部干涉的工况），后者暴露双臂与胸腔。
- 表中具体间隙值（8/5/6/10/3 mm）是 D 级，**先当"告警线"而不是"红线"**，
  跑出实际最小距离后再定。
- $\Delta\theta_{\text{margin}} = 2.5°\sim5°$ 与仓库 URDF 的关节限位可直接对照。

## 4. K6 / K7 / K8

### K6 · 小轴距堆叠 —— 参考价值有，但有一条**不可迁移**
- 三个标杆（OP2/OP3 轴距 18 mm、TonyPi 22–24 mm、SO-ARM100 腕部 28 mm）都是
  D 级、仓库内无法证实，只能当**布局方向的旁证**。
- ⚠️ **不可迁移的一条**：K6 说 TonyPi"轴心距离直接由两舵机**耳**厚度决定"。
  但 TonyPi 用的是幻尔 LX-824HV（**有**安装耳），而本机 STS3215 **没有安装耳**
  ——这一点在第 4 轮之前的核验里已被三源证伪（见 `STS3215-机械接口核验.md`）。
  所以 K6 里"靠耳厚定轴距"的解法**对本机不成立**。
- K6 的"堆叠致命错误"第 3 条（**把舵机壳体当承力骨架、未在对侧设副轴支撑**）
  与本仓库 `joint_cage` 的"−Y 板 MF106ZZ 骑副轴"设计方向一致 ✅，
  可以作为该设计的**独立佐证**。

### K7 · 座口与减重 —— 与仓库现有规则基本一致
- 内角圆角 R≥1.0 / 立柱 R≥1.5 ✅ 已满足（`fillet_min_mm` / `fillet_struct_mm`）。
- 加强肋比例（$T_{rib} \ge 0.8T_{壁}$、$H_{rib} \le 4T_{rib}$、45°–60° 过渡）
  仓库**尚无对应规则** → 可作为新增的建模约束。
- 悬臂梁 $\delta = FL^3/3EI$ 与"挖中心 40% 减重 50%、刚度损失 <15%"
  与仓库 `limb_tube` 的减重窗设计方向一致 ✅。
- "螺栓孔周围 $3\times D$ 范围做实心填充"是**可直接写进零件生成器**的硬规则，
  仓库当前无此约束。
- **蠕变松弛**（PETG 48h 预紧力衰减 20–35%）是 D 级，但方向可信，且解释了
  为什么必须用**大外径平垫圈**（DIN 9021）而非普通小垫圈——仓库 `standards.py`
  目前只有螺钉头径，**没有垫圈规格**，建议补。

### K8 · 失效模式 FMEA —— 本轮最可落地的部分

## 5. 元问题（与第 3 轮同一个）

第 3 轮的结论是："**对方的结构性洞察有价值，具体数值常常无出处**"。
这一轮**同样的模式又出现了一次**，而且更隐蔽：

- K1/K2/K4/K5 是**方法论**，不含需要出处的数值 → 直接可用 ✅
- K3/K5/K6/K7 里的**具体数字几乎全是 D 级**，但对方给每行都标了"置信度：高"
  —— **"置信度高"说的是它自己有多确定，不是"有出处"**。按本仓库的规矩，
  这两件事必须分开看。
- 真正有价值的三条，恰恰不是数字，而是**分类**：
  ① 把"间隙"拆成定位/避空两档（K3 第 5、6 行）；
  ② 把"干涉"按界面类别分级而非一刀切（K1）；
  ③ 把"摆放错误"与"配合不足"分开（K1，与 §6.1 独立同源）。

**因此本轮的处置是**：
1. 方法论（K1/K2/K4/K5/K7/K8 的规则部分）→ 落成 `fitcheck.py` 断言与 CI 门禁；
2. 数值（K3 全表 + K5/K6/K7 的间隙值）→ 登记为 `provisional` 候选，
   **用测试板/试件一次标定**，不覆盖已有的 `calibrated` 值；
3. K6 的标杆数据 → 仅作布局旁证，且**剔除"靠安装耳定轴距"这条对本机不成立的**。
