## 三、② 为什么无解：**同一 link 两端的关节模块自己就互穿**

管子只是"套在两端 Φ34 插接芯棒上的套筒"。若两端模块的轴向占用已经互相重叠，
则**无论管子做成什么形状**都不可能同时套住两根芯棒。`--mode spigot`（零件级真布尔，秒级）：

```
joint_cage（子端笼）: 局部 z[-15.35,29.35]，芯棒基面 z_cap_top = 17.35（= 管口最浅位置）
标准叉（髋/膝/肩）: 局部 z[-39.35,14.35]；z 最负端 = 芯棒尖端（管口最深位置）
紧凑叉（肘）: 局部 z[-28.00,16.00]；z 最负端 = 芯棒尖端（管口最深位置）

--- 大腿/小腿（link 62.8）
    叉 ∩ 笼 = 2207 mm³（1 对 solid）
    重叠区 z[-39.35,-33.45]（轴向重叠 5.90 mm）
    若两端让到芯棒基面则管长只剩 18.10 mm（标准叉）/ 29.45 mm（紧凑叉）
--- 上臂（link 47.1）
    叉 ∩ 笼 = 2414 mm³（1 对 solid）
    重叠区 z[-32.75,-24.35]（轴向重叠 8.40 mm）
    若两端让到芯棒基面则管长只剩 2.40 mm（标准叉）/ 13.75 mm（紧凑叉）
--- 前臂（link 39.2）
    叉 ∩ 笼 = 3684 mm³（1 对 solid）
    重叠区 z[-24.85,-13.00]（轴向重叠 11.85 mm）
    若两端让到芯棒基面则管长只剩 -5.50 mm（标准叉）/ 5.85 mm（紧凑叉）
```

**反证**：铰接件之间的轴向占用是硬账 ——
父端标准叉占 **39.35 mm**（芯棒尖端到关节轴），子端笼占 **17.35 mm**（管口最浅位置 = 顶板上表面），
两者相加 **56.7 mm**。而 URDF 给的 link 长度是：大腿/小腿 62.8 ✓（只剩 6.1 mm 可用）、
上臂 **47.1**（差 9.6）、前臂 **39.2**（差 17.5）。**前臂让位后管长算出负数** ⇒ 该 link 上"管"这个零件在
几何上不存在。这也解释了交接档案队列 ⑦ 那条"叉 ↔ 相邻关节笼 ≥4 对 × 2207"——
我这次实测到的 2207 / 2414 / 3684 就是同一根因的零件级定量。

## 五、C 头颈簇：Top1 的定量诊断与死结边界

### 5.1 Top1 到底怎么来的（`--mode neck` 实测，世界坐标）

```
| # | A | B | 体积 mm³ | 世界包围盒 |
| 1 | `cage__head_yaw`          | `torso_upper__torso_frame` | 4418 | z[106.5,116.1] |
| 2 | `cage__head_yaw`          | `elec__Raspberry Pi 4B (4GB)` | 4224 | z[106.5,108.7] |
| 5 | `elec__UVC 相机模组`       | `servo__head_pitch`        | 3556 | z[163.0,169.3] |
| 6 | `cage__head_yaw`          | `servo__head_pitch`        | 3512 | z[144.7,150.0] |
| 7 | `servo__head_pitch`       | `servo__head_yaw`          | 3226 | z[144.7,153.5] |
```

关键件世界包围盒：`cage__head_yaw z[106.50,150.00]`、`elec__Raspberry Pi 4B z[91.70,108.70]`、
`servo__head_yaw z[107.90,153.50]`、`torso_frame（颈座实体3）z[104.10,116.10]`。

**Top1 的机理**：head_yaw 关节轴在世界 **z = 129.5**（URDF：torso_upper 系 82.4 + 躯干件整体 +47.1）。
笼子的 −Z 侧（输出侧）端板原本按 `z_out = −BOSS_FACE = −20.0` 定位 ⇒ 端板占 z −23.0…−20.0
⇒ 世界 **106.5…109.5**，而 RPi 4B 占位体顶面 **108.7** ⇒ **2.2 mm 压进去**，面积 ~1920 mm²
⇒ 4224 mm³，重合率 20%（= 全机 Top1）。

### 5.2 改法（本线程唯一改动）与"为什么这是对症的"

`joint_cage_yaw()` 里 `z_out = −BOSS_FACE` 这条取值的含义是"−Z 侧板的内表面贴凸台面"，
**它只对"输出凸台朝 −Z"的关节成立**（两个 hip_yaw，`shaft=="-z"`）。head_yaw 是 `shaft=="+z"`（输出朝上），
−Z 侧只有 Φ6 副轴 ⇒ 端板应该贴**机体端面 −Y_HALF**，把副轴放进中央 Ø21 避空里。改成：

```python
z_out = -BOSS_FACE if shaft != "+z" else -Y_HALF
```

效果（零件级实测，`joint_cage_yaw(parent="+z", shaft=...)`）：

```
shaft=+z: solids=1 V=21001 z[-20.50,20.50] x[-28.00,28.00] y[-23.00,23.00] valid=True   ← head_yaw：zmin −23.00 → −20.50
shaft=-z: solids=1 V=21632 z[-20.50,23.00] x[-28.00,28.00] y[-23.00,23.00] valid=True   ← hip_yaw ×2：取值表达式未变，量测一致
```

笼子最低点 106.5 → **109.0 mm**，RPi 顶面 108.7 ⇒ 让出 **0.3 mm** ⇒ Top1 整对消失。

⚠️ **本次改动"没做"什么（别夸大）**：`shaft=="+z"` 时两块端板的功能分工**仍然是错的**——
带 MF106ZZ 轴承孔（+4×M3 法兰孔）的那块板在 **+Z 侧**（= 舵盘侧），带 Ø21舵盘避空的那块在 **−Z 侧**（= 副轴侧）；
按 `orient` 的约定副轴应在 −shaft 侧，所以**轴承装在了有舵盘的一侧、避空开在了有副轴的一侧**。
本线程只把 −Z 那块板**整体上移 2.5 mm**（不动它的开孔与功能），因此这个"两板装反"的问题**依旧存在**，
列入 §九 待拍板清单（它属于接口朝向问题，改它要同时调整 ±Z 两块板与 4×M2.5 孔链，超出本次时间盒）。

## 七、口径发现：`val()` 只取第一块 solid（**建议单独立项**）

本线程在写诊断脚本时发现：`assembly.py::_place()`→`kit.apply_trsf()` 把零件建成**多 solid 的 Workplane**，
而下游一律用 `Workplane.val()` 取件，`val()` 只返回 **`objects[0]`**。受影响链路（主会话已逐行核实）：

| 文件:行 | 语句 | 后果 |
|---|---|---|
| `fitcheck.py:18-19` | `bbox_of()` = `shape.val().BoundingBox()` | **包围盒粗筛就只拿第一块** |
| `fitcheck.py:31` | `common_volume()` = `BRepAlgoAPI_Common(a.val().wrapped, …)` | 真求交只算第一块 |
| `fitcheck.py:42` | `distance()` = `BRepExtrema_DistShapeShape(a.val().wrapped, …)` | 连通性图只看第一块 |
| `fitcheck.py:93` | `overlap_report()` 的 `vols = [w.val().Volume() …]` | 连"重合率"分母也只算第一块 |
| `interference.py:86,94` | `shapes = [(n, w.val()) …]` + 粗筛 | 第 2、3 块**在粗筛阶段就被丢弃** |
| `pair_inspect.py:105` | `BRepAlgoAPI_Common(a.val().wrapped, …)` | 同上 |

**实测影响**：全机 86 件里**只有 `torso_frame` 是多实体（3 块）**（足板重做后已恢复单实体）。
所以官方读数**系统性漏掉了 `torso_frame` 的实体 2 与实体 3**：
实体 2 无干涉（漏检无害）；实体 3 有 4 对 / 8214 mm³（**漏检有害**，且其中 `cage__head_yaw ↔ RPi`
是"真 Top1 旁边的邻居"）。⇒ **任何"把 torso_frame 并成单一实体"的动作都会让官方的干涉总量上升**，
这是**口径变严**（以前没查、现在查到了），不是改动改坏了。建议把这条写进交接档案的"口径提醒"，
并把 `val()` 换成"全 solid 遍历"（一处修改、四处受益）。

### 八·补、主会话独立复核：**"零新增"可用算术定案，且 RPi 仍有 3 处零头残留**

**（1）零新增的算术证明**（不需要再跑一次 CAD）：

```
对数差  = 189 − 188 = 1                  （恰好 1 对）
体积差  = 160339 − 156114 = 4225 mm³
Top1 原值 = 4224 mm³
```

⇒ 体积差 4225 = Top1 的 4224（差 1 mm³ 为舍入）⇒ **被移除的就是那一整对，其余 188 对逐对未变**。
若同时新增了干涉对，对数差会小于 1、或体积差会小于 4224。**"零新增"由此闭合并可复核。**

**（2）⚠️ 措辞更正：`cage__head_yaw ↔ RPi` 消失 ≠ "RPi 不再有任何干涉"**
主会话在全表（前 200 条）里搜 `Raspberry`，**仍有 3 处零头级残留**：

| 名次 | 对 | 体积 | 重合率 | 判定 |
|---:|---|---:|---:|---|
| 119 | `torso_upper__battery_tray` × `elec__Raspberry Pi 4B (4GB)` | 336 mm³ | 1% | · 局部干涉 |
| 174 | `torso_upper__torso_frame` × `elec__Raspberry Pi 4B (4GB)` | 49 mm³ | 0% | · 局部干涉 |
| 184 | `servo__head_yaw` × `elec__Raspberry Pi 4B (4GB)` | 23 mm³ | 0% | · 局部干涉 |

三条都远低于 ⚠️ 阈值（500 mm³ / 5%），属"局部干涉"级——**但答辩时不要说"RPi 完全没有干涉"**，
正确说法是"**RPi 与 head_yaw 笼的 4224 mm³ 已消除，剩余三处均为 ≤336 mm³ 的局部接触**"。

**（3）重要限制（本线程已提，这里再强调）**：0.3 mm 间隙是**对着 17 mm 裸板占位体**算的，
而 `design/components.json` 的 RPi note 写明**需 15 mm 散热高度**、`size_mm` 里没有这 15 mm。
⇒ **实物加散热片后 Top1 会原地复活**，装配前必须实测实物高度。
