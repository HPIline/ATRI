## 0. 一句话结论

现行 `τ = Σ mᵢ·g·rᵢ` 的**求和方式没错**（重力矩确实是逐 link 质量矩之和），错的是 `rᵢ` 的定义：

## 2. 现行公式错在哪（含最小复现算式）

### 2.1 正确算式

绕**任一**关节轴 `â`（单位向量，世界系）的重力力矩是

```
τ = (r × m·g·ẑ) · â = m·g·(r_x·a_y − r_y·a_x)          （r = 质心相对关节原点的位移）
```

⇒ 重力力臂 = `|r_x·a_y − r_y·a_x|`，**只有水平面内垂直于轴的分量**：

* 水平轴（本模型 19/22 个关节：`a_z = 0`）：力臂 = 水平偏移里垂直于轴的那一维；
  **质心正对轴线的上方/下方时力臂恰为 0**（这是对的物理，不是退化）；
* 竖直轴（`a_x = a_y = 0`）：力臂恒为 **0** —— 重力与该轴平行，绕它不产生力矩。
  「质心到轴线的水平距离」**不是**重力力臂（那是水平外力如地面反力的力臂），
  只有转动惯量 `I = Σ m·r⊥²` 才用那个几何半径。

### 2.2 最小复现（一行就能看出错）

```python
perpendicular_arm((0, 0, 137.4), [1, 0, 0])   # 旧口径 -> 137.4 mm  ← 把竖直偏移当成力臂
gravity_moment_arm((0, 0, 137.4), [1, 0, 0])  # 正确   -> 0.0 mm    ← 质心正对轴线，力矩为 0
```

## 3. 修法

### 3.1 两种力臂分开，两个函数各管一件事

| 函数 | 定义 | 用途 |
|---|---|---|
| `perpendicular_arm(offset, axis)` | 质心到轴线的**垂直距离** `r⊥`（含沿轴分量） | **只用于惯性项** `I = Σ m·r⊥²` |
| `gravity_moment_arm(offset, axis)` | `\|r_x·a_y − r_y·a_x\| / \|â\|` | **重力力臂**（零姿态与最不利姿态都用它） |

### 3.2 轴的几何：全部来自 URDF 正解，无任何硬编码方向

新增最小正运动学（纯标准库，无 numpy）：

* `_rpy_rotation()`（URDF 的 `R = Rz·Ry·Rx`）、`_axis_rotation()`（罗德里格斯，轴对齐走快路径）、
  `_mul3()`；
* `_kinematics(model)`：把 22 个关节整理成父子表 / 链 / 子树 / 相关自由度，
  按**模型内容指纹**缓存（不用 `id(model)`——id 会被回收重用，会读到脏缓存）；
* `_joint_state(kin, ji, angles)`：只走"该关节的祖先链 + 自己 + 子树"，返回该关节的
  **世界位姿**（原点 + 世界轴向量）与下游各 link 的质心世界坐标。
  兄弟分支（另一条腿、另一条手臂）既不在它的下游、也不改变它的轴，对它的重力矩没有影响；
* 单位统一 mm（URDF 文本是米，读取时 ×1000）。

模型当前 `origin_rpy` 全为 0（`gen_urdf.py` 不写非零 rpy），但代码走通用路径：
模型若补上 `origin_rpy_rad` / `origin_rpy_deg` 即自动生效。

### 3.3 两种口径（都已落进产物，未替用户二选一）

* **(a) 零姿态静力** `gravity_torque_nm_zero_pose`：URDF 零位（站立不动）的真实重力矩。
* **(b) 限位内最不利** `gravity_torque_nm_worst_case`：在该关节**自身限位**内，
  连同**祖先与后代**关节一起搜索出的最大 `|重力矩|`。

搜索方法（确定性、可复现，写进 `ASSUMPTIONS.worst_case_search` 的 note）：
在相关自由度上做**坐标上升**，每个自由度取**精确极值**——固定其余关节、只转第 k 个时，
τ 恒为 `C + A·cosθ + B·sinθ`（刚体绕定轴转动、重力方向固定），
用 θ = 0/π/2/π 三点定出系数后在限位区间上**闭式取最大**；
起点集 = 零位 + 全下限 + 全上限 + "每个相关自由度单独顶到某一端"（共 `3+2|rel|` 个，|rel| ≤ 13）。
不含地面接触/平衡约束 ⇒ 是**上界**，不是实际步态值（已在产物 `边界声明` 里写明）。

> 起点集的确定过程：先只用 3 个起点时 `trunk_pitch` 只找到 0.1926，
> 用 200 个随机起点挑战发现真值 0.1947（+1.1%）；补上"单轴顶到端点"的起点后即达到 0.1947，
> 再加随机起点无进一步改善（`starts_trial.py`，见 §8）。

### 3.4 主判据取哪一个（不替用户选，但必须有一个 headline）

* `required_torque_nm`（**主判据/选型用**）= 包络里的**保守口径**（最不利姿态）× 1.8 /
  惯性 × 1.8 / 单腿支撑 / 工程下限 四者取大；
* `required_torque_nm_zero_pose` = 同一套工况换成零姿态重力矩；
* `torque_criterion` 里**两套超限清单并列**：
  `joints_exceeding_continuous`（主判据）与 `joints_exceeding_continuous_zero_pose`；
  另给紧凑块 `torque_check.joints_pct_of_continuous_rated`（逐关节两个百分比）+ `same_set` 标记。
* JSON 里同时保留 `gravity_torque_nm` / `required_torque_nm_worst_case` / `max_arm_mm` 等
  **兼容字段**，但语义已在字段旁注明（`max_arm_mm` = 径向臂；`gravity_torque_nm` = 最不利口径），
  下游 `gen_spec_sheet.py` / `check_fit.py` 只读 `required_torque_nm`，不受字段改名影响。
