### 1.1 G1 的元问题

Gemini 的 G1 有**两条正确**（端面 4 孔语义、25T/OD5.9），
但第 3、6 行的错误有一个共同根因：**它把"机身安装耳的既有假设"当成了事实**，
于是把新看到的孔往旧框架里塞。

> 第 7 行"含安装耳总长 51.2"出现在 G2（LX-824HV）里——
> 而这组 51.2 / 48.5×10.0 正是**上一轮写进 `standards.py`、本轮被三源证伪的幽灵数据**
> （原标注"飞特官方 2D 工程图纸"）。也就是说：**上一轮的编造数据，这一轮被它自己复述了一遍。**
> 这条恰好是"为什么必须要求出处"的最好例证。

## 3. G3 · 替代舵机候选

| Gemini 候选 | 官方目录核对结果 |
|---|---|
| **飞特 STS3230**（1.2 N·m 额定 / 3.0 堵转 / 65 g / 45.2×24.7×35 / 110–130 元） | ❌ **飞特官方目录里没有 STS3230 这个型号**。同尺寸（**45.22×24.72×35**）的 12V/30kg 型号是 **STS3235**：铝壳 + 钢齿 + 滚珠轴承，**70.5±1 g**，额定负载**同为 10 kg·cm**，空载 0.222 s/60°、堵转 30 kg·cm、堵转电流 2.7A，**工作电压仅 6–12V**（3S 满电 12.6V 超上限 ⚠️）。→ 它是"同尺寸更耐久"，不是"更高扭矩" |
| **飞特 SM45BL**（1.5 N·m / 4.5 N·m / 105 g / 46.5×28.5×34 / 260–320 元） | ❌ 未能在飞特官方 STS(TTL) 目录中检出该型号（官网可搜到的同族是 12V 40kg 无刷 TTL 等，尺寸更大）。**无法证实** |
| **宇树 GO-M8010-6**（2.5/8.0 N·m，480 g，Φ80×38，CAN） | ❌ 这是**外转子关节电机**（需外置驱动器、CAN 总线、Φ80 法兰），与 22 个 45.2×24.7×35 舵机位**不可互换**——放进 G3 的候选表里属于类别错误 |

**顺带纠正 G3 的一个卖点**：它把"12-bit 磁编码 + 电流回读"当作 STS3230 的优势——
但 **STS3215 官方反馈就有 6 项：负载、位置、速度、输入电压、工作电流、工作温度**，
电流回读不是升级点（STS3215 缺的是**力矩闭环模式**，官方四种模式确认无此项）。

**结论**：G3 的候选名单不可直接采用。真要在同尺寸里升级，官方存在的选项是：
`STS3235`（铝壳钢齿、+15.5 g/只、3S 满电超压）或 `STS3025BL`（40×20×40、89 g、无刷、1/8 8 减速比，尺寸小两维）。

## 6. G6 · 跨品牌兼容性（用官方 SDK 源码逐条验证）

| Gemini 给的 | 核验（源码级） |
|---|---|
| 飞特：帧头 **0xFF 0xFF**，帧 `[ID][Length][Instruction][Params][Checksum]`，校验 = **按位取反累加和** | ✅ **完全正确**。官方 SDK `ftservo/FTServo_Python` `scservo_sdk/protocol_packet_handler.py`：`txpacket[PKT_HEADER0]=0xFF; [1]=0xFF; checksum += …(2..len-1); txpacket[len-1] = ~checksum & 0xFF` |
| 飞特波特率支持 1 Mbps | ✅ 官方规格书 7-4：38400 ~ 1 Mbps，出厂默认 1 Mbps |
| 幻尔：起始字节 **0x55 0x55**，默认 **115200** | ✅ 社区 SDK `BusServoCmd.py`：`serial.Serial("/dev/ttyAMA0", 115200)`、帧头 `0x55 0x55`、校验 `~sum`（去掉两个 0x55） |
| 幻尔"**内部寄存器地址映射**与飞特完全不同" | ❌ **表述错误**：LX 系列是**指令式**协议（`MOVE_TIME_WRITE=1`、`POS_READ=28`、`TEMP_READ=26`、`VIN_READ=27`…），根本没有寄存器地址映射。结论（不通用）对，机理说反了 |
| 三者硬件物理层同为 TTL 单线半双工，但指令集/波特率**完全不通用** | ✅ 成立 |
| 树莓派 USB 供电不足：`I/O Error`、`dmesg` 反复 `USB disconnect` + 重新枚举（ttyUSB0→ttyUSB1） | ✅ 现象可信、判据合理（4 口共享限流） |
| 舵机堵转拉垮主控：地弹（GND 被抬高 0.5~1.0V → HardFault）/ 母线跌落（5V 轨跌破 4.5V） | ✅ 两种形态描述合理 |
| 隔离要求：动力地与数字地**单点星型接地**；总线 DATA 经三态门缓冲，**不可 GPIO 直连** | ⚠️ 星型接地 ✅；"不可 GPIO 直连"**过严**——飞特官方信号电平为**高 2–5V / 低 0–0.45V**，3.3V MCU 直驱是被支持的；长线或强干扰场合再加缓冲更合理 |

## 8. 仍需外部输入（本轮无法闭合）

**A. 买 1 只舵机（约 90 元）后可闭合的 3 项**
1. Φ2.5 孔阵的**螺纹规格**（M2.5 螺纹孔 or M2/M3 自攻底孔）
2. 输出轴心相对实物 **A/B/C 基准面**的偏心（模型 ↔ 实物坐标对应）
3. 副轴轴径/伸出长度**卡尺复核**（官方 4.1，模型 0.6）

**B. 向厂商索取**
- 飞特：**12V 版 STS3215（SER0070 同类）规格书**（现有 12V 数据来自 DFRobot 参数表）
- 幻尔：LX-824HV 规格书、扩展板型号、关节 ID 定义表（原 U3）

**C. 试件实测（决定工艺参数）**
- PETG 舵机腔避空：0.25 单边（我方）vs 0.35（Gemini）
- 填充率 55%（我方）vs 40–50%（Gemini）对承力件强度/质量的影响

**D. 下一轮给 Gemini 的问题（已大幅收窄）**
G1/G2 已被官方文档闭合，**不必再问**；值得问的只剩"无原文、靠经验"的：
1. 跨品牌 25T 舵盘的实测齿形差异（飞特 vs 辉盛/Futaba），以及能否通过修齿互配
2. 商用机（TonyPi Pro / Tonybot）踝关节的**真实装配顺序与线束走法**（有实物拆解经验者更佳）
3. PETG 承力件在**长期交变载荷**下的蠕变/松弛经验值（决定预紧力与螺钉选型）

> 这 3 条都属"经验型"，但优先级**低于**买 1 只舵机实测——
> 后者能一次闭合 3 项硬数据，且成本只有 90 元。

## 9. ⚠️ 顺带发现的内部问题（与 Gemini 无关，需尽快修）

**`design/cad/skeleton.py` 的舵机局部坐标系把 35 与 24.7 用反了。**

```python
L_S, W_S, H_S = S["body_mm"]                  # 45.2 / 24.7 / 35.0
GAP = W_S + FDM["servo_cavity_clearance_mm"]  # 两侧板净距 25.2  ← 应为 35.5
AXIS_DZ = servo_axis_offset_mm(SERVO_NAME)    # 6.5               ← 应为 0
Z_TOP = H_S / 2.0 - AXIS_DZ                   # +11.0             ← 应为 +12.35
Z_BOT = -H_S / 2.0 - AXIS_DZ                  # -24.0             ← 应为 -12.35
```

- 代码里两侧板明确是 **⊥ 输出轴**（`# --- 两侧板（⊥ 输出轴）---`，
  且舵盘避空与 MF106ZZ 轴承位都沿 `axis="Y"` 加工），
  而**沿轴厚度是 35.0**（官方 + 实测一致）→ 当前净距 25.2 会让舵机**穿出两侧板各 4.9 mm**。
- `Z_TOP/Z_BOT` 用 `H_S=35` 当"垂直轴高度"→ 但垂直轴截面是 **24.7 × 45.2**，
  且轴线在宽度方向**居中**（AXIS_DZ 应为 0），长度方向偏心 **10.2 / 35.2**（当前完全没建）。
- 4 个 M2.5 安装孔目前钻在**底板**上（`drill(..., z0=z_floor_bot)`），
  但真实安装孔在**两个端面**上 → 应改到 ±Y 侧板、沿 Y 钻，孔位 **±4.95 × ±4.95**。

**正确取值**（以轴线为原点、输出轴沿 +Y）：

| 方向 | 机身范围 | 依据 |
