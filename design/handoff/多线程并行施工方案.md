## 2. 线程划分

| 线程 | 模型 | 工作面 | 依赖 | 产出 | 验收 |

| **D 经验判据** | **Gemini** | K1/K3 数值区间与假阳性、K7 打印框架、K8 失效清单、K9 温升实测法、K10 电源完整性 | 无 | 一份判据文档（人肉粘回） | 每条有区间 + 来源等级 |

## 3. 文件所有权矩阵（**避免并发改同一文件**，这是本项目已踩过的坑）

| 文件/目录 | 唯一所有者 | 其他人 |
|---|---|---|
| `design/cad/**`（skeleton/kit/assembly/standards/audit/fitcheck） | **DSV4.1F** | 只读；要改就提 patch 建议 |
| `design/handoff/总体参数汇总表.md`、`装配一致性修正记录.md` | DSV4.1F | 只读 |
| `软件/atri/atri/bus_sts3215.py`、`tests/test_bus_sts3215.py`、`固件/**`、`design/handoff/上下位机协议.md` | **Grok 4.6** | 只读 |
| `软件/atri/atri/config.py`、`cerebellum.py` | **DSV4.1F（已冻结语义）** | Grok 可**提议**新方法，由 DSV4.1F 合并 |

**提交纪律**：**同一时刻只有一个会话执行 `git commit`**（建议由用户统一提交）。
其他线程只改工作树、写报告；跨线程改动一律走"报告 + patch 建议"。

## 4. 时间线（相对"硬件到货"）

```
今天         用户：三选一决策 + 下单最小 bring-up 采购（≈200–250 元）
             ├─ Grok：Phase 1 驱动 + 假串口单测 + 协议校核
             ├─ Gemini：K1/K3/K7/K8 + K9/K10（经验判据）
             └─ DSV4.1F：B1 扫掠自碰撞 / B2 工具可达 / B3 参考件间隙反查
决策后 1–2 天 DSV4.1F：A 线程执行（改布局 → 体检压到 <10 → 质量重算）
到货当天      Grok：C 线程 bring-up 三步（scan/limits/jog）→ 点动
到货 +1–3 天  E：温升/连续扭矩实测 → 回填 standards.py（闭合项目唯一硬不确定项）
结构冻结后    DSV4.1F：G 验证档预览 → 录演示档 → F 合规/PPT 同步
```

## 5. 集成与验收（单一入口）

任何线程完成后，由 **DSV4.1F** 执行统一验收：

```bash
bash design/cad/build.sh                  # 零件→装配→体检（含 2.5 步性质判定）
.venv-cad/bin/python design/cad/audit_assembly.py --strict
cd 软件/atri && python3 -m unittest discover -s tests   # 186 项
```

- 门槛：**摆放错误 = 0**（布局定案后）、**关节轴对齐 22/22**、**零件单实体+valid**、
  **测试全绿**；不达标不进主线。
- 集成产物：`总体参数汇总表.md` 每次验收后更新（保持"单一真值"）。

## 6. 风险与回退

| 风险 | 触发 | 回退 |
|---|---|---|
| 并发改同一文件 | 两线程同时动手 | 按第 3 节所有权矩阵；冲突时以 DSV4.1F 版本为基线，对方重放 patch |
| Gemini 编数字 | 无出处精确值 | 只取"区间 + 来源等级 D"；不写进代码阈值，先做试件验证 |
| 布局决策拖延 | 深度/质量悬空 | B/C/D/E 照常并行；A 一旦定案，1–2 天可追平 |
| 硬件到货推迟 | 采购/物流 | Grok Phase 1 与 E 的"单只舵机"不受影响，仍能推进 |
| 真实质量超预算 | 实称 > ≈3136 g（现行纸面推算；重量方案未定案） | 触发"减件/换小件"预案（第 2 节 A 线第③案） |
