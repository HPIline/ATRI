## 1. 目标与验收标准

### 1.1 功能目标（对齐赛题原文）

赛题原文：「① 人脸识别：识别指定人脸并播报姓名。」

即：**给定一个已注册的人出现在镜头里，机器人要在本机离线算出他是谁，并用 TTS 播报姓名。**

### 1.2 验收指标（沿用 `BOM与阶段性指标.md`，不新造口径）

| 指标 | 目标 | 状态 |
|---|---|---|
| 人脸检测成功率 | ≥ 90%（≤1.5 m） | 待测 |
| 人脸播报姓名正确率 | ≥ 90%（5 人以内） | 待测 |

> **如果实测达不到 90%，就如实写实测值 + 差距归因 + 改进路径，不改口径迁就结果。**

### 1.3 本次交付的验证方式（已与需求方确认）

- **不录入组员人脸。** 用**开源人脸库 LFW**（Labeled Faces in the Wild）验证识别成功率。
- 摄像头实测（距离档 0.5/1.0/1.5 m）**本轮不做**，因为需要真人配合；本轮只出**身份识别准确率**，距离维度在报告里明确标注为"未测"。

## 2. 数据流

```
BGR 帧
 └─ FaceDetector (YuNet ONNX, 232 KB)        → N × (bbox, 5 关键点, 检测分)
      └─ align.align_face(frame, landmarks)   → 112×112×3 BGR（相似变换对齐）
           └─ FaceEmbedder (SFace ONNX, ~37 MB) → 128 维 float32 → L2 归一化
                └─ FaceDB.match(vec)          → 与全部注册向量算余弦相似度
                     └─ 最高分 > threshold ? 姓名 : recognized=False（拒识）
```

**可替换单元**：`FaceDetector` 与 `FaceEmbedder` 都是接口 + 多实现。换算法、做对照实验、CI 里用假实现，都不动上层。

## 3. 接口设计

### 3.1 `atri/perception/faces/detector.py`

```python
@dataclass
class FaceBox:
    bbox: tuple[int, int, int, int]      # x, y, w, h
    landmarks: list[tuple[float, float]] # 5 点：右眼、左眼、鼻尖、右嘴角、左嘴角
    score: float

class FaceDetector(ABC):
    name: str
    def detect(self, frame) -> list[FaceBox]: ...

class YuNetDetector(FaceDetector):   # 主力
    model_path, input_size, score_threshold, nms_threshold
class HaarDetector(FaceDetector):    # 对照组；无关键点 → landmarks 为空
```

### 3.2 `atri/perception/faces/embedder.py`

```python
class FaceEmbedder(ABC):
    name: str
    dim: int
    def embed(self, face_bgr) -> np.ndarray | None:   # 返回已 L2 归一化的向量

class SFaceEmbedder(FaceEmbedder):   # dim=128，需 onnx 模型
class LbphEmbedder(FaceEmbedder):    # 兜底路线；训练式，dim 由实现决定
class MockEmbedder(FaceEmbedder):    # 测试用：由图像内容的确定性哈希生成向量
```

**L2 归一化后，余弦相似度 = 点积**，比对退化为一次矩阵乘法，Pi 上零成本。

### 3.3 `atri/perception/faces/face_db.py`

```python
class FaceDB:
    schema_version: int
    embedder: str          # "sface" / "lbph"
    dim: int
    threshold: float
    people: list[Person]   # Person: name, vectors(list[list[float]]), meta

    @classmethod
    def load(path) -> FaceDB          # 校验 schema_version / dim，不匹配即报错
    def save(path)
    def enroll(name, vectors, meta)
    def match(vec) -> MatchResult     # name, similarity, recognized(bool)
```

### 3.4 `atri/perception/faces/pipeline.py`

```python
class FaceRecognizer:
    def __init__(self, detector, embedder, db, min_face_px=40): ...
    def recognize(self, frame) -> FaceFrameResult   # 全部人脸 + 各自识别结果
```

## 5. 阈值标定（不许拍脑袋）

1. 对测试集算**全部同人配对**（genuine）与**全部异人配对**（impostor）的相似度分布。
2. 扫阈值，得 FMR / FNMR 曲线，取 **EER**（等错误率）点。
3. 设计阈值取在 EER 附近偏保守一侧（宁可拒识，不可认错——认错会播报错名字，比"不认识"更糟）。
4. 标定脚本：`software/atri/tools/face_eval.py --calibrate`，输出曲线数据与选定阈值；结论写进库文件与报告。

## 6. 评测协议（LFW）

- 数据：LFW（13233 张、5749 人）。取**图片数 ≥ 15 的 5 个身份**作为注册对象。
- 划分：每人 **前 5 张注册**、**后 10 张测试**（按文件名升序，确定性）。
- 指标：
  - **rank-1 识别正确率** = 测试图被认成正确姓名的比例（主指标，对齐"5 人以内 ≥90%"）
  - **混淆矩阵**（5×5）
  - **相似度分布 + EER 阈值曲线**
  - **拒识率**（相似度低于阈值而判"不认识"的比例）
- ⚠️ **口径声明**：opencv_zoo 公布的 SFace LFW 准确率是**验证（verification）协议的 99.60%**，
  与本方案的 **rank-1 识别（identification）** 协议**不同，数字不可直接对比**。报告中必须写明这一点。

## 7. 隐私与数据入库口径

- **原图不入库。** LFW 原图与派生裁剪图都待在 `本地数据/`（gitignore）。
- 入库的只有：**128 维嵌入向量 + 姓名 + 采集元数据**。
- ⚠️ **嵌入向量本身也是生物特征**（可用于比对，属于个人信息），不是"脱敏后就安全"。
  本方案不把它当敏感度为零的数据；若是真人注册，需本人知情同意。
- 本轮注册对象是 LFW 公开人物，不涉及真人生物特征采集。

### 11.4 与原方案的两处偏离（都说明理由）

1. **不实现 `LbphEmbedder`。** LBPH 是训练式分类器，`predict()` 返回标签+距离，**不产生可比向量**，
   硬塞进 `FaceEmbedder` 会造出一个假抽象。若将来要做经典方法基线，应作为独立的分类策略实现。
2. **`OpenCVPerception.detect_face` 保持原样（Haar 检测-only）**，真识别走新的 `FaceRecognizer`。
   理由：现有 437 项测试依赖该方法的返回结构，双通路比改签名更稳；真识别是新主路径，不是旧路径的补丁。
