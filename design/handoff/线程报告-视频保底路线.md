## 二、盘点：为什么原来不行（三次否决，别重走）

| 候选 | 实测结果 |
|---|---|
| `/usr/bin/avconvert` | ❌ **只接受单个媒体文件**（`--source <media file>`），**不吃图片序列**。所以"逐帧 PNG → avconvert 合成"这条路根本不存在 |
| 系统 Python 的 PyObjC（`AVFoundation`+`AVAssetWriter`） | ❌ 本机 `/usr/bin/python3` 3.9.6 **没有 PyObjC**（`AVFoundation`/`CoreMedia`/`objc`/`Quartz` 全无） |
| 系统 ffmpeg | ❌ 不存在（`command -v ffmpeg` 为空） |

**突破口**：`imageio-ffmpeg`（pip 包）**自带一个 ffmpeg 静态二进制**，不需要系统 ffmpeg。
国内源可达（实测 21.1 MB，2.5 MB/s）。已装入 `.venv-cad`：

```
ffmpeg 二进制：.venv-cad/lib/python3.9/site-packages/imageio_ffmpeg/binaries/ffmpeg-macos-aarch64-v7.1
大小 49.4 MB｜版本 7.1｜libx264 + yuv420p 可用（实测编码 1280×800 H.264 High 成功）
```

## 三、链路三段，逐段已实测

### 第 1 段：无头浏览器渲染 WebGL —— **必须用 SwiftShader**

本机无 Chrome、有 **Microsoft Edge**：
`/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge`

| 参数组合 | 结果 |
|---|---|
| `--headless=new --disable-gpu` | ❌ **白屏**。页面显示"此浏览器不支持 WebGL，请用 Safari/Chrome/Edge 打开"——因为 `--disable-gpu` 把 WebGL 一起关了（截图 13 KB） |
| `--headless=new --enable-unsafe-swiftshader --use-gl=angle --use-angle=swiftshader` | ✅ **成功**（截图 231 KB，日志出现 `GPU stall due to ReadPixels` ⇒ 真的在渲染）。装配体、22 关节滑条、冲突可视化全部正确 |

> ⚠️ 这两个参数是**硬要求**。踩过一次，写进工具注释了。

### 第 2 段：URL 驱动姿态注入 —— 动画不是转台

`design/cad/preview.py` 生成的自包含 HTML 内置 `applyHash()`（约 1307–1328 行）：

```js
// #pose=关节:度,…        逗号分隔
// #preset=名字|序号      预设
const h = location.hash || "";
m = /pose=([^&]+)/.exec(h);
... kv.split(":"); META.joints.findIndex(j => j.name === a[0]); setJoint(k, parseFloat(a[1]));
```

- **实测有效**：`#preset=招手` 精确生效（截图里 `right_shoulder_pitch −88`、`right_elbow_pitch −90`、`head_yaw −14` 等滑条全部到位、手臂抬起）。
- **写法**：`#pose=head_yaw:-14,right_shoulder_pitch:-88`（中文预设名要 URL 编码）。
- ⇒ 可以逐帧喂不同关节角，做出**真正的姿态动画**（举手/挥手/踢球/回零位），不是转台。

### 第 3 段：编码 mp4 —— 已实测

**首次全量出片实测（128 帧 @ 12 fps，1280×800，crf 23）**：

```
128 帧 @ 12 fps = 10.7 秒 ｜ 0.31 MB ｜ 约 0.23 Mbps
Duration: 00:00:10.67 ｜ Video: h264 (High) (avc1), yuv420p(progressive), 1280x800, 12 fps
逐帧失败 0 / 128 ｜ 总耗时 1376 s（≈23 分钟，≈10.8 s/帧）
```

> ⚠️ **本节原先的体积估算表是错的，已按实测更正。**
> 原表按"1080p30 @ 6 Mbps ≈45 MB/min"这类**固定码率**推算，得出"≈11 MB/分钟"；
> 但本工具走 **crf 23（质量恒定）**，而这个画面**背景纯净、几何静态、运动缓慢**，
> libx264 实测只用了 **0.23 Mbps ⇒ ≈1.7 MB/分钟**，比原估**低 6.5 倍**。
> **教训：不要用固定码率去估 crf 编码的体积。**

**修正后的体积预算（对照平台 100 MB 上限）**：

| 场景 | 实测/推算码率 | 100 MB 能放 |
|---|---|---|
| **实测**：1280×800, crf 23, 静态演示动画 | **0.23 Mbps（1.7 MB/min）** | **≈58 分钟** |
| 若画面运动更剧烈（多条轨迹/频繁切镜头） | 估 1–3 Mbps | 4–13 分钟 |
| 若坚持按 1080p30 @ 6 Mbps 固定码率编码 | 45 MB/min | 2.2 分钟 |

⇒ **体积完全不是约束**，默认参数下可以把帧数/时长铺开到分钟级。
若最终仍超限，再用 `avconvert` 压（它接受 mp4 输入）。

**⚠️ 产物时效说明**：本次 `ATRI-pose-demo.mp4` 是在 CAD 让位修正提交（`6190ad4`）**之前**用
`preview.py` 于 11:36 生成的几何渲染的，因此画面上仍是**旧几何**（`head_yaw` 笼多沉 2.5 mm）。
要让视频反映最新几何，需先跑
`.venv-cad/bin/python design/cad/preview.py --all --rebuild` 再重出片（再花 ≈23 分钟）。

## 四、工具与参数

**`design/cad/tools/make_pose_video.py`**（本次新建，属 `tools/` 工具区，与 CAD 线程文件不重叠）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--html` | `design/cad/out/preview/ATRI-preview.html` | 预览产物；不存在会提示先跑 `preview.py --all` |
| `--out` | `design/cad/out/video/ATRI-pose-demo.mp4` | 输出 mp4 |
| `--frames` | 128 | 总帧数 |
| `--fps` | 12 | 帧率（128 帧 ÷ 12 = 10.7 秒） |
| `--size` | `1280x800` | 分辨率 |
| `--crf` | 23 | 越小越清晰越大（23 ≈ 1.5 Mbps） |
| `--budget-ms` | 25000 | **每帧虚拟时间预算**；太小会截到没渲染完的画面 |
| `--mate-alpha` | 沿用预览的 0.50 | 配合件半透明 alpha。**传 `1.0` = 关掉半透明**，结构完整可见 ⇒ 适合拍官图/宣传片；讲干涉时保留默认 |
| `--probe` | — | **只渲 3 帧验证链路（约 45 秒）**，改参数前先跑这个 |
| `--keep-frames` / `--workdir` | — | 保留/指定帧目录，便于抽查单帧 |

**实测耗时**：单帧探测 **约 14 秒/帧**；**全量 128 帧实测总耗时 1376 s（≈23 分钟，≈10.8 秒/帧）**
（SwiftShader 软件渲染，无 GPU 加速；当时另有两个 CAD 线程在跑）。
**建议**：正式出片前先 `--probe`；跑全量时**放后台**，别占着前台。

**动画编排**（`build_keyframes()`，纯常量表，可直接改）：
零位 → 立正 → 举右手 → 左右摆两下 → 收手 → 踢球 → 回零位，用 smoothstep 缓动，镜头 yaw 小幅摆动。

**"只剩画面"的录制副本**：工具会复制一份 HTML 并注入 CSS 隐藏 `#hud` / `#panel` / `#tip`
（**不改 `preview.py`**，只后处理产物）。实测截图确认 UI 已完全隐藏、画面填满视口。

规格：**1920 × 1080**、UI 已隐藏、**配合件不透明（`--mate-alpha 1.0`）**⇒ 结构完整可见，适合当"产品图"。

```bash
# 复现某一张（把 POSE 换成 POSE_ATTENTION / POSE_WAVE_UP / POSE_KICK）
.venv-cad/bin/python - <<'PY'
import sys; from pathlib import Path
```
