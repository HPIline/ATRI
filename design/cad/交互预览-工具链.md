# 交互式 3D 预览工具链（本机可用）

> 目标：**能自由缩放旋转地看模型**，且整条链路满足"稳定、可迭代、方便修改、可自动化"。
> 本文件回答"装什么、怎么用、什么时候用哪个"，并给出各方案在本机的**实测状态**。
> 最后核实：2026-09-11（本机 macOS，工作区 = 本仓库根，下文命令以 `<repo>` 指代仓库根）

---

## 0. 一句话结论（按推荐顺序）

| 顺序 | 方案 | 装什么 | 交互能力 | 本机状态 |
|---|---|---|---|---|
| ① | **自包含 HTML 预览** | **什么都不用装** | 旋转/缩放/平移/按类别显隐/线框/自动旋转 | ✅ **已生成并实测通过** |
| ② | **VS Code 内看 STL/GLB** | 一个 VS Code 扩展（1 条命令，你手动跑） | 旋转/缩放，改完模型重开即刷新 | ⏳ 待你装（命令见 §2） |
| ③ | **CadQuery 官方查看器（VTK）** | **什么都不用装**（vtkmodules 随 cadquery-ocp 一起来） | 真 B-rep（不是网格）旋转/缩放 + 边线显示 + 无头截图 | ✅ **已实测**（含离屏出图） |
| ④ | **CQ-editor**（参数化 IDE） | `pip install cq-editor`（PyQt） | 改 `skeleton.py` 存盘即重载 + 3D 视图 | ❓ 未实测，风险中 |
| ⑤ | **Webots**（可拖动关节 + 仿真） | 官方 dmg（人工安装） | 整机 + 22 关节滑块 + 物理 | ❌ 本机未装（项目本来要用） |
| ⑥ | **FreeCAD / Blender** | 官方 dmg（人工安装） | 开 STEP 做装配/渲染 | ❌ 本机未装，重量级 |

**给你的建议**：日常迭代用 ①（零成本、我已经把它接进构建流程），
需要长时间盯着看细节时用 ② 或 ③。⑤ 应该装——不是为看模型，而是项目本来就要跑仿真联调。

## 1. 方案①：自包含 HTML 预览（零安装，已实测）

```bash
cd <repo>
.venv-cad/bin/python design/cad/preview.py --all          # 整机
.venv-cad/bin/python design/cad/preview.py --part joint_cage   # 单件
open design/cad/out/preview/ATRI-preview.html             # 双击也行
```

- 产物：`design/cad/out/preview/ATRI-preview.html`
  （**单文件、几何 base64 内嵌、不联网、无 CDN 依赖**——比赛现场断网也能给评委看）；
- 交互：左键拖拽旋转 · 滚轮缩放 · 右键/Shift 拖拽平移 · `R` 重置 · `W` 线框 · `空格` 自动旋转；
- 右侧面板按**类别**显隐：关节笼 / 结构大件 / 转接块 / 连杆管 / 舵机 / 连杆叉 / 电子件
  —— 看干涉时先关掉舵机，一眼就能看出结构件之间的碰撞；
- 参数：`--tol 1.2`（网格容差 mm）控制体积与精度。当前 162k 三角面 / 17.5 MB HTML，
  调大到 `--tol 2.0` 可压到约一半。
- **怎么验证它不是"我以为能跑"**：用 Chromium 内核浏览器无头渲染截图（本轮已做）：

```bash
"/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge" \
  --headless=new --disable-gpu --enable-unsafe-swiftshader --no-sandbox \
  --window-size=1400,1000 --virtual-time-budget=15000 \
  --screenshot=design/cad/out/preview/_selftest.png \
  "file://$PWD/design/cad/out/preview/ATRI-preview.html"
```

把这条加进 CI 或本地自检脚本，就等于**每次改模型都自动验一遍"预览没坏"**。

**局限**：看的是三角网格（B-rep 的精确曲面被离散化），量尺寸不可靠——量尺寸请用 STEP + CAD。

## 2. 方案②：VS Code 里看模型（推荐你手动装一次）

VS Code 已装（1.137.0），但当前只有 GitHub 相关扩展。装一个 3D 预览扩展即可：

```bash
# 看 STL（我们已经在导出，最省事）
"/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code" \
  --install-extension slevesque.vscode-3dviewer

# 看 glTF/GLB（带轨道控制，能看颜色与层级）
"/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code" \
  --install-extension cesium.gltf-vscode
```

用法：VS Code 里打开 `design/cad/out/stl/joint_cage.stl` → 右键 `Open with 3D Viewer`。
**这是装扩展、动的是你的编辑器环境，所以由你手动执行**（我按约定不碰你的编辑器配置）。

改完模型想刷新：重跑 `build_all.py` 覆盖同一个 STL，VS Code 里重开一次即可。
配合 `Cmd+Shift+P → Reload Window` 更省事。

## 3. 方案③：CadQuery 官方查看器（真 B-rep，零额外安装）

```bash
cd <repo>
.venv-cad/bin/python design/cad/view.py --assembly            # 整机交互窗口
.venv-cad/bin/python design/cad/view.py --part limb_fork --edges
.venv-cad/bin/python design/cad/view.py --assembly --screenshot out/view/整机.png
```

窗口里是**真 B-rep**（OpenCASCADE 实体直接渲染，不是三角网格）：左键旋转、中键平移、滚轮缩放、
`e` 切换边线、`w` 线框、`q` 退出。适合确认"圆角/倒角/相切面到底做出来没有"。

`--screenshot` 是**离屏渲染**（不需要 GUI、不需要开窗口），本机已实测：
整机 80 零件、1500×1080、带边线，约 22 秒出一张 PNG。这条可以进 CI —— 每次改模型都自动出图。

### ⚠️ 三个踩过的坑（务必不要再踩）

**坑 1：不要单独 `pip install vtk`。**
`cadquery-ocp` 的 wheel **自带一整套 `vtkmodules`**（VTK 9.2.9 系），`cq.vis` 就是靠它工作的。
再装一个独立 `vtk`（9.6.x）会把两套 VTK 塞进同一个 `site-packages/vtkmodules/` 目录，
表现为：

```
ImportError: Initialization failed for vtkCommonTransforms,
             not compatible with vtkmodules.vtkCommonCore
objc[...]: Class vtkCocoaGLView is implemented in both ... This may cause
           spurious casting failures and mysterious crashes.
```

**正确做法：什么都不装。** 冒烟验证：

```bash
.venv-cad/bin/python -c "import cadquery as cq; from cadquery import vis; \
  print(cq.__version__, callable(vis.show))"        # → 2.5.2 True
```

**坑 2：不要用"RECORD 里没有就删"的方式清理 `site-packages/vtkmodules/`。**
`vtkmodules/.dylibs/` 里同时躺着 **cadquery-ocp 的 OpenCASCADE 动态库**
（`libTKOffset.7.7.2.dylib` 等，`OCP.cpython-39-darwin.so` 靠 `@loader_path` 找它们）。
按 vtk 的 RECORD 清理会把 OCP 的库当垃圾删掉，后果是 cadquery 整个不可用：

```
ImportError: dlopen(.../OCP.cpython-39-darwin.so): Library not loaded:
             @loader_path/vtkmodules/.dylibs/libTKOffset.7.7.2.dylib
```

**修复**：`.venv-cad/bin/pip install --force-reinstall --no-deps \
-i https://mirrors.aliyun.com/pypi/simple/ cadquery-ocp==7.7.2`（约 1 分钟，走国内镜像）。

**坑 3：GLB 导出要直接调 `exportGLTF`。**
`cq.exporters.export(asm, "x.glb", exportType="GLTF")` 在 cadquery 2.5.2 上会抛
`DispatchError: ('compound: 0 methods found', ...)`；改成：

```python
from cadquery.occ_impl.exporters.assembly import exportGLTF
exportGLTF(asm, "x.glb", binary=True, tolerance=0.4, angularTolerance=0.4)
```

`preview.py` 里已经这么写了。整机 80 零件 → **6.0 MB GLB**。

## 4. 方案④⑤⑥：什么时候才需要它们

| 需求 | 该用什么 | 说明 |
|---|---|---|
| 改参数、立刻看结果 | ①/② + `build_all.py` | 我们的模型是**代码生成的**，改 `skeleton.py` 重新导出比在 GUI 里拖快得多 |
| 检查干涉/装配顺序 | ① | 类别显隐 + 线框最直观；真要精确干涉量，用 CAD |
| 需要装配约束、出正式图纸 | **SolidWorks / FreeCAD**（STEP） | 我们导出的 `ATRI-assembly.step` 就是为这个准备的 |
| 要关节动起来、跑物理 | **Webots**（未装） | 项目已有 `webots/tools/generate_atri_world.py`，装完可复用 |
| 要好看的渲染图 | Blender（未装）或我们的 `render3d.py` | 我们的渲染器已能出 SVG/PNG，够进 PPT |

**不建议**为了"看模型"去装 FreeCAD/Blender：它们各自 300 MB–1 GB，
而我们的模型是参数化的，**看**用 HTML、**改**用 Python、**精修**用 SolidWorks，链条更短。

## 5. 这条工具链的"自动化"骨架（推荐固化成习惯）

```
skeleton.py / kit.py（唯一真值源，参数化）
        │  build_all.py --all
        ├─► out/step/*.step     → SolidWorks 精修 / 出正式图纸
        ├─► out/stl/*.stl       → 切片打印 / VS Code 预览
        ├─► out/report.md       → 质量审计（每次构建都重算）
        │  assembly.py --all
        ├─► out/step/ATRI-assembly.step
        │  render3d.py --all
        ├─► out/renders/*       → PPT / 文档
        ├─► out/drawings/*      → 工程图（HLR 线框 + 隐藏线）
        │  preview.py --all
        ├─► out/preview/ATRI-preview.html   → 零安装交互预览（本次新增）
        └─► out/preview/ATRI-assembly.glb   → 标准交换格式（需 vtk）
```

一条命令跑完全链（建议加到 `design/cad/build.sh`，谁都能一键复现）：

```bash
cd <repo> && \
  .venv-cad/bin/python design/cad/build_all.py --all && \
  .venv-cad/bin/python design/cad/assembly.py --all && \
  .venv-cad/bin/python design/cad/render3d.py --all && \
  .venv-cad/bin/python design/cad/preview.py --all
```

**纪律**：产物一律**重新生成**，不手改 `out/` 里的任何文件。
改了 `out/` 就等着下一轮"图纸和模型对不上"——v1 的 webots 手写常量就是这么坏掉的。
